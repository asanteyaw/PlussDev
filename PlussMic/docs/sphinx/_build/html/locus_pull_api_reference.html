LocusPull API Reference¶

LocusPull is the root-grain feature builder returned by Locus::pull(root). Plain take() specifications follow root-preserving relationships, while reducers gather all related records back to one value per root record. collect() is the terminal that executes the plan.

Calls such as sum("orders.amount", "spent") use a fully qualified source. When several reducers come from one related catalog, agg("orders") enters the LocusPullAgg API Reference, where the table prefix is bound once and end() returns to the owning pull.

The builder is intentionally mutable: methods append specifications and return a reference to the same plan. That makes a named builder useful when a program adds features conditionally. root() and specs() expose read-only planning metadata; they do not execute a pull.

Reference Data¶

The method pages use one permanent executable-backed workspace. Its customers catalog has four records (id, name, region_id, signup), regions maps region IDs 10, 20, and 30 to west, east, and north, and events contains eight timestamped spends related many-to-one to customers. Customers link many-to-one to regions. Primary keys and time fields are declared where aggregate and window examples require them.

Output helpers print stream names and values directly from the resulting Catalog, including validity masks as null. The complete source is PlussMic/examples/bundle/locus_pull_reference_demo.cpp; every output block on these pages comes from that executable.

Method Pages¶

  • add() appends explicit plain, aggregate, or windowed specifications.

  • agg() binds one related catalog for a sequence of scoped reducers.

  • collect() validates and executes the complete root-grain plan.

  • count() counts usable related values.

  • max() selects each group’s upper numeric extreme.

  • mean() computes the arithmetic center.

  • median() computes the order-statistic center.

  • min() selects each group’s lower numeric extreme.

  • ndistinct() counts unique usable values.

  • options() replaces raggedness and root-key policy.

  • root() reports the catalog that owns the output grain.

  • specs() exposes the ordered stored request vector without executing it.

  • std() computes sample standard deviation.

  • sum() totals usable numeric values.

  • take() appends plain root or related-catalog streams through root-preserving paths.

  • var() computes sample variance.
