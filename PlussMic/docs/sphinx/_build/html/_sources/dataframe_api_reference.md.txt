# DataFrame API Reference

# Practical DataFrame API Reference

## API Reference Style

This page documents the full public `DataFrame` surface with usage-first examples generated from the current table API.

## A

### `add`

#### API Signatures

```cpp
DataFrame add(double other) const
DataFrame add(const DataFrame& other) const
```

#### Parameters

`other` in `add(double other)`
    Scalar added to every compatible numeric feature in the frame. Non-numeric features pass through unchanged.

`other` in `add(const DataFrame& other)`
    Right-hand frame used for feature-wise arithmetic. The two frames must be aligned in height and schema.

#### What It Does

`add(...)` is the explicit method form of `+` for frames.

#### Examples

Add a scalar to every numeric feature:

```cpp
auto sales = pluss::table::DataFrame({
    {"city", pluss::make_note({"Accra", "Tema", "Kumasi"})},
    {"units", pluss::make_series({10.0, 7.0, 12.0})},
    {"price", pluss::make_series({3.0, 4.0, 2.5})},
});

auto bumped = sales.add(1.0);
```

#### Output

```text
===========================
     | city    units  price
---------------------------
0    | Accra   11     4
1    | Tema    8      5
2    | Kumasi  13     3.5
---------------------------
[3 cs x 3 feat]
```

Add two aligned numeric frames feature-by-feature:

```cpp
auto left = pluss::table::DataFrame({
    {"midterm_1", pluss::make_series({15.0, 18.0, 12.0})},
    {"midterm_2", pluss::make_series({16.0, 14.0, 13.0})},
});

auto curve = pluss::table::DataFrame({
    {"midterm_1", pluss::make_series({1.0, 1.0, 1.0})},
    {"midterm_2", pluss::make_series({0.5, 0.5, 0.5})},
});

auto curved = left.add(curve);
```

#### Output

```text
===========================
     | midterm_1  midterm_2
---------------------------
0    | 16         16.5
1    | 19         14.5
2    | 13         13.5
---------------------------
[3 cs x 2 feat]
```

### `add_prefix`

#### API Signature

```cpp
DataFrame add_prefix(std::string_view prefix) const
```

#### Parameters

`prefix` : `std::string_view`
    Text prepended to every feature name. Values, case labels, and row order are unchanged.

#### What It Does

Renames every feature by adding the same prefix.

#### Examples

```cpp
auto sales = pluss::table::DataFrame({
    {"city", pluss::make_note({"Accra", "Tema", "Kumasi"})},
    {"units", pluss::make_series({10.0, 7.0, 12.0})},
    {"price", pluss::make_series({3.0, 4.0, 2.5})},
});

auto tagged = sales.features({"units", "price"}).add_prefix("exam_");
```

#### Output

```text
=============================
     | exam_units  exam_price
-----------------------------
0    | 10          3
1    | 7           4
2    | 12          2.5
-----------------------------
[3 cs x 2 feat]
```

### `aggregate`

#### API Signature

```cpp
DataFrameView aggregate(pluss::msharp::RangeView::Of<SummarySpec> specs,
                        bool render = true) const
```

#### Parameters

`specs` : `pluss::msharp::RangeView::Of<SummarySpec>`
    One or more summary definitions. Each `SummarySpec` controls one output feature in the summary frame.

`SummarySpec.output`
    Output feature name. If you leave it empty, PlussMic auto-generates a name from the source feature and operation.

`SummarySpec.feature`
    Source feature to summarize.

`SummarySpec.op`
    Reduction to apply. Common values include `Count`, `Nunique`, `Sum`, `Mean`, `Median`, `Min`, `Max`, `Std`, `Var`, and `Prod`.

`render` : `bool`
    Controls whether the returned `DataFrameView` auto-renders when used as a temporary in a terminal context. Use `false` in examples, tests, and pipelines where you want explicit output control.

#### What It Does

Builds a one-row summary view from one or more aggregation specs.

#### Examples

Compute one named summary metric:

```cpp
auto grades = pluss::table::DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"assignment", pluss::make_series({9.5, 8.0, 7.5})},
    {"final", pluss::make_series({28.0, 24.0, 21.5})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto summary = grades.aggregate({
    {"mean_final", "final", pluss::table::DataFrame::SummaryOp::Mean},
}, false);
```

#### Output

```text
====================
        | mean_final
--------------------
summary | 24.5
--------------------
[1 cs x 1 feat]
```

Compute several metrics at once:

```cpp
auto summary = grades.aggregate({
    {"n_students", "final", pluss::table::DataFrame::SummaryOp::Count},
    {"max_final", "final", pluss::table::DataFrame::SummaryOp::Max},
    {"min_final", "final", pluss::table::DataFrame::SummaryOp::Min},
}, false);
```

#### Output

```text
==========================================
        | n_students  max_final  min_final
------------------------------------------
summary | 3           28         21.5
------------------------------------------
[1 cs x 3 feat]
```

Let PlussMic auto-name the outputs:

```cpp
auto summary = grades.aggregate({
    {"", "assignment", pluss::table::DataFrame::SummaryOp::Mean},
    {"", "assignment", pluss::table::DataFrame::SummaryOp::Std},
}, false);
```

#### Output

```text
=========================================
        | assignment_mean  assignment_std
-----------------------------------------
summary | 8.333333333      1.040833
-----------------------------------------
[1 cs x 2 feat]
```

### `align_cases`

#### API Signature

```cpp
DataFrame align_cases(const Thread& new_cases) const
```

#### Parameters

`new_cases` : `const Thread&`
    Target case axis. Its labels determine the output row order.

#### What It Does

Reorders rows to match the supplied case labels and replaces the frame's case axis with that ordering.

#### Examples

```cpp
auto grades = pluss::table::DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"assignment", pluss::make_series({9.5, 8.0, 7.5})},
    {"final", pluss::make_series({28.0, 24.0, 21.5})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto scratch = pluss::table::DataFrame({
    {"score", pluss::make_series({88.0, 79.0, 91.0})},
}, pluss::make_note({"s2", "s3", "s1"}));

auto aligned = scratch.align_cases(grades.cases());
```

#### Output

```text
============
     | score
------------
s1   | 91
s2   | 88
s3   | 79
------------
[3 cs x 1 feat]
```

### `all`

#### API Signatures

```cpp
Thread all(pluss::msharp::RangeView::Of<std::string_view> features = {},
           bool skipna = true) const

Thread all(std::int64_t axis,
           pluss::msharp::RangeView::Of<std::string_view> features = {},
           bool skipna = true) const
```

#### Parameters

`axis` : `std::int64_t`
    Reduction direction.
    `0` reduces down rows and returns one boolean per selected feature.
    `1` reduces across selected features and returns one boolean per row.

`features` : `pluss::msharp::RangeView::Of<std::string_view>`
    Optional feature subset. If omitted, all eligible features participate.

`skipna` : `bool`
    When `true`, missing values are skipped during the reduction. When `false`, missing state can affect the result.

#### What It Does

Computes "are all values true?" reductions over boolean-compatible feature sets.

#### Examples

Feature-wise reduction:

```cpp
auto flags = pluss::table::DataFrame({
    {"quiz_ok", pluss::make_series(std::vector<bool>{true, true, false})},
    {"exam_ok", pluss::make_series(std::vector<bool>{true, false, false})},
    {"bonus_ok", pluss::make_series(std::vector<bool>{true, true, true})},
});

auto out = flags.all();
```

#### Output

```text
 quiz_ok  false
 exam_ok  false
bonus_ok  true
dtype: Series
```

Row-wise reduction:

```cpp
auto out = flags.all(1);
```

#### Output

```text
0  true
1  false
2  false
dtype: Series
```

### `assign`

#### API Signatures

```cpp
DataFrame assign(pluss::msharp::RangeView::Of<std::pair<std::string, Thread>> assignments) const
DataFrame assign(pluss::msharp::RangeView::Of<DeriveSpec> specs) const
```

#### Parameters

`assignments`
    Direct feature-to-thread assignments. Use this form when you already computed the thread outside the call.

`assignments.first`
    Target feature name.

`assignments.second`
    Thread to insert or replace.

`specs`
    Derived assignments evaluated inside the call.

`DeriveSpec.feature`
    Target feature name.

`DeriveSpec.expr`
    Function of type `Thread(const DataFrame&)` that computes the new feature.

#### What It Does

Returns a new frame with added or replaced features.

#### Examples

Assign a thread you already computed:

```cpp
pluss::table::Thread total_grade(const pluss::table::DataFrame& df) {
    return df.features("assignment") + df.features("final");
}

auto grades = pluss::table::DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"assignment", pluss::make_series({9.5, 8.0, 7.5})},
    {"final", pluss::make_series({28.0, 24.0, 21.5})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto out = grades.assign({
    std::pair<std::string, pluss::table::Thread>{"total", total_grade(grades)},
});
```

#### Output

```text
========================================
     | student  assignment  final  total
----------------------------------------
s1   | Ada      9.5         28     37.5
s2   | Bola     8           24     32
s3   | Chen     7.5         21.5   29
----------------------------------------
[3 cs x 4 feat]
```

Compute multiple derived features inside the call:

```cpp
auto out = grades.assign({
    pluss::table::DataFrame::DeriveSpec{
        .feature = "total",
        .expr = total_grade,
    },
    pluss::table::DataFrame::DeriveSpec{
        .feature = "passed",
        .expr = [](const pluss::table::DataFrame& df) {
            return df.features("total") >= 30.0;
        },
    },
});
```

#### Output

```text
================================================
     | student  assignment  final  total  passed
------------------------------------------------
s1   | Ada      9.5         28     37.5   true
s2   | Bola     8           24     32     true
s3   | Chen     7.5         21.5   29     false
------------------------------------------------
[3 cs x 5 feat]
```

## B

`DataFrame` currently has two public methods in the `B` section: `bfill` and `bottom`.

### `bfill`

#### API Signature

```cpp
DataFrame bfill() const
```

#### Parameters

None.

#### What It Does

Backward-fills missing values in each feature from the next available non-missing value below them.

#### Examples

```cpp
auto df = pluss::table::DataFrame({
    {"score", pluss::make_series({72.0, std::numeric_limits<double>::quiet_NaN(), 81.0, 90.0})},
});

auto out = df.bfill();
```

#### Output

```text
============
     | score
------------
0    | 72
1    | 81
2    | 81
3    | 90
------------
[4 cs x 1 feat]
```

### `bottom`

#### API Signature

```cpp
DataFrame bottom(std::string_view feature_name, std::int64_t n) const
```

#### Parameters

`feature_name` : `std::string_view`
    Feature used for ascending ordering before the lowest rows are selected.

`n` : `std::int64_t`
    Number of rows to keep from the bottom of the ordered frame.

#### What It Does

Returns the lowest `n` rows by the chosen feature.

#### Examples

```cpp
auto grades = pluss::table::DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"assignment", pluss::make_series({9.5, 8.0, 7.5})},
    {"final", pluss::make_series({28.0, 24.0, 21.5})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto out = grades.bottom("final", 2);
```

#### Output

```text
=================================
     | student  assignment  final
---------------------------------
s3   | Chen     7.5         21.5
s2   | Bola     8           24
---------------------------------
[2 cs x 3 feat]
```

## C

### `cases`

#### API Signatures

```cpp
const Thread& cases() const
DataFrame cases(std::int64_t row) const
DataFrame cases(std::pair<std::int64_t, std::int64_t> row_span) const
std::string cases(std::int64_t row, std::size_t feature_idx) const
std::string cases(std::int64_t row, std::string_view feature_name) const
```

#### Arguments

- `row`: zero-based row position for the row slice or cell lookup.
- `row_span`: row slice as `{start, stop}` with `start` inclusive and `stop` exclusive.
- `feature_idx`: zero-based feature position for rendered cell lookup.
- `feature_name`: named feature for rendered cell lookup.

#### What It Does

`cases(...)` is the case-axis access surface.

- `cases()` returns the current case axis `Thread`.
- `cases(row)` returns one row as a one-case `DataFrame`.
- `cases({start, stop})` returns a row slice.
- `cases(row, feature_idx)` and `cases(row, feature_name)` return one rendered cell as text.

#### Examples

Example 1: inspect the current case labels.

```cpp
auto grades = pluss::table::DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"final", pluss::make_series({91.0, 84.0, 77.0})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto ids = grades.cases();
```

Example 2: slice one row or a row range.

```cpp
auto first_row = grades.cases(0);
auto first_two = grades.cases({0, 2});
```

Example 3: read one cell as rendered text.

```cpp
std::string who = grades.cases(1, "student");
std::string score = grades.cases(1, 1);
```

#### Behavior Notes

- The row-slice overloads preserve feature names and case labels for the returned slice.
- The cell overloads return rendered strings, not typed scalars.
- For typed work, access the feature as a `Thread` instead of going through the string-render path.

### `cases_series`

#### API Signature

```cpp
pluss::Series cases_series() const
```

#### Arguments

- None.

#### What It Does

Returns the case axis as a `pluss::Series` when the case axis is actually Series-backed.

#### Examples

Example 1: numeric case labels can be pulled out directly as a `Series`.

```cpp
auto df = pluss::table::DataFrame({
    {"score", pluss::make_series({72.0, 81.0, 90.0})},
}, pluss::make_series({101.0, 102.0, 103.0}));

auto case_series = df.cases_series();
```

Example 2: use the case series in downstream numeric work.

```cpp
auto shifted = df.cases_series() + 1000.0;
```

#### Behavior Notes

- This throws if the case axis is not Series-backed.
- If your cases are text labels, use `cases()` and then `as_note()` instead.

### `cast`

#### API Signatures

```cpp
DataFrame cast(pluss::msharp::RangeView::Of<CastSpec> specs) const
DataFrame cast(
    pluss::msharp::RangeView::Of<std::pair<std::string_view, pluss::codem::ScalarType>> feature_dtypes) const
```

#### Arguments

- `specs`: one or more `CastSpec` entries.
  - `feature`: feature to rewrite.
  - `target`: target thread kind such as `Series`, `Note`, `Timeline`, or `TimeIndex`.
  - `series_dtype`: optional numeric dtype when the target is `Series`.
- `feature_dtypes`: per-feature numeric dtype map.

#### What It Does

`cast(...)` is the broad typed-conversion surface.

- Use `cast(specs)` when different features need different target thread kinds.
- Use `cast(feature_dtypes)` when every selected target is still numeric `Series`, but the dtypes differ by column.

#### Examples

Example 1: mixed cast targets in one call.

```cpp
auto typed = raw.cast({
    {.feature = "OrgDefinedId", .target = pluss::table::ThreadCastTarget::Note},
    {.feature = "Date Entered", .target = pluss::table::ThreadCastTarget::Timeline},
    {
        .feature = "Final Points Grade",
        .target = pluss::table::ThreadCastTarget::Series,
        .series_dtype = pluss::codem::ScalarType::Float64,
    },
});
```

Example 2: numeric dtype map form.

```cpp
auto typed = raw.cast({
    {"student_id", pluss::codem::ScalarType::Int64},
    {"final_score", pluss::codem::ScalarType::Float64},
});
```

Example 3: combine direct cast helpers and broad cast intentionally.

```cpp
auto typed = raw
    .cast_note({"Username"})
    .cast({
        {.feature = "Date Entered", .target = pluss::table::ThreadCastTarget::Timeline},
    });
```

#### Behavior Notes

- Only selected features are rewritten.
- Duplicate feature requests are ignored after the first occurrence.
- Unknown or empty feature names throw.
- `astype(feature_dtypes)` is the alias of the dtype-map overload shown here.

### `cast_series`

- This is the explicit method behind `astype(features, dtype)`.
- Unknown or empty feature names throw.
- Duplicate names in the request are ignored after the first occurrence.

### `ceil_time`

#### API Signature

```cpp
DataFrame ceil_time(pluss::msharp::RangeView::Of<std::string_view> features,
                    std::string_view unit) const
```

#### Arguments

- `features`: target temporal features. Pass `{}` to apply to all eligible Timeline and TimeIndex features in the frame.
- `unit`: temporal rounding unit such as `"hour"`, `"day"`, or `"month"`.

#### What It Does

Rounds selected temporal features upward to the requested unit boundary.

#### Examples

Example 1: ceil one timeline feature to hourly buckets.

```cpp
auto hourly = logs.ceil_time({"ts"}, "hour");
```

Example 2: ceil every time-like feature in the frame.

```cpp
auto rounded = logs.ceil_time({}, "day");
```

Example 3: cast and round in one chain.

```cpp
auto rounded = raw
    .cast_timeline({"Date Entered"})
    .ceil_time({"Date Entered"}, "day");
```

#### Behavior Notes

- `unit` must be non-empty.
- Only Timeline and TimeIndex features are valid targets.
- The output preserves validity masks on the affected columns.

### `cloc`

#### API Signatures

```cpp
DataFrame cloc(std::int64_t row) const
DataFrame cloc(std::int64_t start, std::int64_t stop) const
```

#### Arguments

- `row`: one zero-based case position.
- `start`: inclusive starting row.
- `stop`: exclusive ending row.

#### What It Does

`cloc(...)` is the case-location row slicer.

- `cloc(row)` is the one-row form.
- `cloc(start, stop)` is the range form.

#### Examples

Example 1: grab one case by position.

```cpp
auto row0 = grades.cloc(0);
```

Example 2: grab a contiguous row span.

```cpp
auto window = grades.cloc(10, 20);
```

Example 3: use it where a row-slicing name reads better than `cases(...)`.

```cpp
auto preview = grades.cloc(0, 5);
```

#### Behavior Notes

- `cloc(row)` is the row-slice alias of `cases(row)`.
- `cloc(start, stop)` is the row-slice alias of `slice(start, stop)`.
- This is row-position access, not feature selection.

### `combine`

#### API Signatures

```cpp
DataFrame combine(const DataFrame& other) const
DataFrame combine(const DataFrame& other, const CombineSpec& spec) const
```

#### Arguments

- `other`: right-hand frame to combine with the current frame.
- `spec`: combine policy.
  - `op = CombineOp::Features`: append right-hand features onto the left frame.
  - `op = CombineOp::Update`: update overlapping left-hand features from the right frame.
  - `collision_suffix`: suffix used when feature-name collisions happen in feature-append mode. The default is `"_right"`.
  - `overwrite`: in update mode, controls whether overlapping left features are replaced.

#### What It Does

`combine(...)` is the lower-level frame composition surface behind the more specialized helpers.

- In feature mode, right-hand features are appended.
- In update mode, overlapping left-hand features can be replaced from the right.
- The output always keeps the left frame's case axis.

#### Examples

Example 1: append new features from the right frame.

```cpp
auto left = pluss::table::DataFrame({
    {"student", pluss::make_note({"s1", "s2", "s3"})},
    {"midterm", pluss::make_series({75.0, 81.0, 68.0})},
});

auto right = pluss::table::DataFrame({
    {"final", pluss::make_series({84.0, 90.0, 71.0})},
});

auto merged = left.combine(right);
```

Example 2: keep both colliding feature names by suffixing the right side.

```cpp
auto left = pluss::table::DataFrame({
    {"score", pluss::make_series({70.0, 80.0})},
});

auto right = pluss::table::DataFrame({
    {"score", pluss::make_series({71.0, 79.0})},
});

pluss::table::DataFrame::CombineSpec spec;
spec.op = pluss::table::DataFrame::CombineOp::Features;
spec.collision_suffix = "_regrade";

auto compared = left.combine(right, spec);
```

Example 3: update only overlapping columns.

```cpp
auto base = pluss::table::DataFrame({
    {"midterm", pluss::make_series({75.0, 81.0, 68.0})},
    {"final", pluss::make_series({84.0, 90.0, 71.0})},
});

auto corrections = pluss::table::DataFrame({
    {"final", pluss::make_series({85.0, 90.0, 72.0})},
    {"bonus", pluss::make_series({1.0, 0.0, 2.0})},
});

pluss::table::DataFrame::CombineSpec spec;
spec.op = pluss::table::DataFrame::CombineOp::Update;
spec.overwrite = true;

auto updated = base.combine(corrections, spec);
```

#### Behavior Notes

- Both frames must have the same case count.
- In feature mode, non-colliding right-hand features append directly.
- In feature mode, colliding right-hand names require a non-empty `collision_suffix`.
- In update mode, right-only features are ignored.
- In update mode, `overwrite = false` leaves overlapping left-hand features untouched.

### `compare`

#### API Signatures

```cpp
DataFrame compare(double other) const
DataFrame compare(const DataFrame& other) const
```

#### Arguments

- `other` in `compare(double other)`: scalar used for frame-vs-scalar mismatch comparison.
- `other` in `compare(const DataFrame& other)`: right-hand frame used for frame-vs-frame mismatch comparison.

#### What It Does

In the current implementation, `compare(...)` is the explicit method form of `ne(...)`.

- `compare(2.0)` returns a boolean mismatch frame against the scalar.
- `compare(other_frame)` returns a boolean mismatch frame against the other frame.
- This is a mask-producing comparison surface, not a rich diff-table renderer.

#### Examples

Example 1: mark cells that are not equal to zero.

```cpp
auto nonzero = scores.compare(0.0);
```

Example 2: mark cells that differ between two aligned frames.

```cpp
auto changed = old_scores.compare(new_scores);
```

Example 3: use the result as a boolean frame for later inspection.

```cpp
auto diff_mask = official.compare(scratch);
auto any_diff = diff_mask.any(1);
```

#### Behavior Notes

- The scalar overload follows the same compatibility rules as `ne(double)`.
- The frame overload follows the same schema requirements as frame-to-frame comparison elsewhere in the API.
- If you want an equality mask, use `eq(...)` instead.

### `conform_to`

#### API Signature

```cpp
DataFrame conform_to(const DataFrame& other) const
```

#### Arguments

- `other`: reference frame whose feature order and case order should drive the output.

#### What It Does

Rewrites the current frame so it conforms to another frame's schema and case order.

Internally this means:

- first reorder the current feature set to match `other.feature_names()` exactly,
- then align the current rows to `other.cases()`.

#### Examples

Example 1: reorder a scratch frame to match the official schema before comparison.

```cpp
auto official = pluss::table::DataFrame({
    {"student", pluss::make_note({"s1", "s2", "s3"})},
    {"midterm", pluss::make_series({75.0, 81.0, 68.0})},
    {"final", pluss::make_series({84.0, 90.0, 71.0})},
}, pluss::make_note({"s1", "s2", "s3"}));

auto scratch = pluss::table::DataFrame({
    {"final", pluss::make_series({90.0, 71.0, 84.0})},
    {"student", pluss::make_note({"s2", "s3", "s1"})},
    {"midterm", pluss::make_series({81.0, 68.0, 75.0})},
}, pluss::make_note({"s2", "s3", "s1"}));

auto conformed = scratch.conform_to(official);
```

Example 2: normalize layout before a strict frame-to-frame arithmetic operation.

```cpp
auto aligned = scratch.conform_to(official);
auto delta = aligned.sub(official);
```

#### Behavior Notes

- The current frame must contain the full feature set required by `other`.
- Feature count must match exactly.
- Every case label requested by `other.cases()` must exist in the current frame.

## J

### `join`

#### Signature

```cpp
DataFrame join(const DataFrame& other, std::string collision_suffix = "_right") const
```

Combines features from another frame by row position and case axis, not by key lookup.

#### Parameters

`other` : `const DataFrame&`
    Right-hand frame to append.

`collision_suffix` : `std::string`
    Suffix used when the right frame contains a feature name that already exists on the left.

#### Returns

`DataFrame`
    Combined frame.

#### See also

- `unify(...)`
- `update(...)`

#### Behavior Notes

- `join(...)` is a feature-wise combine.
- It does not do keyed matching. If you want matching by `OrgDefinedId`, `Username`, or any other join key, use `unify(...)`.
- Name collisions on the right side are resolved with `collision_suffix`.

#### Examples

Default suffix behavior:

```cpp
auto sales = pluss::table::DataFrame({
    {"city", pluss::make_note({"Accra", "Tema", "Kumasi", "Tamale"})},

    {"price", pluss::make_series({3.0, 4.0, 2.5, 5.0})},
}).title("sales");

auto metadata = pluss::table::DataFrame({
    {"region", pluss::make_note({"capital", "harbor", "garden", "savannah"})},
    {"inventory", pluss::make_series({100.0, 80.0, 65.0, 40.0})},
}).title("metadata");

std::cout << sales.join(metadata).to_string();
```

#### Output

```text
============================================================
     | city    region  units  price  region_right  inventory

0    | Accra   south   10     3      capital       100

2    | Kumasi  middle  12     2.5    garden        65
3    | Tamale  north   5      5      savannah      40
------------------------------------------------------------
[4 cs x 6 feat]
```

std::cout << sales.join(metadata, "_meta").to_string();

### `resample`

#### Signature

```cpp
DataFrameView resample(self, std::string_view time_feature, pluss::msharp::RangeView::Of<std::string_view> value_features, std::string_view freq, std::string_view op = "mean", std::int64_t step = 1, bool render = true) const
```

#### Parameters

`time_feature` : `std::string_view`
    Name of the Timeline or TimeIndex feature that defines the resampling axis. The feature must already exist in the frame and must be temporal.

`value_features` : `pluss::msharp::RangeView::Of<std::string_view>`
    Value feature names to aggregate into the new bins. If you leave this empty, PlussMic auto-selects compatible features: numeric Series for numeric reductions, and any non-time feature for `count` and `size`.

`freq` : `std::string_view`
    Bin frequency such as `"1h"`, `"6h"`, `"D"`, `"W"`, or `"M"`. Bins are anchored from the start of the local day for fixed-frequency resampling.

`op` : `std::string_view`
    Aggregation to run inside each bin. Supported values are `"mean"`, `"sum"`, `"min"`, `"max"`, `"first"`, `"last"`, `"count"`, and `"size"`. `count` ignores missing values; `size` counts rows.

`step` : `std::int64_t`
    Frequency multiplier. For example, `"h"` with `step = 6` means six-hour bins, and `"D"` with `step = 7` means seven-day bins.

`render` : `bool`
    Controls whether the returned `DataFrameView` auto-renders when used as a temporary. Use `false` in tests, docs, and pipelines where you want explicit output control.

#### Returns

`DataFrameView`
    Value produced by this call.

#### Notes

This is the frame-level resampling surface. It groups rows into time bins using `time_feature`, preserves bin order, and computes one aggregated output value per selected feature and bin.

#### Examples

```cpp
auto intraday = pluss::table::DataFrame({
    {"ts", pluss::table::Thread(pluss::make_timeline({
        "2024-01-01T09:10:00Z",
        "2024-01-01T09:40:00Z",
        "2024-01-01T10:05:00Z",
    }))},
    {"load", pluss::table::Thread(pluss::make_series({10.0, 20.0, 15.0}))},
});

auto out = intraday.resample("ts", {"load"}, "1h", "mean", 1, false);
```

#### Output

```text
ts                   load
2024-01-01T09:00:00Z  15.0
2024-01-01T10:00:00Z  15.0
```

        "2024-01-02T10:05:00Z",

### `reshuffle`

#### Signature

```cpp
DataFrame reshuffle(self, int axis = 0, std::optional<std::uint64_t> random_state = std::nullopt) const
```

#### Parameters

`axis` : `int`
    Shuffle direction. Use `0` to shuffle rows and keep feature order unchanged. Use `1` to shuffle feature order and keep rows unchanged.

    Optional seed for deterministic shuffling. Pass the same seed to reproduce the same permutation later.

#### Returns

    A shuffled frame with the same payload values, same case count, and same feature set.

#### Notes

Use `reshuffle(...)` when you want random order without dropping rows or features. It is the full-frame version of `sample(...)` without row-count reduction.

#### Examples

```cpp

    {"student", pluss::table::Thread(pluss::make_note({"Ada", "Bola", "Chen"}))},
    {"assignment", pluss::table::Thread(pluss::make_series({9.5, 8.0, 7.5}))},
    {"final", pluss::table::Thread(pluss::make_series({28.0, 24.0, 21.5}))},
}, pluss::table::Thread(pluss::make_note({"s1", "s2", "s3"})));

auto out = grades.reshuffle(0, 7);
```

#### Output

```text
====================================
   | student  assignment  final
------------------------------------
s3 | Chen     7.5         21.5
s2 | Bola     8           24
s1 | Ada      9.5         28
------------------------------------
[3 cs x 3 feat]
```

Shuffle feature order reproducibly:

### `with_cases`

#### Signature

```cpp
DataFrame with_cases(self, const Thread& cases) const
```

#### Parameters

`cases` : `const Thread&`
    Case-label thread to attach to the current object.

#### Returns

`DataFrame`
    Value produced by this call.

#### Notes

Replaces the current case axis with the supplied thread. The row values stay in the same order, but later case-aware operations now use the new labels.

#### Examples

```cpp
auto df = pluss::table::DataFrame({
    {"id", pluss::table::Thread(pluss::make_series({1, 2, 3}))},
    {"sales", pluss::table::Thread(pluss::make_series({100.0, 120.0, 90.0}))},
    {"city", pluss::table::Thread(pluss::make_note({"Accra", "Tema", "Kumasi"}))},
});

auto cases = pluss::table::Thread(pluss::make_note({"cs0", "cs1", "cs2"}));
auto out = df.with_cases(cases);
```

#### Output

```text
df.cases():
[0, 1, 2]

out.cases():
["cs0", "cs1", "cs2"]

out.head():
id  sales  city
1   100.0  Accra
2   120.0  Tema
3    90.0  Kumasi
```
