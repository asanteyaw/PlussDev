# DataFrame::rxor

[Back to DataFrame API Reference](../../dataframe_api_reference)

## Signatures

```cpp
DataFrame::rxor(const DataFrame& other) const -> DataFrame
DataFrame::rxor(const Slate& other) const -> DataFrame
```

## What It Does

The reflected form of [`lxor()`](lxor.md). Since logical XOR is commutative,
`frame.rxor(other)` is indistinguishable from `frame.lxor(other)` in every observable
respect — same cell values, and (for the `DataFrame` overload) the same case labels
and title, both drawn from `frame` itself, exactly as [`lxor()`](lxor.md) documents.
See [`rand()`](rand.md) for the full explanation, including a note on a previous
revision where the `DataFrame` overload's case labels came from `other` instead —
that has since been fixed, and `rxor()` shares the fix.

## Parameters

**other**

`const DataFrame&` or `const Slate&` — identical shape requirements to
[`land()`](land.md).

## Returns

`DataFrame`
    A new frame holding the logical XOR of each cell against the corresponding `other`
    value, with case labels and title drawn from the frame `rxor()` was called on —
    identical in every respect to what [`lxor()`](lxor.md) would produce for the same
    arguments.

## Examples

Example 1. `rxor()` and `lxor()` produce identical results, values and case labels
both.

```cpp
using namespace pluss::table;

auto left = DataFrame({
    {"a", pluss::make_series({true, false, true}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
}, pluss::make_note({"p", "q", "r"}));

auto right = DataFrame({
    {"a", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({false, true, true}, pluss::ScalarType::Bool)},
}, pluss::make_note({"x", "y", "z"}));

auto out = left.rxor(right);
std::cout << out;
```

### Output

```text
===================
     | a      b    
-------------------
p    | false  true 
q    | true   false
r    | true   true 
-------------------
[3 cs x 2 feat]
```

The values match [`left.lxor(right)`](lxor.md) exactly, and the case labels are
`left`'s own (`p, q, r`) — `right`'s labels (`x, y, z`) never appear in the result.

Example 2. XOR against a single shared `Slate`, applied identically to every
feature — same result as [`left.lxor(mask)`](lxor.md).

```cpp
auto mask = Slate(pluss::make_series({false, true, false}, pluss::ScalarType::Bool));
auto out_thread = left.rxor(mask);
std::cout << out_thread;
```

### Output

```text
===================
     | a     b    
-------------------
p    | true  true 
q    | true  false
r    | true  false
-------------------
[3 cs x 2 feat]
```

## Notes

- `rxor()` and [`lxor()`](lxor.md) are fully interchangeable for `DataFrame`
  arguments — same values, same case labels, same title. The reflected name exists
  purely for symmetry with the rest of the reflected method family, not because it
  produces a different result here.
- Requires a genuine `Bool` scalar type on every participating `Series`, same as
  [`land()`](land.md).
