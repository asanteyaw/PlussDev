# TimeSeriesAccessor::returns

[Back to TimeSeriesAccessor API Reference](../../slate_ts_accessor_api_reference)

## Signature

```cpp
TimeSeriesAccessor::returns(std::int64_t periods = 1) const -> Slate
```

## What It Does

Computes the fractional period-over-period change of the bound thread:
`out[i] = x[i] / base[i] - 1`, where `base` is `x` shifted by `periods` (a lag when
`periods > 0`, a lead when `periods < 0`). A position is `NULL` wherever `x[i]` or
`base[i]` is missing, `base[i]` is `0`, or either value is non-finite. Restricted
to a numeric `Series` thread; anything else throws.

## Parameters

**periods** (`std::int64_t`, default `1`)
    The shift distance used to build the comparison base. Positive shifts compare
    each position against an earlier one (a lag); negative shifts compare against
    a later one (a lead). Must not be `0`, or the call throws.

## Returns

`Slate`
    A new thread, same length as the bound source, holding the period-over-period
    fractional return.

## Examples

Example 1. Compute the one-period return of a numeric thread.

```cpp
using namespace pluss::table;

auto load = Slate(pluss::make_series({10.0, 20.0, 15.0, 30.0}));
auto out = load.ts().returns(1);
std::cout << out;
```

### Output

```text
0  NULL
1  1
2  -0.25
3  1

ptype: Series
```

Position `0` has no prior position to compare against, so it's `NULL`. Position
`1` is `20 / 10 - 1 = 1` (a 100% increase); position `2` is `15 / 20 - 1 = -0.25`
(a 25% decrease); position `3` is `30 / 15 - 1 = 1`.

Example 2. Pass a negative `periods`, comparing each position against a *later*
one (a lead) instead of an earlier one.

```cpp
auto out_lead = load.ts().returns(-1);
std::cout << out_lead;
```

### Output

```text
0  -0.5
1  0.3333333333
2  -0.5
3  NULL

ptype: Series
```

With `periods = -1`, each position's `base` is the *next* position instead of
the previous one: position `0` is `10 / 20 - 1 = -0.5`; position `1` is
`20 / 15 - 1 = 0.3333`; position `2` is `15 / 30 - 1 = -0.5`. Position `3` has no
later position to serve as `base`, so it's `NULL` this time — the mirror image of
Example 1's default (`periods = 1`), where it was position `0` that had no prior
position.

Example 3. A `base` of exactly `0` comes back `NULL` rather than infinity.

```cpp
using namespace pluss::table;

auto delta = Slate(pluss::make_series({10.0, 0.0, 20.0}));
auto out2 = delta.ts().returns(1);
std::cout << out2;
```

### Output

```text
0  NULL
1  -1
2  NULL

ptype: Series
```

Position `1` (`x = 0`, base `= 10`) is an ordinary `0 / 10 - 1 = -1`. Position `2`
(`x = 20`, base `= 0`) has a `base` of exactly `0` — rather than dividing by zero,
`returns()` reports `NULL` directly, per the rule stated above.

Example 4. A pre-existing missing entry in the source thread propagates into
every return that touches it.

```cpp
auto with_gap = Slate(
    pluss::make_series({10.0, 20.0, 30.0, 40.0}),
    pluss::make_series(std::vector<bool>{true, false, true, true})
);
auto out3 = with_gap.ts().returns(1);
std::cout << out3;
```

### Output

```text
0  NULL
1  NULL
2  NULL
3  0.3333333333

ptype: Series
```

Position `1` is `NULL` because `x[1]` (`20.0`) itself is masked-missing. Position
`2` is `NULL` because its `base` (`x[1]`) is missing, even though `x[2]` (`30.0`)
is a real, valid value. Only position `3` (`40 / 30 - 1 ≈ 0.3333`) has both sides
valid.

Example 5. Pass `periods = 0`, to see the call throw.

```cpp
try {
  auto out4 = load.ts().returns(0);
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}
```

### Output

```text
subsp::stats::ts::returns: periods cannot be zero
```

Comparing each position against itself isn't a meaningful return, so
`periods = 0` is rejected outright rather than silently returning all-zero
output.

## Notes

- A `base` value of exactly `0` always produces `NULL`, regardless of `x[i]`,
  since the fractional change would otherwise be undefined or infinite.
- A pre-existing missing entry in the source thread is honored — it produces
  `NULL` in every return that would otherwise reference it. See Example 4.
- `periods` must not be `0`, or it throws
  `"subsp::stats::ts::returns: periods cannot be zero"`.
- Restricted to numeric `Series` payloads; a `Note`/`Timeline`/`TimeIndex` thread
  throws `"TimeSeriesAccessor::returns: source must be Series"`; a non-numeric
  `Series` throws `"TimeSeriesAccessor::returns: source Series must be numeric"`.
