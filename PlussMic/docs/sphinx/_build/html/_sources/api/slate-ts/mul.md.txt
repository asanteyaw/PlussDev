# TimeSeriesAccessor::mul

[Back to TimeSeriesAccessor API Reference](../../slate_ts_accessor_api_reference)

## Signature

```cpp
TimeSeriesAccessor::mul(const Slate& other, const Slate& left_axis, const Slate& right_axis, TsAlignMode mode = TsAlignMode::Exact) const -> Slate
```

## What It Does

Multiplies the bound thread by `other` **after first reindexing `other` onto
the bound thread's own positions**, using `left_axis` (the bound thread's time
axis) and `right_axis` (`other`'s own time axis) — exactly the same alignment
[`align_to()`](align_to.md) performs, run automatically before an ordinary
[`Slate::mul`](../thread/mul.md). See [`add()`](add.md) for the shared
alignment mechanics this method also uses.

## Parameters

**other** (`const Slate&`)
    The thread to multiply by, currently living at `right_axis` ticks.

**left_axis** (`const Slate&`)
    The bound thread's own time axis (`Timeline`/`TimeIndex`), same length as
    the bound thread.

**right_axis** (`const Slate&`)
    `other`'s time axis (`Timeline`/`TimeIndex`), same length as `other`.

**mode** (`TsAlignMode`, default `Exact`)
    The alignment strategy — same meaning as [`align_to()`](align_to.md)'s
    `mode`: `Exact`, `Backward`, `Forward`, or `Nearest`.

## Returns

`Slate`
    A new thread, same length as the bound thread, holding
    `bound * aligned(other)` at each position.

## Examples

Example 1. Two threads on different daily axes, multiplied after exact
alignment.

```cpp
using namespace pluss::table;

auto left_axis = Slate(pluss::make_timeline(
    {"2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z", "2024-01-03T00:00:00Z"}));
auto left = Slate(pluss::make_series({10.0, 20.0, 30.0}));

auto right_axis = Slate(pluss::make_timeline(
    {"2024-01-02T00:00:00Z", "2024-01-04T00:00:00Z"}));
auto right = Slate(pluss::make_series({100.0, 200.0}));

auto out = left.ts().mul(right, left_axis, right_axis);
std::cout << out;
```

### Output

```text
0  NULL
1  2000
2  NULL

ptype: Series
```

Only `2024-01-02` has an exact tick match on both sides (`20 * 100 = 2000`);
the other positions have no matching `right_axis` tick under `Exact`, so
they're `NULL`.

Example 2. The same threads, aligned with `Backward` — `other`'s most recent
known value carries forward.

```cpp
auto out2 = left.ts().mul(right, left_axis, right_axis, TsAlignMode::Backward);
std::cout << out2;
```

### Output

```text
0  NULL
1  2000
2  3000

ptype: Series
```

`2024-01-03` now picks up `right`'s most recent value at or before it
(`2024-01-02`'s `100`): `30 * 100 = 3000`.

Example 3. A `right_axis` whose length doesn't match `other` throws.

```cpp
auto short_axis = Slate(pluss::make_timeline({"2024-01-02T00:00:00Z"}));
try {
  auto bad = left.ts().mul(right, left_axis, short_axis);
} catch (const std::exception& e) {
  std::cout << e.what();
}
```

### Output

```text
TimeSeriesAccessor::mul: right values and right time axis length mismatch
```

## Notes

- `left_axis` must be the same length as the bound thread, and `right_axis`
  must be the same length as `other`, or it throws a length-mismatch error
  naming whichever side is wrong.
- The alignment step is identical to [`align_to()`](align_to.md).
- The multiplication itself, once `other` is aligned, is an ordinary
  [`Slate::mul`](../thread/mul.md) — a `NULL` on either side produces `NULL`.
