Part VIII: Time-Series Workflows¶

Time-series work in PlussMic is built from two ideas:

  1. A time axis is data, usually a Timeline or TimeIndex stored in a Thread.

  2. Time-series calculations are ordinary table transformations that return either a Thread or a DataFrame.

Use the Thread accessor when you are working on one numeric value stream:

auto returns = df.features("close").ts().returns(1);

Use the DataFrame accessor when you want to transform one or more named features and keep a table-shaped result:

auto returns = df.features({"close", "volume"}).ts().returns(1);

Use DataFrame resampling and reindexing when the operation needs a time axis:

auto values = df.set_cases("date", false).features({"close", "volume"});
auto daily = values.ts().resample("D").mean();

The accessors do not guess that a feature named "date" is time-like. For cases-based resampling, the frame cases must actually be a Timeline or TimeIndex; use .tl() for datetime columns and .ts() for numeric value streams.

If a date column starts as text, parse it through explicit cast(...) first:

auto parsed = df.cast({
    pluss::table::DataFrame::CastSpec{
        "date_text",
        pluss::table::ThreadCastTarget::Timeline,
        pluss::table::ThreadCastOptions{
            .format = "%Y-%m-%d",
            .invalid = pluss::table::ParseInvalid::Null}},
});

The time data model¶

PlussMic represents time in three common ways:

Representation

Meaning

Timeline

A sequence of timestamps. Use it for date/time columns.

TimeIndex

A timeline with index semantics. Use it when alignment and as-of operations matter.

Numeric Series

A numeric value stream measured over time, such as close price, volume, demand, or latency.

Time-series value transforms require numeric Series threads. Time-axis methods require a Timeline or TimeIndex thread.

This split is deliberate. A price column and a timestamp column have different semantics even though both can be represented internally as arrays.

Creating time features¶

When you construct a frame in C++, use pluss::make_timeline:

DataFrame df({
    {"date", pluss::make_timeline({
        "2024-01-01T00:00:00Z",
        "2024-01-01T12:00:00Z",
        "2024-01-02T00:00:00Z"})},
    {"close", pluss::make_series({100.0, 105.0, 103.0})},
});

When you load from CSV, parse or cast time columns early:

pluss::loader::ReadCsvOptions options;
options.parse_dates = {"date"};

auto df = DataFrame::load_csv("prices.csv", options);

If a column loaded as text or as a numeric YYYYMMDD series, cast it:

auto with_time = df.cast({
    pluss::table::DataFrame::CastSpec{
        "date", pluss::table::ThreadCastTarget::Timeline, {}},
});

The current source supports conversion of integer YYYYMMDD values through cast(..., ThreadCastTarget::Timeline), which is useful for market-data files that store dates as 19900102 instead of ISO strings.

Sorting is your responsibility¶

Time-series calculations use row order unless the method explicitly resamples or aligns by a time axis. PlussMic will not sort a frame for you before computing a return, lag, rolling mean, or line plot.

For ordered calculations, sort first:

auto sorted = df.sort_values({DataFrame::ArrangeSpec{"date", true, true}});
auto returns = sorted.features({"close"}).ts().returns(1);

This matters in production. A return computed on unsorted prices is not a slightly messy return; it is a different calculation.

Thread time-series accessor¶

Thread::ts() creates a TimeSeriesAccessor for one numeric Series payload:

auto close = df.features("close");
auto r = close.ts().returns(1);

The source thread must be defined, must be ThreadKind::Series, and must be numeric. If you call ts() on a Note, Timeline, or non-numeric payload, the operation throws when you call the accessor method.

auto labels = result.labels;
auto values = result.values;

Returns, differences, lag, and lead¶

The simplest time-series methods operate on row order:

auto close = df.features("close");

auto simple_returns = close.ts().returns(1);
auto log_returns = close.ts().log_returns(1);
auto one_row_diff = close.ts().diff(1);
auto lagged = close.ts().lag(1);
auto led = close.ts().lead(1);

The periods argument is a row count. It is not a calendar duration. For daily data, periods = 1 usually means one trading day or one calendar day depending on your rows. For intraday data, periods = 1 means one observation.

Current numeric time-series transforms use floating nan for positions that cannot be computed, such as the first one-period return or the first one-period lag. Do not document or test those positions as table NA unless you have explicitly converted them to a validity-mask representation.

Rolling windows¶

Rolling methods use observation windows:

auto rolling_mean = close.ts().rolling(20, pluss::table::WindowStatistic::Mean, {.min_count = 10});
auto rolling_std = close.ts().rolling(20, pluss::table::WindowStatistic::Std, {.min_count = 10});
auto rolling_sum = close.ts().rolling(20, pluss::table::WindowStatistic::Sum, {.min_count = 10});
auto rolling_var = close.ts().rolling(20, pluss::table::WindowStatistic::Var, {.min_count = 10});
auto rolling_min = close.ts().rolling(20, pluss::table::WindowStatistic::Minimum, {.min_count = 10});
auto rolling_max = close.ts().rolling(20, pluss::table::WindowStatistic::Maximum, {.min_count = 10});

window is the number of rows in the rolling window. min_periods is the minimum number of observations required before a value is emitted.

Use min_periods = window when you want strict full-window results:

auto strict = close.ts().rolling(20, pluss::table::WindowStatistic::Mean, {.min_count = 20});

Use a smaller min_periods when early estimates are acceptable:

auto warmup = close.ts().rolling(20, pluss::table::WindowStatistic::Mean, {.min_count = 5});

Rolling windows are observation-based, not calendar-based. If you need calendar windows, resample first or construct the exact frame you want before rolling.

Expanding and exponentially weighted metrics¶

Expanding metrics grow from the start of the series:

auto expanding_mean = close.ts().expanding(pluss::table::WindowStatistic::Mean, {.min_count = 5});
auto expanding_std = close.ts().expanding(pluss::table::WindowStatistic::Std, {.min_count = 5});

Exponentially weighted metrics give more weight to recent values:

auto ewm_mean = close.ts().ewm(0.1, pluss::table::WindowStatistic::Mean);
auto ewm_std = close.ts().ewm(0.1, pluss::table::WindowStatistic::Std);

alpha controls responsiveness. Values closer to 1.0 react faster. Values closer to 0.0 are smoother.

Rolling z-scores¶

Rolling z-scores are useful for anomaly detection and normalized signals:

auto z = close.ts().zscore_rolling(20, 10, 1e-12);

The epsilon argument protects divisions by very small standard deviations. Use a domain-appropriate value if your data scale is unusual.

Gap filling¶

The Thread and DataFrame accessors expose fill_gaps:

auto forward = close.ts().fill_gaps(
    pluss::subsp::stats::ts::GapFillMode::Forward);

auto zeros = close.ts().fill_gaps(
    pluss::subsp::stats::ts::GapFillMode::Zero);

auto constant = close.ts().fill_gaps(
    pluss::subsp::stats::ts::GapFillMode::Constant, 100.0);

Choose the fill mode based on the domain:

  • Forward fill can be appropriate for last-observation-carried-forward prices or states.

  • Backward fill can be useful for planned schedules where the next known value should apply.

  • Zero fill is appropriate only when missing means zero.

  • Constant fill should be a deliberate modeling choice.

DataFrame time-series accessor¶

DataFrame::ts(...) creates a DataFrameTsAccessor for one or more selected numeric features:

auto one = df.features({"close"}).ts();
auto many = df.features({"close", "volume"}).ts();

The selected feature names must exist and must be unique. Most accessor methods return a DataFrame whose cases come from the source frame. Resampling and reindexing methods return a DataFrame whose cases come from the time labels or target axis.

Resampling¶

Resampling is selection-first. Put the timeline column on the case axis, then select numeric value features and call .ts().

Use the resampler object when you want time-series semantics closer to a grouped pipeline:

auto values = df.set_cases("date", false).features({"close", "volume"});
auto ordered = values.ts().sort();
auto seven_day = values.ts().rolling("7D", pluss::table::WindowStatistic::Mean);
auto daily = values.ts().resample("D").mean();
auto weekly_max = values.features({"close"}).ts().resample("W").max();
auto hourly = values.features({"close"}).ts().resample("H").asfreq();
auto hourly_filled = values.features({"close"}).ts().resample("H").ffill();

Arguments:

Argument

Meaning

time_feature

Name of a Timeline or TimeIndex feature.

freq

Frequency key, such as "D" for daily bins.

step

Positive frequency step.

The resampler object supports these materializers today:

  • .mean()

  • .sum()

  • .min()

  • .max()

  • .first()

  • .last()

  • .count()

  • .asfreq(fill_value = std::nullopt)

  • .ffill()

  • .bfill()

  • .nearest()

When you already know the aggregation at the call site, the immediate overload still exists:

auto values = df.set_cases("date", false).features({"close", "volume"});
auto daily = values.ts().resample(
    "D",
    pluss::subsp::stats::ts::ResampleOp::Mean,
    1);

Both forms produce a DataFrame whose cases are the resample labels. In the verified example later in this chapter, four half-day observations become two daily rows.

The older DataFrame::resample(time_feature, value_features, freq, op, step, render) API still exists and returns a DataFrameView. That older helper is a frame-level bin-and-aggregate call. Prefer df.ts(features).resample(...) when you want the main time-series resampler surface.

As-frequency conversion¶

asfreq resamples and then fills gaps:

auto hourly = df.features({"close"}).ts().asfreq(
    "H",
    1,
    pluss::subsp::stats::ts::GapFillMode::Forward,
    std::nullopt,
    pluss::subsp::stats::ts::ResampleOp::Last);

Use it when your downstream code expects a regular time grid.

Inserting gaps¶

insert_gaps builds regular bins and aligns exact observations onto them:

auto with_gaps = df.set_cases("date", false).features({"close"}).ts().insert_gaps("H", 1);

Rows with no exact source observation are emitted as undefined numeric positions. This is useful before plotting because it makes data outages visible instead of connecting across missing intervals.

Aligning and reindexing to a target axis¶

Use align_to when you already have the target timeline:

auto aligned = df.set_cases("date", false).features({"close", "volume"}).ts().align_to(
    target_axis,
    pluss::table::TsAlignMode::Exact);

TsAlignMode controls how target timestamps map to source timestamps:

Mode

Meaning

Exact

Only exact timestamp matches are valid.

Backward

Use the nearest source timestamp at or before the target.

Forward

Use the nearest source timestamp at or after the target.

Nearest

Use the nearest source timestamp in either direction.

Use reindex_time when you also want to fill missing aligned values:

auto reindexed = df.set_cases("date", false).features({"close"}).ts().reindex_time(
    target_axis,
    pluss::table::TsAlignMode::Exact,
    pluss::table::TsReindexFill::Forward);

TsReindexFill controls post-alignment filling:

Fill

Meaning

None

Keep missing aligned values.

Forward

Forward-fill aligned gaps.

Backward

Backward-fill aligned gaps.

Zero

Fill aligned gaps with zero.

Constant

Fill aligned gaps with the supplied constant.

If you use Constant, pass the constant value:

auto filled = df.set_cases("date", false).features({"close"}).ts().reindex_time(
    target_axis,
    pluss::table::TsAlignMode::Exact,
    pluss::table::TsReindexFill::Constant,
    100.0);

Calendar features¶

calendar(time_feature) extracts useful calendar columns from a time axis:

auto cal = df.features({"date"}).tl().year();

It returns:

  • date_year

  • date_month

  • date_day

  • date_hour

  • date_weekday

The prefix comes from the time feature name. For a feature named "timestamp", the output columns are timestamp_year, timestamp_month, and so on.

Calendar features are often used for grouping, joins, or model features:

auto enriched = df.combine(cal, {DataFrame::CombineOp::Columns, "_cal", true});

Lag blocks¶

lag_block creates several lagged features at once:

auto lags = df.features({"close", "volume"}).ts().lag_block({1, 2, 5});

For features close and volume, that emits:

  • close_lag1

  • close_lag2

  • close_lag5

  • volume_lag1

  • volume_lag2

  • volume_lag5

Use lag blocks for supervised learning datasets, event studies, or feature engineering.

Rolling blocks¶

rolling_block creates many rolling features in one pass:

pluss::table::TsRollingBlockOptions options;
options.include_mean = true;
options.include_std = true;
options.include_min = true;
options.include_max = true;
options.min_periods = 5;

auto block = df.features({"close", "volume"}).ts().rolling_block({5, 20}, options);

The output naming convention is:

        "2024-01-01T00:00:00Z",
        "2024-01-01T12:00:00Z",
        "2024-01-02T00:00:00Z",
        "2024-01-02T12:00:00Z"})},
    {"close", pluss::make_series({100.0, 105.0, 103.0, 109.0})},
    {"volume", pluss::make_series({10.0, 20.0, 30.0, 40.0})},
});

std::cout << "returns:\n"
          << df.features("close").ts().returns(1).to_string() << '\n';
std::cout << "rolling mean window 2:\n"
          << df.features("close").ts().rolling(2, pluss::table::WindowStatistic::Mean, {.min_count = 2}).to_string()

auto daily = values.ts().resample("D", pluss::subsp::stats::ts::ResampleOp::Mean);

auto calendar = df.features({"date"}).tl().year();
std::cout << "calendar:\n"
          << calendar.features({"date_year", "date_month",

Production checklist¶

Before using a time-series result in a report, model, or downstream pipeline:

  • Confirm the time feature is Timeline or TimeIndex.

  • Sort by the time feature before order-dependent calculations.

  • Know whether periods means rows, not calendar units.

  • Choose min_periods deliberately.

  • Decide whether early undefined numeric positions should remain nan or be converted to table missingness.

  • Use resampling when observations need calendar bins.

  • Use reindexing when outputs must match a target schedule.

  • Keep the original time feature available unless the resampled labels have replaced it as cases.

  • Validate output row counts after resampling or reindexing.

Common mistakes¶

Calling the wrong accessor¶

This returns a Thread:

auto out = df.features("close").ts().returns(1);

This returns a DataFrame:

auto out = df.features({"close"}).ts().returns(1);

Choose based on the return shape you need.

Treating row periods as calendar periods¶

This is a one-row return:

auto out = df.features({"close"}).ts().returns(1);

It is not necessarily a one-day return. If the frame has hourly rows, it is a one-hour return. If the frame has irregular rows, it is a one-observation return. Resample first when the calendar interval matters.

Resampling a non-time feature¶

This fails when "date" is not a Timeline or TimeIndex:

auto daily = df.set_cases("date", false).features({"close"}).ts().resample("D").mean();

Fix the schema first:

auto fixed = df.cast({
    pluss::table::DataFrame::CastSpec{
        "date", pluss::table::ThreadCastTarget::Timeline, {}},
});
auto daily = fixed.set_cases("date", false).features({"close"}).ts().resample("D").mean();

Rolling unsorted data¶

This compiles but can be wrong:

auto rolling = df.features({"close"}).ts().rolling(20, pluss::table::WindowStatistic::Mean, {.min_count = 20});

If df is not sorted by time, the rolling window follows row order. Sort first:

auto sorted = df.sort_values({DataFrame::ArrangeSpec{"date", true, true}});
auto rolling = sorted.features({"close"}).ts().rolling(20, pluss::table::WindowStatistic::Mean, {.min_count = 20});
