Locus API Reference¶

This page documents the public Locus surface as part of the bundle workspace model.

Locus is a named, heterogeneous workspace of Catalogs with declared relationships – the Catalog counterpart of Nexus, which coordinates DataFrames. Native Locus joins, pulls, traversal, plans, and integrity checks preserve Catalog and Stream semantics; their matching and gathering work runs through the shared relational and Catalog kernels rather than forcing ragged data through a rectangular frame. nexus() remains the explicit aligned bridge for DataFrame-oriented workflows, reports, and SQL.

Use the pluss::bundle namespace for Locus itself, and pluss::kindle for the Catalog objects it coordinates.

Note

No dedicated constructor page Construct a Locus with Locus({{"name", catalog}, ...}) (a vector or brace list of name/Catalog pairs); there is no dedicated constructor page, the same as Nexus’s own constructors. The two named factories, from_archive and from_nexus, each have their own page.

Note

Full surface coverage Locus has roughly ninety public members across six classes (Locus, LocusPull, LocusPullAgg, LocusTraverse, LocusQuery, LocusQueryPrepared). Every one has a method page: this page’s own tranche below covers Locus itself; LocusPull and LocusPullAgg have their own landing pages (LocusPull, LocusPullAgg); and LocusTraverse, LocusQuery, and LocusQueryPrepared have theirs (LocusTraverse, LocusQuery, LocusQueryPrepared).
