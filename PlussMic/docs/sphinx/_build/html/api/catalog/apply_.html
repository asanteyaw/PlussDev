Catalog::apply_¶

Back to Catalog API Reference

Signature¶

Catalog::apply_(std::string_view field, const std::function<Stream(const Stream&)>& func) -> Catalog&

What It Does¶

The in-place counterpart to apply() — mutates *this directly, replacing field’s stream with func’s result, and returns a reference to it. apply() itself delegates to this method internally (after its own separate unknown-key check), so the throw messages for an empty callback, an empty field name, or a length mismatch all carry the apply_ prefix even when triggered through apply().

Parameters¶

field (std::string_view) The stream name to transform.

func (const std::function<Stream(const Stream&)>&) Called once with the current stream at field; must return a defined Stream of the same length.

Returns¶

Catalog& A reference to *this, after the update.

Examples¶

Example 1. Transform a stream in place; the return value is a reference to the same object.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "id"_k = pluss::kindle::Stream(pluss::make_series({1.0, 2.0, 3.0})),
});

ct.apply_("id", [](const pluss::kindle::Stream& s) {
  return pluss::kindle::Stream(s.as_series() * 10.0);
});
std::cout << ct;

Output¶

Notes¶

  • Unlike apply(), apply_() does not pre-check has(field) itself — an unknown key surfaces as at()’s own "Catalog: key '...' not found" throw instead of apply()’s "Catalog::apply: unknown key '...'".

  • func’s returned stream must be defined and the same length as the input; throws "Catalog::apply_: output stream length must match input stream length" otherwise.

See Also¶

  • Catalog::apply: the non-mutating form, with an extra unknown-key check before delegating here.

  • Catalog::apply_all_: the whole-catalog, in-place counterpart.
