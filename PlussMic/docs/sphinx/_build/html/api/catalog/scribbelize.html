Catalog::scribbelize¶

Back to Catalog API Reference

Signature¶

pluss::scribble::Registry Catalog::scribbelize() const

What It Does¶

Converts the catalog into a pluss::scribble::Registry — the reverse direction of Registry::kindelize. Every stream the catalog holds is converted to a pluss::scribble::Slot (via Stream::scribbelize) and reassembled into a registry field, in exactly the catalog’s own keys() order. Nothing about the values themselves changes shape or count — only the model they live in: a catalog is a named collection of typed, columnar Streams, while a registry is a named collection of Slots, each a heterogeneous, per-element std::variant sequence. The two models are designed to round-trip: catalog.scribbelize().kindelize() reproduces the same key set (though not necessarily byte-identical internals — see the important callout below).

Important

scribbelize() is per-stream conversion, not a single bulk pass Catalog::scribbelize() does not touch the catalog’s underlying storage directly – it calls keys(key).scribbelize() once per key, which itself dispatches on that stream’s own kind() (Series/Note/Timeline/TimeIndex) and, within Series, further dispatches on scalar_type() (Bool/Int64/other, the last cast through Float64). A catalog with a Series-typed key and a Note-typed key is converted through two different code paths internally, even though this method’s own signature looks uniform. See Stream::scribbelize’s own page for the full per-kind conversion table.

Parameters¶

None

Returns¶

pluss::scribble::Registry A new registry with one Slot field per catalog key, in catalog key order.

Examples¶

Example 1. A three-key catalog (Series numeric, Series float, Note text) — scribbelize() produces a registry with the same field count and key order.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "id"_k = pluss::kindle::Stream(pluss::make_series({1, 2, 3})),
    "metric"_k = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 30.0})),
    "city"_k = pluss::kindle::Stream(pluss::make_note({"Accra", "Tema", "Kumasi"})),
});
auto reg = ct.scribbelize();
std::cout << reg.nfields() << "\n";
std::cout << reg.fields().at(0) << "," << reg.fields().at(1) << "," << reg.fields().at(2) << "\n";
std::cout << reg.fields("id").size() << "\n";

Output¶

3
id,metric,city
3

Example 2 (round trip, not a distinct rendering). Converting back with Registry::kindelize reproduces the same key count — confirming the two directions are genuinely inverse operations for this data.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "id"_k = pluss::kindle::Stream(pluss::make_series({1, 2, 3})),
    "metric"_k = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 30.0})),
});
auto reg = ct.scribbelize();
auto ct2 = reg.kindelize();
std::cout << ct2.nkeys() << "\n";

Output¶

2

Example 3 (edge case). An undefined catalog throws before any key is touched.

try {
  pluss::kindle::Catalog undefined_catalog;
  undefined_catalog.scribbelize();
} catch (const pluss::Error& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

Catalog::scribbelize: catalog undefined

Notes¶

  • Requires defined() — an undefined catalog throws "Catalog::scribbelize: catalog undefined" immediately, before any key is visited.

  • Field order in the resulting Registry always matches Catalog::keys()’s own order — scribbelize() performs no reordering, sorting, or deduplication of its own.

  • An empty catalog (zero keys, but still defined()) produces a registry with zero fields, not a throw.

  • Every value in every stream — including null positions, when a stream carries a validity mask — round-trips through the per-stream conversion; see Stream::scribbelize’s own page for exactly how nulls are represented on the Slot side (std::monostate).
