TimeSeriesAccessor::sub¶

Back to TimeSeriesAccessor API Reference

Signature¶

TimeSeriesAccessor::sub(const Thread& other, const Thread& left_axis, const Thread& right_axis, TsAlignMode mode = TsAlignMode::Exact) const -> Thread

What It Does¶

Subtracts other from the bound thread after first reindexing other onto the bound thread’s own positions, using left_axis (the bound thread’s time axis) and right_axis (other’s own time axis) — exactly the same alignment align_to() performs, run automatically before an ordinary Thread::sub. See add() for the shared alignment mechanics this method also uses.

Parameters¶

other (const Thread&) The thread to subtract, currently living at right_axis ticks.

left_axis (const Thread&) The bound thread’s own time axis (Timeline/TimeIndex), same length as the bound thread.

right_axis (const Thread&) other’s time axis (Timeline/TimeIndex), same length as other.

mode (TsAlignMode, default Exact) The alignment strategy — same meaning as align_to()’s mode: Exact, Backward, Forward, or Nearest.

Returns¶

Thread A new thread, same length as the bound thread, holding bound - aligned(other) at each position.

Examples¶

Example 1. Two threads on different daily axes, subtracted after exact alignment.

using namespace pluss::table;

auto left_axis = Thread(pluss::make_timeline(
    {"2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z", "2024-01-03T00:00:00Z"}));
auto left = Thread(pluss::make_series({10.0, 20.0, 30.0}));

auto right_axis = Thread(pluss::make_timeline(
    {"2024-01-02T00:00:00Z", "2024-01-04T00:00:00Z"}));
auto right = Thread(pluss::make_series({100.0, 200.0}));

auto out = left.ts().sub(right, left_axis, right_axis);
std::cout << out;

Output¶

0  NULL
1  -80
2  NULL

ptype: Series

Only 2024-01-02 has an exact tick match on both sides (20 - 100 = -80); the other positions have no matching right_axis tick under Exact, so they’re NULL.

Example 2. The same threads, aligned with Backward — other’s most recent known value carries forward.

auto out2 = left.ts().sub(right, left_axis, right_axis, TsAlignMode::Backward);
std::cout << out2;

Output¶

0  NULL
1  -80
2  -70

ptype: Series

2024-01-03 now picks up right’s most recent value at or before it (2024-01-02’s 100): 30 - 100 = -70.

Example 3. A right_axis whose length doesn’t match other throws.

auto short_axis = Thread(pluss::make_timeline({"2024-01-02T00:00:00Z"}));
try {
  auto bad = left.ts().sub(right, left_axis, short_axis);
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

TimeSeriesAccessor::sub: right values and right time axis length mismatch

Notes¶

  • left_axis must be the same length as the bound thread, and right_axis must be the same length as other, or it throws a length-mismatch error naming whichever side is wrong.

  • The alignment step is identical to align_to().

  • The subtraction itself, once other is aligned, is an ordinary Thread::sub — a NULL on either side produces NULL.

See Also¶

  • TimeSeriesAccessor::add: the same align-then-combine pattern, fully worked through with both alignment modes.

  • Thread::sub: the plain positional subtraction this method performs after alignment.
