TimeSeriesAccessor::rolling_block¶

Back to TimeSeriesAccessor API Reference

Signature¶

TimeSeriesAccessor::rolling_block(pluss::msharp::RangeView::Int windows, const TsRollingBlockOptions& options = {}) const -> DataFrame

What It Does¶

Computes several rolling window statistics, at several window sizes, of the bound thread all at once — each {statistic, window} combination becomes its own output column named "roll_" + <statistic> + "_w" + <window>. Requires at least one window.

Important

does not use the same engine as rolling() Unlike rolling(), this method’s statistics do not skip missing values within a window — like zscore_rolling(), they accumulate every position in the window with plain floating-point arithmetic, so one missing entry makes every column’s value come back NULL for every position whose window still contains it. See zscore_rolling()’s important callout for a fully worked example of this exact effect.

Parameters¶

windows (pluss::msharp::RangeView::Int) The window sizes to compute, in the order given. Must not be empty, or it throws.

options (const TsRollingBlockOptions&) Which statistics to include, and the shared min_periods:

  • include_mean (bool, default true)

  • include_std (bool, default true)

  • include_min (bool, default false)

  • include_max (bool, default false)

  • include_sum (bool, default false)

  • include_var (bool, default false)

  • min_periods (std::int64_t, default 1): the minimum number of positions that must structurally exist in a window near the start of the thread — see zscore_rolling()’s parameter note for why this isn’t the same as “non-missing observations.”

Returns¶

DataFrame A new frame with one column per requested {statistic, window} pair, same case labels as the bound thread. Columns are ordered by window (in the order given), then by statistic in the fixed order mean, std, min, max, sum, var.

Examples¶

Example 1. The default statistics (mean, std) across two window sizes.

using namespace pluss::table;

auto values = Thread(pluss::make_series({10.0, 20.0, 30.0, 40.0, 50.0}));
auto out = values.ts().rolling_block({2, 3});
std::cout << out;

Output¶

===========================================================
     | roll_mean_w2  roll_std_w2  roll_mean_w3  roll_std_w3
-----------------------------------------------------------
0    | 10            0            10            0          
1    | 15            5            15            5          
2    | 25            5            20            8.164965809
3    | 35            5            30            8.164965809
4    | 45            5            40            8.164965809
-----------------------------------------------------------
[5 cs x 4 feat]

roll_std_w2/roll_std_w3 use a population convention (divide by count, not count - 1), same as zscore_rolling() — there’s no ddof to change that here.

Example 2. Toggle which statistics are included — min, max, sum, and var instead of the defaults.

auto out2 = values.ts().rolling_block(
    {3},
    TsRollingBlockOptions{
        .include_mean = false, .include_std = false,
        .include_min = true, .include_max = true,
        .include_sum = true, .include_var = true});
std::cout << out2;

Output¶

=========================================================
     | roll_min_w3  roll_max_w3  roll_sum_w3  roll_var_w3
---------------------------------------------------------
0    | 10           10           10           0          
1    | 10           20           30           25         
2    | 10           30           60           66.66666667
3    | 20           40           90           66.66666667
4    | 30           50           120          66.66666667
---------------------------------------------------------
[5 cs x 4 feat]

Example 3. An empty windows throws.

try {
  auto bad = values.ts().rolling_block({});
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

TimeSeriesAccessor::rolling_block: expected at least one window

Notes¶

  • See the important callout above: this method’s rolling statistics poison an entire window on a single missing value, rather than skipping it the way rolling() does.

  • std/var here always use a population convention (divide by count, not count - 1).

  • Column names are fixed ("roll_" + statistic + "_w" + window) and column order follows windows, then the fixed statistic order mean/std/min/max/ sum/var — there’s no way to rename or reorder them from this method directly.

See Also¶

  • TimeSeriesAccessor::rolling: a single window/statistic at a time, using the skip-missing-values engine instead.

  • TimeSeriesAccessor::lag_block: the equivalent “several at once” pattern for lags instead of rolling statistics.

  • TimeSeriesAccessor::zscore_rolling: shares this method’s underlying rolling-mean/rolling-std engine and its missing-value-poisons-the-window behavior.
