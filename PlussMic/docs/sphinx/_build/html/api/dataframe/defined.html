DataFrame::defined¶

Back to DataFrame API Reference

Signature¶

DataFrame::defined() const noexcept -> bool

What It Does¶

Reports whether the DataFrame handle currently owns a usable backing object at all — not whether any cell inside it is missing. A default-constructed DataFrame() (no columns argument) is the ordinary way to end up with an undefined frame; almost every other constructor and factory method produces a defined one.

Important

defined() is about object existence, not missing data defined() answers “does this frame exist and can it be used?”, not “does this frame contain nulls?”. For missing-data questions, use isnull(), notnull(), or dropnull() instead — a frame full of nulls in every cell is still defined() == true.

Parameters¶

None

Returns¶

bool true if the frame owns a usable backing object and is safe to use in ordinary operations; false for a default-constructed, not-yet-initialized handle.

Examples¶

Example 1. An ordinarily constructed frame is defined.

using namespace pluss::table;

auto grades = DataFrame({
    {"student", pluss::make_note({"Ada", "Bola", "Chen"})},
    {"score",   pluss::make_series({88.0, 79.0, 91.0})},
});

auto out = grades.defined();
std::cout << std::boolalpha << out;

Output¶

true

Example 2. A default-constructed frame is not.

auto empty_handle = DataFrame();
auto out_empty = empty_handle.defined();
std::cout << std::boolalpha << out_empty;

Output¶

false

empty_handle was constructed with no columns argument at all — it has no backing object yet, unlike a frame constructed with an empty column list, which would be defined but hold zero features.

Example 3. Calling an ordinary method on an undefined frame throws, exactly as the warning above states.

try {
  auto n = empty_handle.ncases();
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

DataFrame: undefined handle

ncases() (like nearly every other DataFrame method) needs a real backing object to read from; calling it on empty_handle — which defined() already reported as false in Example 2 — rejects immediately rather than returning a meaningless 0 or crashing. Checking defined() first, as this page recommends, lets calling code sidestep this throw entirely.

Notes¶

  • defined() is noexcept and cheap — it’s a pointer check, not a data scan.

  • Most factory methods (load_csv(), arithmetic results, copy(), and so on) always return a defined frame; the main way to encounter an undefined one is the default constructor, or a moved-from handle.

  • Calling most other methods on an undefined frame throws — defined() exists to let you check first, particularly around optional construction branches or defensive API boundaries.

See Also¶

  • DataFrame::isnull / DataFrame::notnull: per-cell missing-data checks, unrelated to object existence.

  • DataFrame::copy: always produces a defined frame, sharing storage with the source until either side is mutated.
