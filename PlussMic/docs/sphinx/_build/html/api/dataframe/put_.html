What It Does¶

The in-place counterpart to put(): rewrites one feature’s values at the rows where bool_mask is true, mutating *this directly and returning a reference to it, instead of returning a new frame. Every parameter and replacement rule is identical to put() — see that page for the full breakdown of scalar-vs-Thread replacement semantics; this page only covers what differs about mutating in place.

Parameters¶

feature (std::string_view)

The feature to rewrite in place. Must already exist on the frame.

bool_mask (const Thread& or const pluss::Series&)

A boolean row mask, identical in behavior to put()’s bool_mask.

value (const Thread&, double, std::string_view, const char*, or pluss::null_t)

The replacement, identical in behavior to put()’s value — a scalar broadcasts to every masked row, a Thread supplies a different value per row.

options (const AlignOptions&, optional)

Controls how bool_mask is aligned to the frame’s case axis, identical to put()’s options.

Returns¶

DataFrame& A reference to *this, after feature’s masked rows have been rewritten.

Examples¶

Example 1. Rewrite a feature’s masked rows in place, then keep working with the same frame.

using namespace pluss::table;

auto orders = DataFrame({
    {"id",    Thread(pluss::make_series({1, 2, 3}))},
    {"sales", Thread(pluss::make_series({100.0, 120.0, 90.0}))},
    {"city",  Thread(pluss::make_note({"Accra", "Tema", "Kumasi"}))},
});

auto is_middle = orders.features("id") == 2.0;
orders.put_("sales", is_middle, 999.0);
std::cout << orders;

Output¶

==========================
     | id    sales  city  
--------------------------
0    | 1     100    Accra 
1    | 2     999    Tema  
2    | 3     90     Kumasi
--------------------------
[3 cs x 3 feat]

orders itself now has 999 at case 1 — no separate result variable was needed, unlike put(), which would have left orders unchanged and returned a new frame instead.

Example 2. Chain a second in-place rewrite onto the same frame.

orders.put_("city", is_middle, "Tamale");
std::cout << orders;

Output¶

============================
     | id    sales  city    
----------------------------
0    | 1     100    Accra   
1    | 2     999    Tamale  
2    | 3     90     Kumasi  
----------------------------
[3 cs x 3 feat]

Both rewrites accumulate on the same orders object — case 1’s sales (from Example 1) and now its city too, both replaced in place.

Notes¶

  • put_() mutates and returns *this by reference; it never allocates a new DataFrame the way put() does.

  • Any other DataFrame value that shares the same underlying columns (via a prior copy) does not see this mutation — pluss::table::DataFrame’s copies are value-like, not aliased references to shared state.

  • See put() for the complete parameter and replacement-semantics breakdown; every rule there (scalar vs. per-row Thread replacement, Series-mask convenience overloads, kind constraints) applies identically here.

See Also¶

  • DataFrame::put: the non-mutating counterpart, returning a new frame instead of mutating in place.

  • DataFrame::mask: nulls out masked cells outright, rather than replacing them with a chosen value.
