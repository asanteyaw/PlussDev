DataFrame::rand¶

Back to DataFrame API Reference

Signatures¶

DataFrame::rand(const DataFrame& other) const -> DataFrame
DataFrame::rand(const Thread& other) const -> DataFrame

What It Does¶

The reflected form of land(). Since logical AND is commutative, frame.rand(other) is indistinguishable from frame.land(other) in every observable respect — same cell values, and (for the DataFrame overload) the same case labels and title, both drawn from frame itself, exactly as land() documents.

Note

Previously, the DataFrame overload inherited case labels from other An earlier revision of rand(const DataFrame&) computed the reflection as other.land(*this), which meant the result’s case labels and title came from other instead of from the frame the method was called on — a real, verified quirk that was documented here as a caution. That has since been fixed: rand() now zips *this and other directly (with Thread::rand() handling the per-cell operand order internally), so the result’s structure always comes from *this, matching land() and every other method in this family. If you’re working against an older build where this fix isn’t present, verify which behavior you’re actually seeing before relying on either.

Parameters¶

other

const DataFrame& or const Thread& — identical shape requirements to land(): same feature names in order and same case count for the DataFrame overload; one boolean thread matching ncases() for the Thread overload.

Returns¶

DataFrame A new frame holding the logical AND of each cell against the corresponding other value, with case labels and title drawn from the frame rand() was called on — identical in every respect to what land() would produce for the same arguments.

Examples¶

Example 1. rand() and land() produce identical results, values and case labels both.

using namespace pluss::table;

auto left = DataFrame({
    {"a", pluss::make_series({true, false, true}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
}, pluss::make_note({"p", "q", "r"}));

auto right = DataFrame({
    {"a", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({false, true, true}, pluss::ScalarType::Bool)},
}, pluss::make_note({"x", "y", "z"}));

auto forward = left.land(right);
std::cout << forward;

Output (land)¶

===================
     | a      b    
-------------------
p    | true   false
q    | false  true 
r    | false  false
-------------------
[3 cs x 2 feat]

auto reflected = left.rand(right);
std::cout << reflected;

Output (rand)¶

===================
     | a      b    
-------------------
p    | true   false
q    | false  true 
r    | false  false
-------------------
[3 cs x 2 feat]

Both calls produce the exact same table — same values, same case labels (p, q, r, from left, the frame both methods were called on), even though right uses a completely different set of case labels (x, y, z) that never appear in either result.

Example 2. The Thread overload behaves identically, as it always has.

auto mask = Thread(pluss::make_series({true, false, true}, pluss::ScalarType::Bool));
auto out = left.rand(mask);
std::cout << out;

Output¶

===================
     | a      b    
-------------------
p    | true   true 
q    | false  false
r    | true   false
-------------------
[3 cs x 2 feat]

Case labels p, q, r come from left, exactly as land(mask) would produce.

Notes¶

  • rand() and land() are fully interchangeable for DataFrame arguments — same values, same case labels, same title. The reflected name exists purely for symmetry with the rest of the reflected method family (ror(), rxor(), radd(), and so on), not because it produces a different result here.

  • Requires a genuine Bool scalar type on every participating Series, same as land().
