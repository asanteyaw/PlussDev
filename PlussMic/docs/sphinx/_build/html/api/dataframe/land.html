DataFrame::land¶

Back to DataFrame API Reference

Signatures¶

DataFrame::land(const DataFrame& other) const -> DataFrame
DataFrame::land(const Thread& other) const -> DataFrame

What It Does¶

Elementwise logical AND between every Bool-typed feature on this frame and the matching value on other. land() is one of three logical methods (land, lor(), lxor()) — each with a reflected counterpart (rand(), ror(), rxor()) — that operate strictly on boolean payloads, unlike the arithmetic and comparison families.

Important

Both operands must already be Bool Series Every logical method requires each participating feature to be a Series-kind Thread with a genuine Bool scalar type. A numeric 0/1 column (even int64 or float64) is rejected — cast it first with astype(..., pluss::ScalarType::Bool) if it isn’t already boolean.

Important

Much simpler overload shape than add()/eq() Unlike the arithmetic family (add()) or the comparison family (eq()), the logical methods take no axis and no AlignOptions — there are exactly two overloads: another DataFrame, or a single Thread. See “Parameters” below for what each one requires.

Parameters¶

other

The right-hand operand, in one of two shapes:

  • const DataFrame&: another frame with the exact same feature names, in the same order, and the same number of cases. Values are combined position-by-position — there is no case-label alignment step; only the feature-name list and the case count are checked, not the case label values themselves.

  • const Thread&: a single boolean Thread whose length matches ncases(). The same thread is combined against every feature identically, position-by-position — there is no per-feature broadcast the way the Thread overloads of add() or eq() support via axis.

Returns¶

DataFrame A new frame, same shape as the source, with every feature holding the logical AND of the source cell and the corresponding other value.

Examples¶

Example 1. AND two boolean frames with identical feature names, case-by-case.

using namespace pluss::table;

auto left = DataFrame({
    {"a", pluss::make_series({true, false, true}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
}, pluss::make_note({"p", "q", "r"}));

std::cout << left;

Output (left)¶

===================
     | a      b    
-------------------
p    | true   true 
q    | false  true 
r    | true   false
-------------------
[3 cs x 2 feat]

auto right = DataFrame({
    {"a", pluss::make_series({true, true, false}, pluss::ScalarType::Bool)},
    {"b", pluss::make_series({false, true, true}, pluss::ScalarType::Bool)},
}, pluss::make_note({"x", "y", "z"}));

std::cout << right;

Output (right)¶

===================
     | a      b    
-------------------
x    | true   false
y    | true   true 
z    | false  true 
-------------------
[3 cs x 2 feat]

auto out = left.land(right);
std::cout << out;

Output¶

===================
     | a      b    
-------------------
p    | true   false
q    | false  true 
r    | false  false
-------------------
[3 cs x 2 feat]

Every cell is combined by position, not by case label: position 0 in left (case p) is ANDed with position 0 in right (case x), and so on, even though left’s and right’s case labels (p,q,r vs x,y,z) don’t overlap at all. left and right each have 3 cases and the same two feature names (a, b) in the same order, which is all land(DataFrame) requires — it never checks whether the case labels themselves match.

Example 2. AND a frame against a single shared Thread, applied identically to every feature.

auto mask = Thread(pluss::make_series({true, false, true}, pluss::ScalarType::Bool));
auto out_thread = left.land(mask);
std::cout << out_thread;

Output¶

===================
     | a      b    
-------------------
p    | true   true 
q    | false  false
r    | true   false
-------------------
[3 cs x 2 feat]

The same three-value mask is combined against both a and b at matching positions — there is no way to supply a different mask per feature in one call, unlike add()’s Axis::Feature Thread overload.

Notes¶

  • Requires a genuine Bool scalar type on every participating Series; a numeric 0/1 column throws rather than being treated as truthy.

  • land(const DataFrame&) checks only that feature names match (in order) and that case counts match — it does not verify or use the case label values for alignment, unlike add()’s AlignOptions-based alignment.

  • The reflected form rand() computes the same cell values (AND is commutative) and, since a fix to an earlier revision, the same case labels and title too — rand() and land() are now fully interchangeable. See rand() for a worked comparison and a note on the earlier behavior this replaced.

See Also¶

  • DataFrame::lor / DataFrame::lxor: the OR and XOR counterparts, sharing this exact overload shape.

  • DataFrame::rand: the reflected form, and where the case-label caveat is demonstrated concretely.

  • DataFrame::astype: cast a numeric feature to Bool before using it with any logical method.
