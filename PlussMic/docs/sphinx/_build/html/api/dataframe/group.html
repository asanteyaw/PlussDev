DataFrame::group¶

Back to DataFrame API Reference

Signatures¶

DataFrame::group() const -> DataFrameGroupBuilder
DataFrame::group(const GroupOptions& options) const -> DataFrameGroupBuilder

What It Does¶

Enters the grouped-workflow builder for the current frame. group() itself does not aggregate, broadcast, or filter yet. It only captures group-level execution policy through GroupOptions, after which you choose:

  • .by({...}) for ordinary feature keys

  • .by(LabelGroup{...}) for case-label levels

  • .agg({...}) for explicit named per-group reductions

  • .transform({...}) for broadcasted grouped values back to original row order

  • .filter(keep) for keeping or dropping whole groups

  • grouped convenience terminals such as .count(), .sum(), .mean(), .median(), .min(), .max(), .std(), .var(), .mode(), and .ndistinct(), each available either as a no-argument “all remaining value features” form or a targeted selected-feature form

The mental model is:

  1. group(...) chooses grouping policy.

  2. by(...) chooses what defines a group.

  3. A grouped terminal actually executes the work.

This keeps grouping declarative and stable. You do not pass keys, specs, null policy, sort policy, and execution mode into one giant call; the builder separates those concerns cleanly.

Mental Model¶

There are three different things users often conflate when they say “group by”:

  1. What defines a group

  • one feature: by({"city"})

  • several features as a tuple: by({"city", "product"})

  • one or more case-label levels: by(LabelGroup{...})

  1. What should happen to the rows

  • collapse to one row per group: agg(...), count(), mean(), …

  • stay at source row count with broadcasted group features: transform(...)

  • stay as source rows but keep/drop whole groups: filter(...)

  • stay as source rows but reorder into grouped neighborhoods: yield()

  1. How groups are ordered / cleaned before execution

  • dropnull: whether rows with null grouping keys participate at all

  • sort: whether group keys print in first-seen order or ascending tuple order

Once you separate those three concerns, the surface becomes predictable.

When To Use It¶

Use group() when the operation is fundamentally “split rows into groups, then do something per group.”

That includes:

  • grouped summaries

  • grouped row counts

  • grouped categorical modes

  • per-row broadcast of group statistics

  • whole-group pruning

  • grouped row neighborhood prep before row-wise operations

Use a different surface when the problem is not grouped execution:

  • one-row whole-frame summary -> aggregate()

  • contingency/joint categorical distribution -> contingency()

  • reshape grouped values into spreadsheet-like columns -> pivot_table()

This page previews the builder’s most common shape. Every grouped method (by, agg, transform, filter, and the convenience terminals) has its own dedicated, example-rich reference page — start at the DataFrameGroupBuilder API Reference and use its left sidebar to jump straight to any method.

Parameters¶

options (const GroupOptions&, optional)

  • dropnull: drop rows with null group keys before grouping

  • sort: sort groups lexicographically by key instead of preserving first-seen order

  • layout: grouped result layout; currently only GroupLayout::Flat is supported

The zero-argument overload is shorthand for GroupOptions{}.

Returns¶

DataFrameGroupBuilder A lightweight builder bound to the current frame. Calling by(...) returns a grouped handle, and grouped terminals return a new DataFrame.

Failure Modes¶

  • unsupported layout -> validation error at grouped execution time

  • no grouping keys passed later to by(...) -> validation error

  • null or missing grouping labels with dropnull = true -> those rows are excluded, not errors

  • convenience terminal with no remaining value features -> validation error, except count() which falls back to a row-count column

  • targeted convenience terminal naming a grouping key as a value feature -> validation error

  • grouped numeric reduction on a non-numeric value feature -> validation error

Examples¶

Example 1. Group by one key and aggregate explicitly.

using namespace pluss::table;

auto orders = DataFrame({
    {"city",   Thread(pluss::make_note({"Accra", "Accra", "Tema", "Tema"}))},
    {"units",  Thread(pluss::make_series({2, 5, 1, 3}))},
    {"price",  Thread(pluss::make_series({1200.0, 45.5, 1150.0, 320.0}))},
});

auto by_city = orders.group({.dropnull = true})
                   .by({"city"})
                   .agg({
                       {"units_total", "units", DataFrame::GroupOp::Sum},
                       {"avg_price", "price", DataFrame::GroupOp::Mean},
                   });
std::cout << by_city;

Output¶

====================================
     | city   units_total  avg_price
------------------------------------
0    | Accra  7            622.75
1    | Tema   4            735
------------------------------------
[2 cs x 3 feat]

Example 2. Use a grouped convenience terminal after selecting value columns.

auto means = orders.features({"city", "units", "price"})
                 .group()
                 .by({"city"})
                 .mean();
std::cout << means;

Output¶

============================
     | city   units_mean  price_mean
------------------------------------
0    | Accra  3.5         622.75
1    | Tema   2           735
------------------------------------
[2 cs x 3 feat]

Example 3. Ask for row counts explicitly.

auto rows = orders.features({"city"})
               .group()
               .by({"city"})
               .agg({
                   {"count", "", DataFrame::GroupOp::Count},
               });
std::cout << rows;

Output¶

================
     | city  count
----------------
0    | Accra 2
1    | Tema  2
----------------
[2 cs x 2 feat]

Example 4. Broadcast a grouped statistic back to the original row space.

auto city_mean = orders.group()
                    .by({"city"})
                    .transform({
                        {"price_mean", "price", DataFrame::GroupOp::Mean},
                    });
std::cout << city_mean;

Output¶

================
     | price_mean
----------------
0    | 622.75
1    | 622.75
2    | 735
3    | 735
----------------
[4 cs x 1 feat]

Example 5. Keep whole groups from a grouped boolean mask.

auto totals = orders.group()
                  .by({"city"})
                  .agg({
                      {"units_total", "units", DataFrame::GroupOp::Sum},
                  });
auto keep = totals.features("units_total").gt(4.0);
auto only_large = orders.group().by({"city"}).filter(keep);
std::cout << only_large;

Output¶

==========================
     | city   units  price
--------------------------
0    | Accra  2      1200
1    | Accra  5      45.5
--------------------------
[2 cs x 3 feat]

Notes¶

  • Explicit .agg({...}) is the most precise form when you want mixed operations or custom output names.

  • Convenience terminals such as .mean() and .sum() operate on the current frame’s non-key value features by default.

  • Those same convenience terminals also accept one or more feature names when you want to aggregate only a targeted subset, for example group().by({"city"}).mean({"price"}).

  • Convenience .count() counts non-null values for the current non-key value features. Use .agg({{"count", "", DataFrame::GroupOp::Count}}) when you want row count per group as an explicit aggregate.

  • .transform({...}) returns only the broadcasted grouped output features, not the key columns and not the original frame.

  • .filter(keep) expects one boolean per group, in the same group order produced by .agg(...) on the same grouped handle.

  • For multi-key grouping, rows belong to the same group only if the entire key tuple matches. This is not a “group by first key, then re-group by the second” pipeline.

Workflow Map¶

Use this accessor when you need one of three grouped execution shapes:

  • Collapse to one row per group: use agg()

  • Broadcast grouped values back to row space: use transform()

  • Retain/drop whole groups from the original frame: use filter()

by(...) itself has three overload families:

  • by({"city", "product"}): ordinary feature-key grouping

  • by(RangeView<...>): the same thing from a dynamic key list

  • by(LabelGroup{...}): group by case-label levels instead of ordinary features
