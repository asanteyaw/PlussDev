DataFrame::case_study¶

Back to DataFrame API Reference

Signatures¶

DataFrame::case_study(const Case& rows) const -> DataFrame
DataFrame::case_study(const Case& rows, const Feat& features) const -> DataFrame
DataFrame::case_study(const CasePick& pick) const -> DataFrame

What It Does¶

The general-purpose row-and-feature selection method: pick rows by position, by case label, or by boolean mask, optionally combined with a feature projection, all in one call that always returns a DataFrame — even when the selection resolves to a single row, a single column, or a single cell. Case and Feat are small selector structs built via their own static factory methods (Case::at(...), Feat::name(...), and so on, documented below) rather than by setting their fields directly — the fields are an implementation detail of how the selector is dispatched internally.

The third overload, taking a CasePick, is for a different situation: a frame that already has one or more named case-label levels, set up via label().set(...). It looks up rows by matching those named levels’ values rather than by position or by the plain default case label.

Parameters¶

rows (DataFrame::Case) — built with one of:

  • Case::at(row): one row by position. Negative positions count from the end (Case::at(-1) is the last row).

  • Case::slice(start, stop): a half-open positional slice [start, stop), the same convention slice() uses.

  • Case::take({r1, r2, ...}): an explicit, arbitrarily ordered (and possibly repeating) list of positions — the same generality take() offers.

  • Case::label(value): every row whose current case label equals value. If the same label appears on more than one row, all of them are returned, not just the first.

  • Case::labels({v1, v2, ...}): several labels, in the order you list them — the output order follows your list, not the frame’s original row order.

  • Case::span(start, stop): an inclusive case-label window, from the first row matching start through the last row matching stop. This is a positional distinction worth noting: it is inclusive on both ends, unlike Case::slice(start, stop), which is exclusive on stop.

  • Case::where(bool_thread): every row where a boolean Thread/Series (one entry per case) is true — the same selection filter() performs.

features (DataFrame::Feat, optional) — built with one of:

  • Feat::all(): every feature, in source order (the default when this parameter is omitted entirely).

  • Feat::name(value) / Feat::at(position): one feature, by name or by position.

  • Feat::names({n1, n2, ...}) / Feat::take({p1, p2, ...}): several features, by name or by position, in the order you list them.

  • Feat::slice(start, stop): a half-open positional feature slice.

  • Feat::span(start, stop): an inclusive feature-name window, from start’s position through stop’s position (in the frame’s own feature order, not alphabetical) — inclusive on both ends, mirroring Case::span()’s convention.

pick (CasePick) — a struct with:

  • label / value: match rows where the named case-label level label equals value.

  • names / values: the same idea across several named levels at once — every row must match all of the given level/value pairs.

  • key: a full positional key, one value per level in the frame’s own case-level order, when you’d rather not name each level explicitly.

  • drop (bool, default false): when true, removes the matched level(s) from the result’s case-label structure after selection, instead of keeping them (now redundant, since they’re constant across the matched rows) on every result row.

Exactly one of label/value, names/values, or key should be set per call.

Returns¶

DataFrame A new frame containing the matched rows (and, with the two-argument overload, only the selected features), in the order the selector produced them.

Examples¶

Example 1. Select a single row by position, including counting from the end.

using namespace pluss::table;

auto orders = DataFrame({
    {"order_id",   Thread(pluss::make_series({101, 102, 103, 104, 105, 106}))},
    {"city",       Thread(pluss::make_note({"Accra", "Accra", "Tema", "Tema", "Kumasi", "Kumasi"}))},
    {"product",    Thread(pluss::make_note({"Laptop", "Headphones", "Laptop", "Monitor", "Headphones", "Monitor"}))},
    {"units",      Thread(pluss::make_series({2, 5, 1, 3, 4, 2}))},
    {"unit_price", Thread(pluss::make_series({1200.0, 45.5, 1150.0, 320.0, 42.0, std::numeric_limits<double>::quiet_NaN()}))},
    {"discount",   Thread(pluss::make_series({0.1, 0.05, std::numeric_limits<double>::quiet_NaN(), 0.08, 0.05, 0.12}))},
});

std::cout << orders.case_study(DataFrame::Case::at(2));
std::cout << orders.case_study(DataFrame::Case::at(-1));

Output¶

===========================================================
     | order_id  city  product  units  unit_price  discount
-----------------------------------------------------------
2    | 103       Tema  Laptop   1      1150        NULL    
-----------------------------------------------------------
[1 cs x 6 feat]
=============================================================
     | order_id  city    product  units  unit_price  discount
-------------------------------------------------------------
5    | 106       Kumasi  Monitor  2      NULL        0.12    
-------------------------------------------------------------
[1 cs x 6 feat]

Case::at(-1) reaches the last row (case 5) without needing to know ncases() first.

Example 2. Select a positional slice, then an explicit reordered list combined with a feature projection.

using Case = DataFrame::Case;
using Feat = DataFrame::Feat;

auto middle = orders.case_study(Case::slice(1, 4));
std::cout << middle;

auto picked = orders.case_study(Case::take({0, 2, 4}), Feat::names({"city", "product"}));
std::cout << picked;

Output¶

===============================================================
     | order_id  city   product     units  unit_price  discount
---------------------------------------------------------------
1    | 102       Accra  Headphones  5      45.5        0.05    
2    | 103       Tema   Laptop      1      1150        NULL    
3    | 104       Tema   Monitor     3      320         0.08    
---------------------------------------------------------------
[3 cs x 6 feat]
=========================
     | city    product   
-------------------------
0    | Accra   Laptop    
2    | Tema    Laptop    
4    | Kumasi  Headphones
-------------------------
[3 cs x 2 feat]

picked keeps only city and product, and its rows follow Case::take({0, 2, 4})’s exact order — which happens to already be ascending here.

Example 3. Select by case label — including a duplicate label matching more than one row, and a custom output order.

auto sales = DataFrame({
    {"city",   Thread(pluss::make_note({"Accra", "Tema", "Kumasi", "Tamale"}))},
    {"region", Thread(pluss::make_note({"south", "south", "middle", "north"}))},
    {"units",  Thread(pluss::make_series({10, 7, 12, 5}))},
});
auto labeled = sales.with_cases(Thread(pluss::make_note({"A100", "B200", "B200", "D400"})));

auto b200_rows = labeled.case_study(Case::label("B200"));
std::cout << b200_rows;

auto reordered = labeled.case_study(Case::labels({"D400", "A100"}));
std::cout << reordered;

Output¶

============================
     | city    region  units
----------------------------
B200 | Tema    south   7    
B200 | Kumasi  middle  12   
----------------------------
[2 cs x 3 feat]
============================
     | city    region  units
----------------------------
D400 | Tamale  north   5    
A100 | Accra   south   10   
----------------------------
[2 cs x 3 feat]

Case::label("B200") matches both rows carrying that label — labels are not required to be unique, and duplicates are never silently collapsed. Case::labels({"D400", "A100"}) returns exactly those two rows in the order requested, not in the frame’s original top-to-bottom order.

Example 4. Select an inclusive case-label range, combined with an inclusive feature-name range.

auto window = labeled.case_study(Case::span("B200", "D400"), Feat::span("city", "region"));
std::cout << window;

Output¶

=====================
     | city    region
---------------------
B200 | Tema    south 
B200 | Kumasi  middle
D400 | Tamale  north 
---------------------
[3 cs x 2 feat]

The row range runs from the first row matching "B200" through the last row matching "D400", inclusive — three rows, not two, since "B200" itself matches twice. The feature range keeps city through region (positions 0 and 1 in the frame’s own feature order), excluding units.

Example 5. Select with a boolean mask, exactly like filter(), and project features in the same call.

auto expensive = orders.case_study(
    Case::where(orders.features("unit_price") > 100.0),
    Feat::names({"city", "product", "unit_price"}));
std::cout << expensive;

Output¶

=================================
     | city   product  unit_price
---------------------------------
0    | Accra  Laptop   1200      
2    | Tema   Laptop   1150      
3    | Tema   Monitor  320       
---------------------------------
[3 cs x 3 feat]

Example 6. Use CasePick to look up rows by a named case-label level, after label().set(...) has promoted a feature into the case axis.

auto regional = DataFrame({
    {"region", Thread(pluss::make_note({"West", "West", "East", "East"}))},
    {"sales",  Thread(pluss::make_series({10.0, 20.0, 30.0, 40.0}))},
    {"cost",   Thread(pluss::make_series({4.0, 8.0, 12.0, 16.0}))},
}).label().set("region", true);

auto west = regional.case_study(DataFrame::CasePick{.label = "region", .value = "West"});
std::cout << west;

auto east = regional.case_study(DataFrame::CasePick{.key = {"East"}});
std::cout << east;

Output¶

==================
     | sales  cost
------------------
West | 10     4   
West | 20     8   
------------------
[2 cs x 2 feat]
==================
     | sales  cost
------------------
East | 30     12  
East | 40     16  
------------------
[2 cs x 2 feat]

west uses the named form (.label / .value); east uses the equivalent .key form, which specifies a value for every case-label level in order instead of naming each level — here there is only one level (region), so .key = {"East"} is a single-element list. Both forms leave region in the result’s case labels (shown as the row index) because drop was left at its default false; pass drop = true when a level’s value is now constant across every matched row and no longer worth carrying.

Notes¶

  • Case and Feat should be built via their static factory methods (Case::at, Case::slice, Case::take, Case::label, Case::labels, Case::span, Case::where; Feat::all, Feat::name, Feat::at, Feat::names, Feat::take, Feat::slice, Feat::span) rather than by setting their fields directly — those fields are an implementation detail of how the selector is dispatched internally.

  • Positional slices (Case::slice, Feat::slice) are half-open, exclusive on stop — the same convention as slice(). Label-based ranges (Case::span, Feat::span) are inclusive on both ends — a different convention, worth remembering when switching between the two.

  • An out-of-range single position (Case::at(row) after negative normalization) is a validation error, matching take()’s behavior, not slice()’s silent clamping.

  • The CasePick overload only works on a frame with a named case axis from label().set(...); on a frame using the plain default case label, use Case::label(...) / Case::labels(...) / Case::span(...) instead.

  • names / values on CasePick generalizes label / value to matching several named levels simultaneously — every listed level must match its paired value for a row to be included.

See Also¶

  • DataFrame::take: the simpler positional-only primitive Case::at / Case::take selection is built on.

  • DataFrame::filter: boolean-mask row selection without the feature projection case_study() also offers.

  • DataFrame::features: a lighter-weight path when you only need feature projection and no row selection at all.

  • DataFrame::label: the accessor used to inspect or set the case-label axis that Case::label, Case::labels, Case::span, and CasePick all read from.

  • DataFrame::observe: a display-oriented row window, for quick previewing rather than a result meant for further computation.
