What It Does¶

The named-method form of elementwise exponentiation: raises every numeric feature to the power of other. pow() shares the exact same six-overload shape and alignment rules as add() and the rest of the arithmetic family (add, sub, mul, div, truediv, floordiv, mod) — only the operation itself differs. See add()’s “What It Does” for the general explanation of why each shape exists; this page demonstrates every one of them with pow()’s own numbers.

Parameters¶

other

The right-hand operand (the exponent), in one of three shapes:

  • double: one scalar exponent, applied to every numeric feature.

  • const DataFrame&: another frame supplying one exponent per cell, after the two frames are aligned.

  • const Thread&: one column of exponents, broadcast according to axis.

axis (Axis, default Axis::Feature, Thread overloads only)

  • Axis::Feature (the default): other supplies one exponent per feature — its length must match nfeatures(). Feature i’s exponent is applied to every case in column i.

  • Axis::Case: other supplies one exponent per case — its length must match ncases(). Case i’s exponent is applied across every feature in row i.

options (AlignOptions, optional)

Controls how the DataFrame or Thread right-hand operand is aligned to the current frame before the exponentiation runs (by position, case label, or feature name), and how missing values are filled during alignment. Defaults to strict positional alignment (AlignBy::Pos).

Returns¶

DataFrame A new frame, same shape as the source, with every numeric feature raised to the power of other. Non-numeric features are left unchanged.

Examples¶

Example 1. Raise every numeric feature to a scalar power.

using namespace pluss::table;

auto values = DataFrame({
    {"base",  pluss::make_series({2.0, 3.0, 4.0})},
    {"scale", pluss::make_series({10.0, 20.0, 30.0})},
}, pluss::make_note({"a", "b", "c"}));

std::cout << values;

Output (before)¶

===================
      | base  scale
-------------------
a     | 2     10   
b     | 3     20   
c     | 4     30   
-------------------
[3 cs x 2 feat]

auto out = values.pow(2.0);
std::cout << out;

Output (after)¶

===================
      | base  scale
-------------------
a     | 4     100  
b     | 9     400  
c     | 16    900  
-------------------
[3 cs x 2 feat]

Example 2. Raise each feature to its own exponent via a Thread with one value per feature (Axis::Feature, the default) — base gets ^2, scale gets ^3.

auto per_feature_exp = Thread(pluss::make_series({2.0, 3.0}));
auto out = values.pow(per_feature_exp);
std::cout << out;

Output¶

===================
      | base  scale
-------------------
a     | 4     1000 
b     | 9     8000 
c     | 16    27000
-------------------
[3 cs x 2 feat]

Example 3. Raise each case to its own exponent instead (Axis::Case) — row a gets ^1, row b gets ^2, row c gets ^3, applied across every feature in that row.

auto per_case_exp = Thread(pluss::make_series({1.0, 2.0, 3.0}));
auto out = values.pow(per_case_exp, Axis::Case);
std::cout << out;

Output¶

===================
      | base  scale
-------------------
a     | 2     10   
b     | 9     400  
c     | 64    27000
-------------------
[3 cs x 2 feat]

Example 4. Raise by another DataFrame using the default (const DataFrame&) overload — a plain positional pairing that ignores both frames’ case labels.

auto exponents = DataFrame({
    {"col1", Thread(pluss::make_series({3.0, 1.0, 2.0}))},
    {"col2", Thread(pluss::make_series({1.0, 2.0, 1.0}))},
}, Thread(pluss::make_note({"x", "y", "z"})));
std::cout << exponents;

auto out = values.pow(exponents);
std::cout << out;

Output (exponents)¶

==================
      | col1  col2
------------------
x     | 3     1   
y     | 1     2   
z     | 2     1   
------------------
[3 cs x 2 feat]

Output (values.pow(exponents))¶

===================
      | base  scale
-------------------
a     | 8     10   
b     | 3     400  
c     | 16    30   
-------------------
[3 cs x 2 feat]

exponents’s case labels (x, y, z) share nothing with values’s (a, b, c), and the default overload doesn’t care — it pairs row 0 with row 0 (base = 2 raised to col1’s row-0 exponent 3, giving 8), row 1 with row 1, and so on, purely by physical position.

Example 5. The exact same exponents values as Example 4, but with the case labels shuffled to c, a, b instead of x, y, z — now using AlignOptions{.align = AlignBy::Caselbl} to pair rows by case label instead of physical position.

auto exponents_by_label = DataFrame({
    {"col1", Thread(pluss::make_series({3.0, 1.0, 2.0}))},
    {"col2", Thread(pluss::make_series({1.0, 2.0, 1.0}))},
}, Thread(pluss::make_note({"c", "a", "b"})));
std::cout << exponents_by_label;

auto out = values.pow(exponents_by_label, AlignOptions{.align = AlignBy::Caselbl});
std::cout << out;

Output (exponents_by_label)¶

==================
      | col1  col2
------------------
c     | 3     1   
a     | 1     2   
b     | 2     1   
------------------
[3 cs x 2 feat]

Output (values.pow(exponents_by_label, Caselbl))¶

===================
      | base  scale
-------------------
a     | 2     100  
b     | 9     20   
c     | 64    30   
-------------------
[3 cs x 2 feat]

With AlignBy::Caselbl, case "a" in values is matched to case "a" in exponents_by_label — which sits in the second physical row here (col1 = 1, col2 = 2) — giving base_a = 2^1 = 2 and scale_a = 10^2 = 100. Compare this to Example 4’s positional pairing, which matched values’s row 0 ("a") to exponents’s row 0 ("x", col1 = 3) and got a different answer, base_a = 2^3 = 8. Same underlying numbers, different pairing rule, different result — exactly the contrast add()’s own Examples 4 and 5 make with addition instead of exponentiation.

Notes¶

  • Non-numeric features are always left unchanged.

  • Unlike the other arithmetic methods in this family, pow() always evaluates feature-by-feature rather than as a single batched matrix operation internally — this is an implementation detail with no observable effect on the result.

  • Shares its full overload shape, alignment semantics, and AlignOptions behavior with add(), sub(), mul(), div(), floordiv(), and mod().
