DataFrame::count_by¶

Back to DataFrame API Reference

Signature¶

DataFrame::count_by(std::string_view feature, std::int64_t top_n = 0, bool dropnull = true, bool render = false) const -> DataFrameView

What It Does¶

Builds a frequency table for a single feature: one row per distinct value of feature, paired with how many cases carry that value, sorted from most frequent to least frequent (ties broken alphabetically by the value itself). It is a dedicated shortcut for the single most common group_by query — “how many of each?” — without hand-writing a GroupSpec for a plain count.

Parameters¶

feature (std::string_view)

The feature whose distinct values define the groups.

top_n (std::int64_t, default 0)

Cap the result to the top_n most frequent groups after sorting. 0 (the default) keeps every group; a positive value truncates the (already count-sorted) result down to that many rows.

dropnull (bool, default true)

Whether a missing feature value is excluded from the count entirely (true, the default) or allowed to form its own group (false).

render (bool, default false)

Display toggle for the returned DataFrameView, following the same convention as head().

Returns¶

DataFrameView A two-column frequency table: feature (the distinct values) and count (an Int64 occurrence count), sorted by count descending, then by value ascending on ties.

Examples¶

Example 1. Tally every distinct value of a grouping feature.

using namespace pluss::table;

auto orders = DataFrame({
    {"city", Thread(pluss::make_note({"Accra", "Tema", "Accra", "Kumasi", "Accra", "Tema"}))},
});

auto counts = orders.count_by("city");
std::cout << counts;

Output¶

====================
     | city    count
--------------------
0    | Accra   3    
1    | Tema    2    
2    | Kumasi  1    
--------------------
[3 cs x 2 feat]

Example 2. Keep only the two most frequent groups with top_n.

auto top_cities = orders.count_by("city", /*top_n=*/2);
std::cout << top_cities;

Output¶

===================
     | city   count
-------------------
0    | Accra  3    
1    | Tema   2    
-------------------
[2 cs x 2 feat]

Kumasi (count 1) is dropped since only the top two rows of the already-sorted table survive top_n = 2.

Example 3. See the alphabetical tie-break rule in action.

auto letters = DataFrame({
    {"grade", Thread(pluss::make_note({"B", "A", "B", "A", "C"}))},
});

auto out = letters.count_by("grade");
std::cout << out;

Output¶

===================
     | grade  count
-------------------
0    | A      2    
1    | B      2    
2    | C      1    
-------------------
[3 cs x 2 feat]

A and B are tied at count 2; the tie is broken alphabetically, so A is listed first even though B happened to appear first in the source data.

Example 4. dropnull = false: a missing feature value gets its own group, labeled NULL, instead of being excluded.

auto with_missing = DataFrame({
    {"city", Thread(
        pluss::make_note({"Accra", "Tema", "Accra", "Kumasi"}),
        pluss::make_series(std::vector<bool>{true, false, true, true}))},
});

auto dropped = with_missing.count_by("city");
std::cout << dropped;

auto kept = with_missing.count_by("city", /*top_n=*/0, /*dropnull=*/false);
std::cout << kept;

Output (dropnull = true, the default)¶

===================
     | city   count
-------------------
0    | Accra  2    
1    | Kumasi 1    
-------------------
[2 cs x 2 feat]

Output (dropnull = false)¶

====================
     | city    count
--------------------
0    | Accra   2    
1    | Kumasi  1    
2    | NULL    1    
--------------------
[3 cs x 2 feat]

with_missing’s second row (index 1) is genuinely missing: it was built by pairing "Tema" with false in an explicit validity mask, so the cell itself is NULL, not the string "Tema". dropnull = true correctly excludes it. With dropnull = false, that row forms its own group, printed as NULL in the city column — one occurrence, same as Kumasi. NULL’s group sorts after Kumasi despite the tied count of 1, since a missing key is never alphabetized against real values; it always sorts last among ties.

Example 5. Pass render = true and let the returned view print itself, with no explicit std::cout at all.

orders.count_by("city", /*top_n=*/0, /*dropnull=*/true, /*render=*/true);

Output¶

====================
     | city    count
--------------------
0    | Accra   3    
1    | Tema    2    
2    | Kumasi  1    
--------------------
[3 cs x 2 feat]

As with aggregate()’s render parameter, this bare statement prints automatically only because render = true; with the default render = false, the same unassigned, unstreamed call would produce no output.

Notes¶

  • The sort is always count-descending, value-ascending-on-ties — there is no parameter to reverse either ordering; pipe the result through sort_values afterward if you need a different order. A missing key is never alphabetized against real values for tie-breaking; it always sorts after every real value tied with it on count.

  • dropnull = false gives a missing feature value its own group in the count, printed as NULL in the output, rather than excluding those rows.

  • top_n truncates after sorting, so it always keeps the most frequent groups, not an arbitrary prefix of the unsorted data.

See Also¶

  • DataFrame::group_by: the general grouped-aggregation surface count_by() is a convenience shortcut for.

  • DataFrame::bucketize: often used just before count_by(), to tally how many cases fell into each engineered band.

  • DataFrame::mean_by: the same grouping idea, but averaging a value feature per group instead of counting rows.
