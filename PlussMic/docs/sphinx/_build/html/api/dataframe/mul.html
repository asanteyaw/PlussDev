What It Does¶

The named-method form of elementwise multiplication. mul() shares the exact same overload shape and alignment rules as add() and the rest of the arithmetic family — see add()’s “What It Does” for the full explanation of the scalar/frame/Thread operand shapes and the axis/options parameters.

A common use is rescaling a feature (unit conversion, currency conversion, applying a tax or discount rate) without hand-writing a loop over cells.

Parameters¶

other

The right-hand operand, multiplied against the current frame: double (broadcast scalar), const DataFrame& (aligned frame-to-frame), or const Thread& (broadcast per axis).

axis (Axis, default Axis::Feature, Thread overloads only)

Same meaning as add()’s axis: Axis::Feature (default) supplies one value per feature; Axis::Case supplies one value per case.

options (AlignOptions, optional)

Same meaning as add()’s options.

Returns¶

DataFrame A new frame, same shape as the source, with every numeric feature multiplied by other. Non-numeric features are left unchanged.

Examples¶

Example 1. Scale every numeric feature by a constant factor.

using namespace pluss::table;

auto prices = DataFrame({
    {"units", pluss::make_series({2.0, 5.0, 1.0})},
    {"price", pluss::make_series({10.0, 20.0, 30.0})},
}, pluss::make_note({"a", "b", "c"}));

auto out = prices.mul(2.0);
std::cout << out;

Output¶

===================
     | units  price
-------------------
a    | 4      20   
b    | 10     40   
c    | 2      60   
-------------------
[3 cs x 2 feat]

Example 2. Multiply by a Thread with one value per feature (Axis::Feature, the default) — apply a different scale factor to each column.

auto per_feature_scale = Thread(pluss::make_series({10.0, 0.9})); // units x10, price x0.9
auto out = prices.mul(per_feature_scale);
std::cout << out;

Output¶

===================
     | units  price
-------------------
a    | 20     9    
b    | 50     18   
c    | 10     27   
-------------------
[3 cs x 2 feat]

Notes¶

  • Non-numeric features are always left unchanged.

  • Multiplication is commutative, so a.mul(b) and b.mul(a) (or the reflected rmul()) produce the same result for a shared shape.

  • Shares its full overload shape, alignment semantics, and AlignOptions behavior with add(), sub(), div(), truediv(), floordiv(), mod(), and pow().
