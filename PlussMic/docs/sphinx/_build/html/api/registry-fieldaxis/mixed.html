RegistryFieldAxisAccessor::mixed¶

Back to RegistryFieldAxisAccessor API Reference

Signature¶

Registry RegistryFieldAxisAccessor::mixed() const

What It Does¶

A named shorthand for kind(SlotKind::Mixed) — returns a new registry containing only the fields whose Slot::kind() is SlotKind::Mixed (the field holds more than one distinct value kind, or a Series field mixes numeric dtypes). These are exactly the fields that make a registry fail kindelize()’s stream-compatibility check.

Parameters¶

None

Returns¶

Registry A new registry containing only the genuinely mixed-kind fields.

Examples¶

Example 1. Isolate the mixed field in a registry that also has a uniform field.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1), pluss::make_series(2)})},
    {"mixed", pluss::bundle::Slot({pluss::make_series(1), pluss::make_note("x")})},
});

auto out = rg.fieldaxis().mixed();
for (const auto& key : out.fields()) std::cout << key << " ";

Output¶

mixed

Notes¶

  • Equivalent to kind(SlotKind::Mixed) — see kind() for the general form.

  • Directly identifies which fields would make kindelize() throw.

See Also¶

  • RegistryFieldAxisAccessor::kind: the general form this method wraps.

  • Registry::kindelize: the conversion these fields block.

  • Registry::profiles: the per-field type tally that shows exactly why a field is mixed.
