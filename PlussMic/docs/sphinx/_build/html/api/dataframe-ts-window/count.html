DataFrameTsWindowAccessor::count¶

Back to DataFrameTsWindowAccessor API Reference

Signature¶

DataFrameTsWindowAccessor::count(std::string_view value_feature = {}) const -> DataFrame

What It Does¶

Computes, once per group, the number of observations of value_feature over the trailing duration-length window ending at that group’s own most recent time-axis value (or an explicit TsOptions.anchor, if one was set) — the same per-group trailing window sum() uses, with Count in place of Sum. Unlike the other DataFrameTsWindowAccessor methods, value_feature doesn’t need to be numeric for count(), since it only counts observations rather than combining their values.

Parameters¶

value_feature (std::string_view, default empty)

The feature to count observations of. May be omitted only if exactly one feature is currently bound on the accessor.

Returns¶

DataFrame One row per distinct group, with a group-key column (or columns) and a "count_" + value_feature column.

Examples¶

Example 1. Count each sensor’s readings over the trailing 2 days ending at that sensor’s own last reading — the same dataset as sum().

using namespace pluss::table;

auto readings = DataFrame(
    {{"sensor_id", Thread(pluss::make_note({"A", "A", "A", "B", "B", "B"}))},
     {"value",     Thread(pluss::make_series({10.0, 20.0, 15.0, 5.0, 8.0, 12.0}))}},
    Thread(pluss::make_timeline({
        "2024-01-01T00:00:00Z", "2024-01-03T00:00:00Z", "2024-01-04T00:00:00Z",
        "2024-01-02T00:00:00Z", "2024-01-05T00:00:00Z", "2024-01-06T00:00:00Z"})));

auto groups = readings.features("sensor_id");
auto out = readings.features({"value"}).ts({.group = groups}).window("2d").count();
std::cout << out;

Output¶

=============================
     | sensor_id  count_value
-----------------------------
0    | A          2          
1    | B          2          
-----------------------------
[2 cs x 2 feat]

Sensor A’s trailing window holds 2 observations (20, 15); the earlier reading (10, from 2024-01-01) falls outside the (2024-01-02, 2024-01-04] window, so it isn’t counted. Sensor B’s window similarly holds 2 observations.

Example 2. Count a Note-kind (text) feature — unlike sum/mean/min/max, count() doesn’t require value_feature to be numeric.

using namespace pluss::table;

auto readings = DataFrame(
    {{"sensor_id", Thread(pluss::make_note({"A", "A", "A", "B", "B", "B"}))},
     {"status",    Thread(pluss::make_note({"ok", "ok", "warn", "ok", "warn", "ok"}))}},
    Thread(pluss::make_timeline({
        "2024-01-01T00:00:00Z", "2024-01-03T00:00:00Z", "2024-01-04T00:00:00Z",
        "2024-01-02T00:00:00Z", "2024-01-05T00:00:00Z", "2024-01-06T00:00:00Z"})));
std::cout << readings;

auto groups = readings.features("sensor_id");
auto out = readings.features({"status"}).ts({.group = groups}).window("2d").count();
std::cout << out;

Output (before)¶

==============================
           | sensor_id  status
------------------------------
2024-01-01 | A          ok    
2024-01-03 | A          ok    
2024-01-04 | A          warn  
2024-01-02 | B          ok    
2024-01-05 | B          warn  
2024-01-06 | B          ok    
------------------------------
[6 cs x 2 feat]

Output (after)¶

==============================
     | sensor_id  count_status
------------------------------
0    | A          2           
1    | B          2           
------------------------------
[2 cs x 2 feat]

count() only tallies how many observations fall in the window — it never reads status’s actual text values, so there’s no numeric requirement on it the way there is for sum()/mean()/min()/max().

Notes¶

  • See sum() for the full window, closure, and anchoring rules — they apply identically here.

  • Unlike sum/mean/min/max, count’s value_feature isn’t required to be numeric.

See Also¶

  • DataFrameTsWindowAccessor::sum, DataFrameTsWindowAccessor::mean, DataFrameTsWindowAccessor::min, DataFrameTsWindowAccessor::max: the other per-group trailing aggregates sharing this same window.
