DataFrameTsWindowAccessor::mean¶

Back to DataFrameTsWindowAccessor API Reference

Signature¶

DataFrameTsWindowAccessor::mean(std::string_view value_feature = {}) const -> DataFrame

What It Does¶

Computes, once per group, the mean of value_feature over the trailing duration-length window ending at that group’s own most recent time-axis value (or an explicit TsOptions.anchor, if one was set) — the same per-group trailing window sum() uses, with Mean in place of Sum. See sum() for the full setup requirements (TsOptions.group, window closure, anchoring).

Parameters¶

value_feature (std::string_view, default empty)

The feature to average. May be omitted only if exactly one feature is currently bound on the accessor.

Returns¶

DataFrame One row per distinct group, with a group-key column (or columns) and a "mean_" + value_feature column.

Examples¶

Example 1. Average each sensor’s readings over the trailing 2 days ending at that sensor’s own last reading — the same dataset as sum().

using namespace pluss::table;

auto readings = DataFrame(
    {{"sensor_id", Thread(pluss::make_note({"A", "A", "A", "B", "B", "B"}))},
     {"value",     Thread(pluss::make_series({10.0, 20.0, 15.0, 5.0, 8.0, 12.0}))}},
    Thread(pluss::make_timeline({
        "2024-01-01T00:00:00Z", "2024-01-03T00:00:00Z", "2024-01-04T00:00:00Z",
        "2024-01-02T00:00:00Z", "2024-01-05T00:00:00Z", "2024-01-06T00:00:00Z"})));

auto groups = readings.features("sensor_id");
auto out = readings.features({"value"}).ts({.group = groups}).window("2d").mean();
std::cout << out;

Output¶

============================
     | sensor_id  mean_value
----------------------------
0    | A          17.5      
1    | B          10        
----------------------------
[2 cs x 2 feat]

Sensor A’s trailing window holds (20, 15), averaging to 17.5; sensor B’s holds (8, 12), averaging to 10 — matching sum()’s 35/20 divided by 2 observations each.

Example 2. Pass value_feature explicitly when more than one feature is bound on the accessor.

using namespace pluss::table;

auto readings = DataFrame(
    {{"sensor_id", Thread(pluss::make_note({"A", "A", "B", "B"}))},
     {"temp",      Thread(pluss::make_series({10.0, 20.0, 5.0, 8.0}))},
     {"humidity",  Thread(pluss::make_series({40.0, 42.0, 55.0, 50.0}))}},
    Thread(pluss::make_timeline({
        "2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z",
        "2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z"})));
std::cout << readings;

auto groups = readings.features("sensor_id");
auto out = readings.features({"temp", "humidity"}).ts({.group = groups}).window("2d").mean("humidity");
std::cout << out;

Output (before)¶

======================================
           | sensor_id  temp  humidity
--------------------------------------
2024-01-01 | A          10    40      
2024-01-02 | A          20    42      
2024-01-01 | B          5     55      
2024-01-02 | B          8     50      
--------------------------------------
[4 cs x 3 feat]

Output (after)¶

===============================
     | sensor_id  mean_humidity
-------------------------------
0    | A          41           
1    | B          52.5         
-------------------------------
[2 cs x 2 feat]

With two features bound (temp and humidity), value_feature can no longer be inferred — naming "humidity" explicitly picks it out and leaves temp untouched by the aggregate.

Notes¶

  • See sum() for the full window, closure, and anchoring rules — they apply identically here.

  • A group whose window ends up with zero observations produces NULL rather than a divide-by-zero error.

See Also¶
