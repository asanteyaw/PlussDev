DataFrameTsAccessor::lead¶

Back to DataFrameTsAccessor API Reference

Signature¶

DataFrameTsAccessor::lead(std::int64_t periods = 1) const -> DataFrame

What It Does¶

Shifts every bound feature periods rows backward: out[i] = x[i + periods] where that index is in bounds, NULL otherwise. A negative periods delegates to lag() with the sign flipped.

Parameters¶

periods (std::int64_t, default 1)

The number of rows to shift backward. Negative values behave as lag(-periods) instead.

Returns¶

DataFrame A new frame, same shape and case labels as the accessor’s bound features, with each feature led by periods rows.

Examples¶

Example 1. Lead a numeric feature by one row.

using namespace pluss::table;

auto readings = DataFrame({
    {"sensor_id", Thread(pluss::make_series({1, 2, 3, 4}))},
    {"load",      Thread(pluss::make_series({10.0, 20.0, 15.0, 30.0}))},
});

auto out = readings.features({"load"}).ts().lead(1);
std::cout << out;

Output¶

===========
     | load
-----------
0    | 20  
1    | 15  
2    | 30  
3    | NULL
-----------
[4 cs x 1 feat]

Each case now shows the next case’s load value: case 0 shows case 1’s 20, case 1 shows case 2’s 15, and so on. Case 3 has no successor, so it’s NULL — the NULL lands at the opposite end from lag().

Notes¶

  • lead(periods) with a negative periods is exactly lag(-periods) — the two methods share one implementation, differing only in shift direction.

  • The result keeps the accessor’s original case labels; nothing is dropped or re-indexed.

See Also¶

  • DataFrameTsAccessor::lag: the mirror-image shift.

  • DataFrame::shift: the equivalent top-level operation (a negative shift argument corresponds to a lead) outside the ts() accessor.
