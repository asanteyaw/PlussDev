ThreadLabelAccessor::has¶

Back to ThreadLabelAccessor API Reference

Signatures¶

ThreadLabelAccessor::has() const -> bool
ThreadLabelAccessor::has(const Thread& values) const -> Thread

What It Does¶

Two unrelated questions share this name:

  • has() (no arguments) answers a structural question: have case labels ever been explicitly attached to this thread (via set() or a derived operation), as opposed to still sitting at the default integer range? A direct forward to Thread::has_caselbl().

  • has(values) answers an elementwise membership question over the case labels themselves (not the thread’s own data): for each row, is its case label equal to any of values? The result keeps the same case labels as *this, display_name "has".

Parameters¶

values (const Thread&, one overload)

A collection of values; each row’s case label is tested for membership against all of them.

Returns¶

bool (No-argument overload) Whether case labels have been explicitly set.

Thread (values-taking overload) A Bool thread, one entry per row, with the same case labels as *this.

Examples¶

Example 1. Check structural state before and after attaching labels.

using namespace pluss::table;

auto sales = Thread(pluss::make_series({100.0, 200.0, 150.0, 90.0}));
std::cout << sales.label().has();

auto tagged = sales.label().set(
    Thread(pluss::make_note({"east", "west", "east", "north"})));
std::cout << tagged.label().has();

Output¶

false
true

sales still sits at the default integer range — no case labels attached yet. tagged had set() called on it, so has() becomes true.

Example 2. Elementwise membership against several values, testing the case labels rather than tagged’s own numeric data.

auto in_set = tagged.label().has(Thread(pluss::make_note({"west", "north"})));
std::cout << in_set;

Output¶

east   false
west   true
east   false
north  true

ptype: Series

Rows whose case label is "west" or "north" flag true — the check runs against the labels shown on the left, not against tagged’s own sales values.

Notes¶

  • The no-argument overload is purely structural — it says nothing about whether any particular label value is present.

  • has(values) tests the case labels, not the thread’s own data — for a membership test over the data itself, use Thread::has() directly.

  • Identical to calling Thread::has_caselbl() (no-argument overload) directly.

See Also¶

  • ThreadLabelAccessor::set: the operation that turns has() from false to true.

  • ThreadLabelAccessor::pos, ThreadLabelAccessor::find: locate where a label value occurs, rather than just whether it does.
