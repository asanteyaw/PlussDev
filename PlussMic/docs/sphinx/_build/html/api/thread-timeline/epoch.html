ThreadTimelineAccessor::epoch¶

Back to ThreadTimelineAccessor API Reference

Signature¶

ThreadTimelineAccessor::epoch(TimeUnit unit = TimeUnit::Nanos) const -> Thread

What It Does¶

Replaces the bound thread with its Unix epoch value in unit, as a numeric Series.

Parameters¶

unit (TimeUnit, default TimeUnit::Nanos)

One of the fixed-duration units: Nanos, Micros, Millis, Seconds, or Days. Passing a span-only unit (Weeks, Months, Years, BusinessDays — the calendar-relative units meant for span(), not a fixed epoch count) throws.

Returns¶

Thread A new Series-kind (Int64) thread, same length as the bound thread, holding each row’s epoch count in unit.

Examples¶

Example 1. Extract the epoch second from every row.

using namespace pluss::table;

auto events = Thread(pluss::make_timeline({
    "1970-01-01T00:00:00Z",
    "2024-01-01T00:00:10Z",
}));
auto out = events.tl().epoch(TimeUnit::Seconds);
std::cout << out;

Output¶

0  0
1  1704067210

ptype: Series

Example 2. Call epoch() with no argument to confirm the default unit is Nanos, not Seconds.

auto out2 = events.tl().epoch();
std::cout << out2;

Output¶

0  0
1  1704067210000000000

ptype: Series

Example 3. Pass a span-only unit to see the call throw.

try {
  auto bad = events.tl().epoch(TimeUnit::Months);
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

Thread::tl().epoch: unit is span-only; use Thread::tl().span

Months (like Weeks, Years, and BusinessDays) only makes sense as a calendar-relative distance between two timestamps, so epoch() rejects it outright — see span() for the method that does accept it.

Notes¶

  • The default unit is Nanos, not Seconds.

  • Only fixed-duration units are accepted (Nanos/Micros/Millis/Seconds/ Days); passing Weeks, Months, Years, or BusinessDays throws.

  • .tl() requires the bound thread to already be Timeline/TimeIndex-kind — the accessor’s constructor throws otherwise.

  • A NaT row (or one already null on the underlying thread) displays as "NULL", not a sentinel epoch value.

See Also¶

  • ThreadTimelineAccessor::span: elapsed distance between two timelines, including calendar-relative units epoch() doesn’t support.
