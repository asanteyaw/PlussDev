ThreadTimelineAccessor::localize¶

Back to ThreadTimelineAccessor API Reference

Signature¶

ThreadTimelineAccessor::localize(const TimelineLocalizeOptions& options = {}) const -> Thread

What It Does¶

Reinterprets the bound thread’s current clock reading as a naive local wall-clock time in options.tz, and converts it to the true UTC instant that local reading corresponds to — same length, still Timeline/TimeIndex-kind. This changes the underlying instant (unlike tz(), which only relabels display). The result is then displayed under options.tz, so its wall-clock text looks unchanged even though the instant it now represents has shifted.

Parameters¶

options (const TimelineLocalizeOptions&)

tz (default "UTC"; must be one of the four supported names — see tz()’s Notes — and cannot be empty), fold (0 or 1; during the one-hour daylight-saving fall-back overlap, fold = 0 resolves to the daylight offset and fold = 1 resolves to the standard offset), and nonexistent (only the literal "shift_forward" is recognized as a real handling mode; any other value — including the default "raise" — throws when a row’s local reading falls in the daylight-saving spring-forward gap, a wall-clock reading that never actually occurred).

Returns¶

Thread A new Timeline/TimeIndex-kind thread, same length as the bound thread, with its underlying instant recomputed as if its prior reading were local time in options.tz.

Examples¶

Example 1. Localize a naive-looking reading to "America/New_York" and confirm the underlying instant moved via epoch().

using namespace pluss::table;

auto events = Thread(pluss::make_timeline({
    "2024-01-31T09:15:30Z",
    "2024-07-15T09:15:30Z",
}));

TimelineLocalizeOptions options;
options.tz = "America/New_York";
auto out = events.tl().localize(options);
std::cout << out;

std::cout << events.tl().epoch(TimeUnit::Seconds);
std::cout << out.tl().epoch(TimeUnit::Seconds);

Output (localized display)¶

0  2024-01-31 09:15:30
1  2024-07-15 09:15:30

ptype: Timeline

Output (epoch seconds, before)¶

0  1706692530
1  1721034930

ptype: Series

Output (epoch seconds, after)¶

0  1706710530
1  1721049330

ptype: Series

The displayed wall-clock text is identical before and after — both still read 09:15:30 — because the result is displayed under the new "America/New_York" label, which reintroduces the same offset that was just subtracted. The epoch(Seconds) values prove the underlying instant actually moved: 18,000 seconds later in January (Eastern Standard Time) and 14,400 seconds later in July (Eastern Daylight Time).

Example 2. Use fold to disambiguate a wall-clock reading that occurs twice during New York’s fall-back transition.

auto reading = Thread(pluss::make_timeline({"2024-11-03T01:30:00Z"}));

TimelineLocalizeOptions fold0;
fold0.tz = "America/New_York";
fold0.fold = 0;
std::cout << reading.tl().localize(fold0).tl().epoch(TimeUnit::Seconds);

TimelineLocalizeOptions fold1;
fold1.tz = "America/New_York";
fold1.fold = 1;
std::cout << reading.tl().localize(fold1).tl().epoch(TimeUnit::Seconds);

Output (fold = 0)¶

0  1730611800

ptype: Series

Output (fold = 1)¶

0  1730615400

ptype: Series

01:30 local occurs twice on 2024-11-03 — fold = 0 picks the earlier (daylight-time) occurrence; fold = 1 picks the later one, exactly 3,600 seconds after.

Example 3. nonexistent = "shift_forward" resolves a spring-forward-gap reading instead of throwing.

auto gap = Thread(pluss::make_timeline({"2024-03-10T02:30:00Z"}));

TimelineLocalizeOptions options;
options.tz = "America/New_York";
options.nonexistent = "shift_forward";
auto out3 = gap.tl().localize(options);
std::cout << out3;

Output¶

0  2024-03-10 03:00:00

ptype: Timeline

02:30 local never happened on 2024-03-10 — clocks jumped straight from 02:00 to 03:00. "shift_forward" resolves to the first instant after the gap closes.

Example 4. Leave nonexistent at its default "raise" for the same reading, to see it throw.

TimelineLocalizeOptions defaults;
defaults.tz = "America/New_York";
try {
  auto bad = gap.tl().localize(defaults);
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

tz_localize: nonexistent local time (DST spring-forward gap)

Notes¶

  • localize() changes the underlying instant; tz() never does. Reach for localize() only when the current ticks are naive local readings that have never been anchored to a real instant; reach for tz() when the ticks are already correct and you just want a different display timezone.

  • options.tz only accepts the same four names as tz() — anything else throws — and cannot be empty.

  • fold only matters for the one hour of wall-clock time that repeats during a fall-back transition; outside that window it has no effect.

  • nonexistent only recognizes "shift_forward" as an actual handling strategy; every other value (default "raise" included) throws for a spring-forward-gap reading.

  • .tl() requires the bound thread to already be Timeline/TimeIndex-kind — the accessor’s constructor throws otherwise.

  • A NaT row stays NaT regardless of options.

See Also¶

  • ThreadTimelineAccessor::utc: shorthand for tz("UTC").
