AtlasTimelineAccessor::localize¶

Back to AtlasTimelineAccessor API Reference

Signature¶

AtlasTimelineAccessor::localize(const TimelineLocalizeOptions& options = {}) const -> Atlas

What It Does¶

Reinterprets every Timeline/TimeIndex feature’s current clock reading, in every frame of the stack, as a naive local wall-clock time in options.tz, and converts it to the true UTC instant that local reading corresponds to — the same transform DataFrame::tl().localize() applies to a single frame, broadcast across the whole Atlas via map_frames(). This changes the underlying instant (unlike tz(), which only relabels display).

Parameters¶

options (const TimelineLocalizeOptions&) tz (default "UTC"; must be one of the four supported names — see tz() — and cannot be empty), fold (0 or 1; disambiguates the daylight-saving fall-back overlap), and nonexistent (only "shift_forward" is a recognized handling mode for a spring-forward-gap reading; anything else, including the default "raise", throws). See DataFrameTimelineAccessor::localize for the full field breakdown and DST edge-case examples.

Returns¶

Atlas A new atlas, same depth and depth labels as the source, with each frame’s time feature’s underlying instant recomputed as if its prior reading were local time in options.tz.

Examples¶

Example 1. Localize a Timeline feature stacked across two frames to "America/New_York", confirming via epoch() that the underlying instant actually moves.

using namespace pluss::table;

auto q1 = DataFrame({
    {"ts", Thread(pluss::make_timeline({"2024-01-31T09:15:30Z", "2024-02-29T23:45:00Z"}))},
});
auto q2 = DataFrame({
    {"ts", Thread(pluss::make_timeline({"2024-07-06T14:00:00Z", "2023-03-01T00:00:00Z"}))},
});
auto atlas = Atlas({q1, q2});

TimelineLocalizeOptions options;
options.tz = "America/New_York";
auto localized = atlas.tl().localize(options);

std::cout << localized.frame(0) << "\n" << localized.frame(1) << "\n";
std::cout << "epoch before:\n" << atlas.tl().epoch(TimeUnit::Seconds).frame(0);
std::cout << "epoch after:\n" << localized.tl().epoch(TimeUnit::Seconds).frame(0);

The displayed wall-clock text is identical before and after localizing — both frames still read the same 09:15:30/23:45:00/etc. — because the result is displayed under the new "America/New_York" label, which reintroduces the same offset that was just subtracted. The epoch(Seconds) values on frame(0) prove the underlying instant actually moved: 18,000 seconds later for January (Eastern Standard Time, -5:00).

Notes¶

  • localize() changes the underlying instant; tz() never does. Reach for localize() only when the current ticks are naive local readings that have never been anchored to a real instant; reach for tz() when the ticks are already correct and a different display timezone is all that’s needed.

  • options.tz only accepts the same four names as tz(), and cannot be empty.

  • Atlas::tl() requires every feature on each stacked frame to already be Timeline/TimeIndex-kind, checked lazily per frame the first time a method like this one is actually called — see Atlas::tl.

  • A NaT row stays NaT regardless of options.

  • Each frame is transformed independently — see AtlasTimelineAccessor::year for a worked example of this per-frame independence.
