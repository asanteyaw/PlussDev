What It Does¶

Replaces every Timeline/TimeIndex feature in every frame of the stack with the elapsed distance between it and other, in options.unit (or plain unit) — the same transform DataFrame::tl().span() applies to a single frame, broadcast across the whole Atlas via map_frames().

```{important} No Atlas overload — the same other is applied to every frame Unlike DataFrameTimelineAccessor::span, which has a const DataFrame& overload pairing each frame against its own matching other frame, this accessor has no Atlas overload. Only a single Thread or pluss::Timeline is accepted as other, and that same value is used as the right-hand side for every frame in the stack — there is no way to pair each frame against a different per-frame other in one call.


## Parameters

**other** (`const Thread&` / `const pluss::Timeline&`)
    The right-hand timestamp(s), applied identically to every frame in the stack — see
    the important callout above.

**options** (`const TimelineSpanOptions&`)
    `unit` (default `TimeUnit::Days`), `mode`, `anchor`, `signed_result`, and
    `calendar` — the same fields as
    [`DataFrameTimelineAccessor::span`](../dataframe-timeline/span.md)'s `options`; see
    that page for the full breakdown and worked examples of each.

**unit** (`TimeUnit`, convenience overload)
    Shorthand for `TimelineSpanOptions{.unit = unit}` with every other option left at
    its default.

## Returns

`Atlas`
    A new atlas, same depth and depth labels as the source, with each frame's time
    feature replaced by an `Int64` Series of elapsed distances to `other`.

## Examples

Example 1. Span two frames' single-row `Timeline` features against the same `other`
value.

```cpp
using namespace pluss::table;

auto s1 = DataFrame({{"ts", Thread(pluss::make_timeline({"2024-01-01T00:00:00Z"}))}});
auto s2 = DataFrame({{"ts", Thread(pluss::make_timeline({"2024-02-01T00:00:00Z"}))}});
auto atlas = Atlas({s1, s2});

auto other = Thread(pluss::make_timeline({"2024-02-01T00:00:00Z"}));
auto out = atlas.tl().span(other, TimeUnit::Days);
std::cout << out.frame(0) << "\n" << out.frame(1);

Output¶

===========
     | ts  
-----------
0    | 31  
-----------
[1 cs x 1 feat]
===========
     | ts  
-----------
0    | 0   
-----------
[1 cs x 1 feat]

frame(0)’s "2024-01-01" is 31 days before other ("2024-02-01"); frame(1)’s own value is already exactly other, so its span is 0 — the same other value was measured against both frames.

Notes¶

  • See the important callout above before reaching for this method to compare two atlases frame-by-frame — there is no such overload; other is one fixed value (or column) applied to every frame.

  • Fixed-duration units (Nanos/Micros/Millis/Seconds/Days/Weeks) are plain elapsed-time differences. Calendar units (Months/Years) count completed calendar periods or crossed calendar boundaries, per options.mode. BusinessDays counts business days per options.calendar.

  • Calendar units and BusinessDays require *this and other to share the same timezone — mismatched timezones throw; convert with tz() first.

  • Atlas::tl() requires every feature on each stacked frame to already be Timeline/TimeIndex-kind, checked lazily per frame the first time a method like this one is actually called — see Atlas::tl.

  • If either side is NaT for a row, that row’s span displays as "NULL".

  • Each frame is transformed independently against the same other — see the important callout above.
