ThreadPlotAccessor::lag¶

Back to ThreadPlotAccessor API Reference

Signature¶

ThreadPlotAccessor::lag(const LagPlotOptions& options = {}) const -> pluss::pl::Studio

What It Does¶

Draws a lag plot for the bound thread’s values: a scatter of x(t) against x(t + lag) — the single-series specialization of DataFramePlotAccessor::lag, which on the 2D accessor requires naming a feature; here the bound thread is always the one and only feature lagged.

Note

At least two data points are required Same as the 2D accessor: a thread with fewer than two rows throws "flash::lagplot requires at least two points".

Parameters¶

options (LagPlotOptions) The identical struct documented on DataFramePlotAccessor::lag (lag, max_points, marker_area, trace_width).

Returns¶

pluss::pl::Studio A figure with one pane containing a single scatter (“cloud”) trace of x(t) vs. x(t + lag).

Examples¶

Example 1. Default options (lag = 1).

using namespace pluss::table;

auto level = Thread(pluss::make_series({10.0, 10.5, 11.0, 10.8, 11.2, 11.5, 11.3, 11.8}));
level = level.name("level");

auto chart = level.plot().lag();
chart.show();

Example 2. An explicit LagPlotOptions with a larger lag.

LagPlotOptions options;
options.lag = 3;

auto chart = level.plot().lag(options);
chart.show();

Notes¶

  • The bound thread is always the single lagged feature — there is no feature-name argument the way the 2D accessor’s lag() has.

  • lag is clamped to [1, n - 1], never throwing for an out-of-range request.

  • A thread with fewer than two rows throws before any point is drawn.

  • Returns a pluss::pl::Studio — see line() for how to view or save the result.

See Also¶

  • DataFramePlotAccessor::lag: the method this delegates to.

  • ThreadPlotAccessor::act: every lag’s correlation coefficient at once, instead of one lag’s raw scatter.
