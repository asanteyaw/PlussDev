AxelFieldAxisAccessor::kind¶

Back to AxelFieldAxisAccessor API Reference

Signature¶

Axel AxelFieldAxisAccessor::kind(SlotKind kind) const

What It Does¶

Returns a new axel where every registry frame is narrowed to only the fields whose Slot::kind() equals kind. This is the general form behind the seven named shorthand methods (series(), note(), timeline(), timeindex(), mixed(), nulls(), empty()) — each is a one-line wrapper calling kind() with a fixed SlotKind value. Applies RegistryFieldAxisAccessor::kind to every frame via Axel::map.

Parameters¶

kind (SlotKind) The kind to filter fields by — one of SlotKind::Empty, SlotKind::Null, SlotKind::Series, SlotKind::Note, SlotKind::Timeline, SlotKind::TimeIndex, SlotKind::Mixed.

Returns¶

Axel A new axel with every frame narrowed to fields whose kind matches.

Examples¶

Example 1. Select every Series-kind field directly via kind(), equivalent to calling series().

auto r0 = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1), pluss::make_series(2)})},
    {"user_id", pluss::bundle::Slot({pluss::make_series(3), pluss::make_series(4)})},
    {"city", pluss::bundle::Slot({pluss::make_note("Accra"), pluss::make_note("Tema")})},
});
auto axel = pluss::bundle::Axel({r0, r0});

auto out = axel.fieldaxis().kind(pluss::bundle::SlotKind::Series);
for (const auto& key : out.registry(0).fields()) std::cout << key << " ";

Output¶

id user_id

Notes¶

  • Prefer the named shorthand (series(), note(), etc.) at call sites — they read more clearly than kind(SlotKind::...).

  • A field’s kind reflects its Slot’s own kind() — see Slot::kind for exactly how a slot’s kind is determined from its values.

  • Applied independently per frame — different frames can end up with different resulting field sets if their schemas differ.

See Also¶
