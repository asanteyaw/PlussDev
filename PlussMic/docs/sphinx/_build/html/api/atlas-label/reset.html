AtlasLabelAccessor::reset¶

Back to AtlasLabelAccessor API Reference

Signature¶

AtlasLabelAccessor::reset() const -> Atlas

What It Does¶

Returns a copy of the bound atlas with its depth-axis labels cleared back to the default integer sequence 0, 1, 2, ..., depth() - 1 — the depth-axis counterpart to DataFrame::label().reset().

Parameters¶

None

Returns¶

Atlas A new atlas, identical in frame content, with its depth labels cleared to 0, 1, 2, ....

Examples¶

Example 1. Reset a labeled atlas’s depth labels back to the default sequence.

auto q1 = pluss::table::DataFrame({
    {"sales", pluss::table::Thread(pluss::make_series({100.0, 120.0}))},
});
auto q2 = pluss::table::DataFrame({
    {"sales", pluss::table::Thread(pluss::make_series({110.0, 90.0}))},
});
auto atlas = pluss::table::Atlas({q1, q2}, pluss::table::Thread(pluss::make_note({"jan", "feb"})));

auto reset_atlas = atlas.label().reset();
std::cout << "has after reset: " << reset_atlas.label().has() << "\n";
std::cout << reset_atlas.label().values();

Output¶

has after reset: 0
0  0
1  1
ptype: Series

Notes¶

  • After reset(), has() reports false again — reset() clears the explicit-labels flag, not just the values, even though values() always returns something regardless.

  • The original atlas is left unchanged — reset() returns a new Atlas.

  • Functionally identical to range(); prefer whichever name reads more clearly at the call site.

See Also¶

  • AtlasLabelAccessor::has: check whether depth labels are set — flips to false after reset().

  • AtlasLabelAccessor::range: the same operation, named after its result rather than the act of clearing.

  • AtlasLabelAccessor::set: set the depth labels to something other than the default sequence.
