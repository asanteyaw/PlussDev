CatalogTimelineAccessor::time¶

Back to CatalogTimelineAccessor API Reference

Signature¶

Catalog CatalogTimelineAccessor::time() const

What It Does¶

Keeps only the time-of-day portion of each bound key’s timestamp — the date is reset to the Unix epoch day (1970-01-01) — replacing each bound key’s values in place.

Important

CatalogTimelineAccessor requires every bound key to be Timeline- or TimeIndex-kind Same precondition as every method on this accessor — see CatalogTimelineAccessor::isnat’s own important callout for the full explanation and the exact throw message.

Parameters¶

None

Returns¶

Catalog A new catalog with every bound key’s date portion reset to 1970-01-01, keeping only the time-of-day.

Examples¶

Example 1. Keep only the time-of-day from two timestamps.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "ts"_k = pluss::kindle::Stream(pluss::make_timeline({"2024-01-31T09:15:30Z", "2024-02-29T23:45:00Z"})),
});
auto out = ct.tl().time();
auto fmted = out.tl().fmt("%Y-%m-%d %H:%M:%S");
std::cout << fmted.keys("ts").as_note().at(0) << " | " << fmted.keys("ts").as_note().at(1);

Output¶

1970-01-01 09:15:30 | 1970-01-01 23:45:00

Every row’s date is now 1970-01-01; each original time-of-day is preserved exactly.

Notes¶

  • The result is still Timeline/TimeIndex-kind with a fixed date component — it’s meant for comparing or grouping by time-of-day, not as a display format. Use fmt("%H:%M:%S") for a bare text time.

  • See the important callout above.

See Also¶

  • CatalogTimelineAccessor::date: the mirror-image operation, keeping the date and zeroing the time-of-day.

  • Catalog::tl: the entry point this accessor is reached from.

  • RegistryTimelineAccessor::time: the bundle-model equivalent.
