CatalogTimelineAccessor::localize¶

Back to CatalogTimelineAccessor API Reference

Signature¶

Catalog CatalogTimelineAccessor::localize(const pluss::table::TimelineLocalizeOptions& options = {}) const

What It Does¶

Reinterprets each bound key’s current clock reading as a naive local wall-clock time in options.tz, and converts it to the true UTC instant that local reading corresponds to. This changes the underlying instant (unlike tz(), which only relabels display). The options.tz label attached by localize() also survives being read back through any further .tl() call — see Example 1.

Important

CatalogTimelineAccessor requires every bound key to be Timeline-kind Same precondition as every method on this accessor — see CatalogTimelineAccessor::isnat’s own important callout for the full explanation and the exact throw message.

Parameters¶

options (const pluss::table::TimelineLocalizeOptions&) tz (default "UTC"; must be one of the four supported names — see tz() — and cannot be empty), fold (0 or 1; disambiguates the daylight-saving fall-back overlap), and nonexistent (only "shift_forward" is a recognized handling mode for a spring-forward-gap reading; anything else, including the default "raise", throws).

Returns¶

Catalog A new catalog with every bound key’s underlying instant recomputed as if its prior reading were local time in options.tz.

Examples¶

Example 1. Localize a timestamp to "America/New_York". epoch() confirms the instant actually moved; a follow-up fmt() shows the shifted instant correctly rendered in NY-local wall-clock time.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "ts"_k = pluss::kindle::Stream(pluss::make_timeline({"2024-01-31T09:15:30Z"})),
});

pluss::table::TimelineLocalizeOptions options;
options.tz = "America/New_York";
auto localized = ct.tl().localize(options);

auto before = ct.tl().epoch(pluss::table::TimeUnit::Seconds);
auto after = localized.tl().epoch(pluss::table::TimeUnit::Seconds);
std::cout << "epoch before: " << before.keys("ts").as_series().to_vec<std::int64_t>()[0] << "\n";
std::cout << "epoch after: " << after.keys("ts").as_series().to_vec<std::int64_t>()[0] << "\n";

auto fmted = localized.tl().fmt("%Y-%m-%d %H:%M:%S");
std::cout << "displayed: " << fmted.keys("ts").as_note().at(0);

Output¶

epoch before: 1706692530
epoch after: 1706710530
displayed: 2024-01-31 09:15:30

The 18,000-second delta (5 hours) confirms the instant genuinely moved — the correct behavior for "America/New_York" in January (Eastern Standard Time, -5:00). The displayed text, 09:15:30, is the shifted instant correctly rendered as NY-local wall-clock time.

Notes¶

  • localize() changes the underlying instant; tz() never does.

  • options.tz only accepts the same four names as tz(), and cannot be empty.

  • Internally, each bound key stores its Timeline values independently; the resulting per-row tz labels round-trip correctly through the kindle::Stream boundary every further .tl() call goes through. If every row does not already share the same display timezone going into a .tl() call, the call throws rather than picking one arbitrarily.

  • See the important callout above.
