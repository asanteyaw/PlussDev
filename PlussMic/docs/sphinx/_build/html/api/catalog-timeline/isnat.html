CatalogTimelineAccessor::isnat¶

Back to CatalogTimelineAccessor API Reference

Signature¶

Catalog CatalogTimelineAccessor::isnat() const

What It Does¶

Flags whether each bound key’s timestamp is NaT (missing/”Not a Time”), replacing each Timeline- or TimeIndex-kind key with a Bool Series key.

Important

CatalogTimelineAccessor requires every bound key to be Timeline- or TimeIndex-kind Every method on this accessor — not just isnat() — routes through Stream::tl() for each bound key. tl() accepts both Timeline-kind and TimeIndex-kind keys uniformly; if any bound key is neither (Series, Note, Mixed, Null, or Empty), the call throws "Thread::tl: expected Timeline or TimeIndex payload". Since Catalog::tl() binds every key of the catalog by default, project down to just the timestamp keys first with Catalog::keys(names) or Catalog::keyaxis().timeline() before calling .tl().

isnat()’s own result is never itself NaT — it always answers true or false, even for the row it’s flagging.

Parameters¶

None

Returns¶

Catalog A new catalog with every bound key replaced by a Bool Series key: true where the value is NaT, false otherwise.

Examples¶

Example 1. Flag a NaT timestamp alongside a valid one. An empty string passed to pluss::make_timeline produces NaT rather than throwing.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "ts"_k = pluss::kindle::Stream(pluss::make_timeline({"", "2024-01-01T00:00:00Z"})),
});
auto out = ct.tl().isnat();
std::cout << out;

Output¶

kindle::Catalog  keys=1
keys: [ts]
------------------------------------------------------------------------------------------------------------------------
key                      | kind         | dtype            | cs      | preview

Example 2. A non-Timeline/TimeIndex key throws — see the important callout above.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "id"_k = pluss::kindle::Stream(pluss::make_series({1, 2, 3})),
});
try {
  auto out = ct.tl().isnat();
} catch (const pluss::Error& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n'));
}

Output¶

Thread::tl: expected Timeline or TimeIndex payload

Notes¶

  • See the important callout above — this precondition applies to every method on CatalogTimelineAccessor, not only isnat().

  • Unlike almost every other method on this accessor, isnat()’s output is never itself masked — it directly answers the missingness question.

See Also¶

  • CatalogTimelineAccessor::valid: the logical inverse.

  • Catalog::tl: the entry point this accessor is reached from.

  • Catalog::keys: project down to timestamp-only keys before calling .tl(), per the important callout above.

  • RegistryTimelineAccessor::isnat: the bundle-model equivalent, which only accepts Timeline-kind (not TimeIndex).
