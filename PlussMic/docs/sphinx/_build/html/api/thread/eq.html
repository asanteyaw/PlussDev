Thread::eq¶

Back to Thread API Reference

Signatures¶

Thread::eq(double other) const -> Thread
Thread::eq(std::string_view other) const -> Thread
Thread::eq(const char* other) const -> Thread
Thread::eq(const Thread& other) const -> Thread

What It Does¶

Elementwise equality, returning a Bool-typed Series thread. The double overload compares every value against the same scalar; the Thread overload compares two threads positionally (same length required, no case-label alignment); the std::string_view overload (with a const char* convenience wrapper that just forwards to it) behaves differently depending on the calling thread’s kind:

  • On a Note (string) thread, it compares each string directly against other.

  • On any other kind (a numeric Series thread, for example), it stringifies each value first, then does a plain string comparison against other. It does not parse other as a number and compare numerically.

Important

eq() is the canonical comparison-family reference ne, lt, le, gt, and ge all share this exact overload shape and positional-matching rule. Their own pages focus on what’s different about each operator; this page covers the shared mechanics once. See lt() specifically for why the string-overload’s stringify-then-compare behavior matters more for ordering operators than it does for equality.

Parameters¶

other (double, std::string_view, or const Thread&)

The value to compare against. For the Thread overload, must be the same length as *this.

Returns¶

Thread A new Bool-typed thread, same length as *this, holding the elementwise equality result.

Examples¶

Example 1. Compare every value against a scalar.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({72.0, 85.0, 91.0}));
auto out = scores.eq(85.0);
std::cout << out;

Output¶

0  false
1  true
2  false

ptype: Series

Example 2. Compare two threads positionally.

auto targets = Thread(pluss::make_series({72.0, 80.0, 95.0}));
auto out_pair = scores.eq(targets);
std::cout << out_pair;

Output¶

0  true
1  false
2  false

ptype: Series

Only position 0 matches (72 == 72); the others differ (85 != 80, 91 != 95).

Example 3. String equality on a Note thread compares text directly.

auto names = Thread(pluss::make_note({"Ada", "Bola", "Chen"}));
auto out_names = names.eq("Bola");
std::cout << out_names;

Output¶

0  false
1  true
2  false

ptype: Series

Example 4. String equality on a numeric thread stringifies first.

auto values = Thread(pluss::make_series({9.0, 10.0, 11.0}));
auto out_values = values.eq("10");
std::cout << out_values;

Output¶

0  false
1  true
2  false

ptype: Series

10.0 stringifies to "10", which matches the literal "10" — for equality specifically, stringify-then-compare and parse-then-compare-numerically happen to agree here. That’s not true for the ordering operators; see lt() for a case where it matters.

Example 5. A length mismatch throws rather than aligning or padding.

auto too_short = Thread(pluss::make_series({1.0, 2.0}));
try {
  auto bad = scores.eq(too_short);
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

Thread::eq(Thread): positional comparison requires identical lengths

Notes¶

  • The comparison family also accepts Timeline/TimeIndex-kind threads on the Thread overload (comparing timestamps), and Note-vs-Note on the same overload (comparing strings) — this page focuses on the numeric case, which is the most common.

  • Mixing incompatible payload kinds on the Thread overload (for example, a numeric thread against a Note thread) throws "unsupported payload combination".

  • Every method in this family reports its own name in error messages (Thread::eq(Thread), Thread::lt(Thread), and so on), not a shared generic one.

See Also¶

  • Thread::lt, Thread::le, Thread::gt, Thread::ge: the ordering operators, sharing this overload shape but with a real gotcha in the string overload.

  • DataFrame::eq: the multi-feature counterpart.
