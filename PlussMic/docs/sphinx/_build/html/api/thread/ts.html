Thread::ts¶

Back to Thread API Reference

Signature¶

Thread::ts() const -> TimeSeriesAccessor

What It Does¶

Enters the dedicated time-series-numerics accessor for this thread — period-over- period returns, differencing, lag/lead, rolling and expanding windows, exponentially- weighted statistics, gap filling, resampling, and axis-aligned arithmetic, one method per operation. Unlike tl() (which requires Timeline/TimeIndex payloads), ts() requires the thread to already be a numeric Series — cast it first with astype()/cast() if it isn’t.

Unlike DataFrame::ts(), this overload takes no options — there’s no group/anchor concept for a single thread outside a frame, and duration-based methods that need an explicit time axis (like the duration overload of rolling()) simply take that axis as a direct argument instead.

This page previews the accessor’s most common entry points. Every one of its methods has its own dedicated, example-rich reference page — start at the TimeSeriesAccessor API Reference and use its left sidebar to jump straight to any method (lag, diff, rolling, expanding, ewm, and more).

Parameters¶

None

Returns¶

TimeSeriesAccessor A lightweight accessor bound to this (numeric) thread. Every method on it returns a new Thread (or a TimeSeriesResample/DataFrame for the block/resample methods); the source thread is never mutated.

Examples¶

Example 1. Compute a lag and a period-over-period difference on a numeric thread.

using namespace pluss::table;

auto load = Thread(pluss::make_series({10.0, 20.0, 15.0, 30.0}));

auto lagged = load.ts().lag(1);
std::cout << lagged;

Output¶

0  NULL
1  10
2  20
3  15

ptype: Series

.lag(1) is equivalent to shift(1): each position now shows the previous position’s value, with position 0 becoming NULL since it has no predecessor.

auto changes = load.ts().diff(1);
std::cout << changes;

Output¶

0  NULL
1  10
2  -5
3  15

ptype: Series

.diff(1) is load[i] - load[i - 1]: position 1 is 20 - 10 = 10, position 2 is 15 - 20 = -5, position 3 is 30 - 15 = 15; position 0 has no prior position to subtract, so it’s NULL.

Example 2. ts() on a non-numeric thread throws before the accessor’s methods can run.

auto words = Thread(pluss::make_note({"a", "b"}));
try {
  auto bad = words.ts().lag(1);
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

TimeSeriesAccessor::lag: source must be Series

The check happens lazily, on the first method call against the accessor — ts() itself never throws, since it just binds the thread without inspecting it.

Notes¶

  • The source thread must already be a numeric Series; every accessor method throws otherwise (ts() itself doesn’t validate eagerly).

  • .lag(periods) on a numeric thread behaves identically to shift(periods) — both introduce NULL at the vacated end.

  • No options/TsOptions parameter here, unlike DataFrame::ts() — duration-aware methods take their time axis directly as an argument instead.

See Also¶

  • Thread::shift: the lower-level positional shift .ts().lag() is built on, without the time-series-accessor framing.

  • Thread::tl: the equivalent dedicated accessor for calendar/timestamp components on Timeline/TimeIndex payloads, instead of numeric time-series values.

  • Thread::weigh, Thread::bounded: lower-level windowing primitives that some of this accessor’s fixed-width methods are built on top of.
