Thread::has¶

Back to Thread API Reference

Signatures¶

Thread::has(double value) const -> Thread
Thread::has(std::string_view value) const -> Thread
Thread::has(const char* value) const -> Thread
Thread::has(const Thread& values) const -> Thread

What It Does¶

A row-wise membership test — despite the name suggesting a single “does this thread contain X anywhere” answer, has() returns one boolean per row, not one boolean for the whole thread.

The scalar overloads (double, std::string_view, const char*) are a direct alias for eq(): has(value) is exactly eq(value), testing each row against the one value. The Thread-argument overload is the more useful form in practice — it’s an isin style test: row i is true if it equals any value in values, checked by ORing together one has(scalar) call per (valid) entry of values.

Important

has(const Thread&) is per-row “is this value in the candidate set”, not a global “does this thread contain any of these” thread.has(candidates) returns a Thread the same length as thread — row i tells you whether thread’s row i matches one of candidates’ values, not whether candidates appears anywhere in thread as a whole. This is the isin/membership pattern common to most table libraries. Invalid rows in candidates are skipped (never contribute a match).

Parameters¶

value (double / std::string_view / const char*) A single scalar to test every row against — equivalent to eq(value).

values (const Thread&) A set of candidate values (typically a short, Note- or Series-kind thread) — each row of *this is tested against every entry of values, matching if it equals any of them.

Returns¶

Thread A Series-kind thread of Bool values, one membership result per row.

Examples¶

Example 1. Test a numeric thread against one scalar — identical to eq(20.0).

using namespace pluss::table;

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0}));

auto out = scores.has(20.0);
std::cout << out;

Output¶

0  false
1  true
2  false
ptype: Series

Example 2. Test a Note-backed thread against one text scalar.

auto names = Thread(pluss::make_note({"Ada", "Bola", "Chen"}));

auto out = names.has("Bola");
std::cout << out;

Output¶

0  false
1  true
2  false
ptype: Series

Example 3. isin-style membership against a short candidate set of numeric values.

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0, 40.0}));
auto candidates = Thread(pluss::make_series({20.0, 40.0}));

auto out = scores.has(candidates);
std::cout << out;

Output¶

0  false
1  true
2  false
3  true
ptype: Series

Example 4. The same isin-style membership test, with a Note-backed candidate set — useful for allowlist/denylist-style row filtering.

auto names = Thread(pluss::make_note({"Ada", "Bola", "Chen", "Ada"}));
auto allowed = Thread(pluss::make_note({"Ada", "Chen"}));

auto out = names.has(allowed);
std::cout << out;

Output¶

0  true
1  false
2  true
3  true
ptype: Series

Notes¶

  • The scalar overloads are a pure alias for eq() — prefer whichever name reads better at the call site.

  • The Thread-argument overload is the genuinely distinct behavior: a per-row isin test against a candidate set, not a whole-thread containment check.

  • Invalid rows in the values candidate set are skipped and never produce a match; an invalid row in *this is compared normally against each candidate (matching compare()’s general rule that invalid rows just compare false).
