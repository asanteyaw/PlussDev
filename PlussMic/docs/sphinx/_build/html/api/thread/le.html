Thread::le¶

Back to Thread API Reference

Signatures¶

Thread::le(double other) const -> Thread
Thread::le(std::string_view other) const -> Thread
Thread::le(const char* other) const -> Thread
Thread::le(const Thread& other) const -> Thread

What It Does¶

Elementwise “less than or equal”, following eq()’s shared overload shape and positional matching. Like lt(), the string overload stringifies numeric values before comparing — see lt() for why that can disagree with numeric ordering.

Parameters¶

other (double, std::string_view, or const Thread&)

Same shape as eq().

Returns¶

Thread A new Bool-typed thread, same length as *this, holding the elementwise “less than or equal” result.

Examples¶

Example 1. Compare every value against a scalar.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({72.0, 85.0, 91.0}));
auto out = scores.le(85.0);
std::cout << out;

Output¶

0  true
1  true
2  false

ptype: Series

Position 1 is true here (85 <= 85) where lt(85.0) gave false — the only difference between the two operators.

Example 2. Compare two threads positionally.

auto targets = Thread(pluss::make_series({72.0, 80.0, 95.0}));
auto out_pair = scores.le(targets);
std::cout << out_pair;

Output¶

0  true
1  false
2  true

ptype: Series

Example 3. String comparison on a Note thread.

auto names = Thread(pluss::make_note({"Ada", "Bola", "Chen"}));
auto out_names = names.le("Bola");
std::cout << out_names;

Output¶

0  true
1  true
2  false

ptype: Series

"Ada" <= "Bola" and "Bola" <= "Bola" are both true lexicographically; "Chen" <= "Bola" is false.

Notes¶

  • See eq() for the family-wide mechanics.

  • See lt() for the lexicographic-vs-numeric gotcha on the string overload — it applies here too.

See Also¶

  • Thread::lt: the strict form.

  • Thread::ge: the opposite direction’s inclusive form.
