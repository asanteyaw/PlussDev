Thread::align¶

Back to Thread API Reference

Signature¶

Thread::align(const Thread& target_labels, const AlignOptions& options = {}) const -> Thread

What It Does¶

Realigns one thread’s values to a target label order — the typed, single-column alignment surface behind many higher-level DataFrame operations. Use it when you’re working with one extracted column directly and need to reorder or relabel it against another label vector before comparison, arithmetic, export, or manual reconstruction.

enum class AlignBy : std::uint8_t {
  Pos = 0,      // strict positional alignment — no label-based remapping
  Caselbl = 1,  // gather by case label
  Feature = 2,  // gather by feature label
  Both = 3,     // DataFrame-only; rejected for Thread
};

struct AlignOptions {
  AlignBy align{AlignBy::Pos};
  std::optional<double> fill{std::nullopt};
};

target_labels’ interpretation depends entirely on options.align: under Caselbl, it’s the desired case-axis order; under Feature, the desired feature-label order; under Pos (the default), it’s only checked for length compatibility — no label matching happens at all, and the thread’s own current values and visible labels pass through unchanged.

Important

Unmatched target labels become NULL unless fill is set Under Caselbl/Feature alignment, a target_labels entry with no corresponding source label produces a NULL row in the output — not a thrown error. Set options.fill to a numeric scalar if you’d rather those gaps came back filled instead. See Examples 1 and 2.

Parameters¶

target_labels (const Thread&) The target label vector defining the output order — typically a Note-kind thread of label strings (a bare pluss::Note also works, thanks to Thread’s implicit constructor from Note). Under AlignBy::Pos, only its length matters.

options (const AlignOptions&) align selects the matching rule (see above); fill, if set, supplies a numeric scalar for target labels that have no match in the source thread. AlignBy::Both is rejected — it’s a DataFrame-only concept (aligning both the case axis and the feature axis at once), which has no meaning for a single Thread.

Returns¶

Thread A new thread reordered/relabeled per options.align, the same length as target_labels.

Examples¶

Example 1. Align by case label, leaving an unmatched target label NULL.

using namespace pluss::table;

auto labeled = Thread(pluss::make_series({10.0, 20.0, 30.0}))
                   .label().set(pluss::make_note({"b", "a", "c"}));

auto out = labeled.align(
    pluss::make_note({"a", "b", "d"}),
    AlignOptions{.align = AlignBy::Caselbl}
);
std::cout << out;

Output¶

a  20
b  10
d  NULL
ptype: Series

Example 2. The same case-label alignment, now with fill supplying a value for the unmatched "d" label instead of leaving it NULL.

auto labeled = Thread(pluss::make_series({10.0, 20.0, 30.0}))
                   .label().set(pluss::make_note({"b", "a", "c"}));

auto out = labeled.align(
    pluss::make_note({"a", "b", "d"}),
    AlignOptions{.align = AlignBy::Caselbl, .fill = 0.0}
);
std::cout << out;

Output¶

a  20
b  10
d  0
ptype: Series

Example 3. Align a one-value-per-feature thread by feature label — useful when a thread represents, e.g., one aggregate per column and you need it in a specific column order.

auto feature_thread = Thread(pluss::make_series({1.5, 2.5}))
                          .label().set(pluss::make_note({"A2", "A1"}));

auto out = feature_thread.align(
    pluss::make_note({"A1", "A2"}),
    AlignOptions{.align = AlignBy::Feature}
);
std::cout << out;

Output¶

A1  2.5
A2  1.5
ptype: Series

Example 4. AlignBy::Pos performs no label-based remapping at all — it only validates length compatibility, and the thread’s own values and visible labels pass through unchanged even though target_labels here holds entirely different label text.

auto labeled = Thread(pluss::make_series({10.0, 20.0, 30.0}))
                   .label().set(pluss::make_note({"b", "a", "c"}));

auto out = labeled.align(
    pluss::make_note({"x", "y", "z"}),
    AlignOptions{.align = AlignBy::Pos}
);
std::cout << out;

Output¶

b  10
a  20
c  30
ptype: Series

Example 5. AlignBy::Both is a DataFrame-only concept and throws when requested on a Thread.

auto thread = Thread(pluss::make_series({10.0, 20.0, 30.0}));
try {
  auto out = thread.align(pluss::make_note({"a", "b", "c"}), AlignOptions{.align = AlignBy::Both});
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::align: AlignBy::Both is only valid for DataFrame-to-DataFrame alignment

Notes¶

  • AlignBy::Both is rejected on Thread — see Example 5. It only makes sense for DataFrame::align, which can align both axes (case and feature) simultaneously.

  • Unmatched target labels become NULL unless options.fill is set — see the important callout above.

  • AlignBy::Pos does not broadcast or remap by label at all; it expects a compatible length and preserves the thread’s current value order and visible labels untouched.

See Also¶

  • DataFrame::align: frame-level alignment for several features at once, including the Both-axis mode this method rejects.

  • Thread::label: use label().set(...) to attach explicit case/feature labels before aligning by label, as every example above does.
