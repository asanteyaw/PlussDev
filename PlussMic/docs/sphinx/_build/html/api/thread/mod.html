Thread::mod¶

Back to Thread API Reference

Signatures¶

Thread::mod(double other) const -> Thread
Thread::mod(const Thread& other) const -> Thread

What It Does¶

Elementwise remainder — the complement to floordiv(): for each position, divisor * floordiv_result + mod_result reconstructs the original dividend. Follows add()’s shared mechanics (positional matching, length-mismatch throw, no Note-payload support).

Important

Negative operands are deliberately not covered mod() delegates to the underlying Series library’s own remainder() primitive, which is not implemented in this repository — its exact sign convention for negative dividends or divisors can’t be verified here. Every example on this page uses positive operands only, where the convention is unambiguous.

Parameters¶

other (double or const Thread&)

The divisor(s). For the Thread overload, must be the same length as *this.

Returns¶

Thread A new thread, same length as *this, holding the elementwise remainder.

Examples¶

Example 1. Remainder against a scalar divisor.

using namespace pluss::table;

auto amounts = Thread(pluss::make_series({17.0, 26.0, 33.0}));
auto out = amounts.mod(5.0);
std::cout << out;

Output¶

0  2
1  1
2  3
ptype: Series

17 = 5*3 + 2, 26 = 5*5 + 1, 33 = 5*6 + 3 — matching amounts.floordiv(5.0)’s 3, 5, 6 from the same dividends.

Example 2. Remainder against another thread, positionally.

auto divisors = Thread(pluss::make_series({4.0, 7.0, 9.0}));
auto out_pair = amounts.mod(divisors);
std::cout << out_pair;

Output¶

0  1
1  5
2  6
ptype: Series

17 = 4*4 + 1, 26 = 7*3 + 5, 33 = 9*3 + 6.

Notes¶

  • See add() for the family-wide mechanics: positional matching and the length-mismatch throw.

  • See floordiv() for the complementary quotient — the two methods are computed independently (not derived from each other), but always satisfy divisor * floordiv_result + mod_result == dividend for the positive operands shown here.
