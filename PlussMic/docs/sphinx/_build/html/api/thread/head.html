Thread::head¶

Back to Thread API Reference

Signature¶

Thread::head(std::int64_t n = 5, bool render = false) const -> ThreadView

What It Does¶

Returns the first n entries of the thread as a ThreadView — a Thread subclass (it inherits every Thread method and renders identically via operator<<) that additionally carries a display title ("head") and an opt-in auto-render behavior for interactive/terminal contexts. n is silently clamped into [0, size()] — head() never throws for an out-of-range n, the same convention top()/bottom() use.

Note

ThreadView is a Thread Every method documented elsewhere in this reference — arithmetic, string ops, reductions, everything — works directly on the ThreadView returned here, since it publicly inherits from Thread. The ThreadView wrapper only adds a couple of show() overloads and a distinct stream-insertion operator (which renders exactly like Thread’s own).

Parameters¶

n (std::int64_t, default 5) Number of leading entries to keep. Values below 0 clamp to 0; values above size() clamp to size() — no error either way.

render (bool, default false) When true, the returned view may auto-render itself if it reaches the end of its scope without being explicitly printed (a convenience for interactive/REPL contexts). Has no effect on what an explicit std::cout << ... prints, which is what every example on this page uses.

Returns¶

ThreadView A view over the first n entries (or every entry, if n >= size()).

Examples¶

Example 1. The default n = 5 on a shorter thread returns everything.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0}));
auto out = scores.head(2);
std::cout << out;

Output¶

0  10
1  20

ptype: Series

Example 2. n larger than size() clamps — no error, just the whole thread back.

auto out2 = scores.head(100);
std::cout << out2;

Output¶

0  10
1  20
2  30

ptype: Series

Notes¶

  • n is clamped into [0, size()], never throws.

  • The returned ThreadView is a full Thread — chain any other method directly on it.

  • render only affects auto-render-on-scope-exit behavior in interactive contexts, not what an explicit stream insertion prints.

See Also¶

  • Thread::tail: the trailing-entries counterpart.

  • Thread::view: an arbitrary [start, stop) window, not anchored to either end.

  • Thread::top / Thread::bottom: value-sorted previews, rather than positional ones.
