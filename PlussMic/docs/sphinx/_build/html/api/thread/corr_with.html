Thread::corr_with¶

Back to Thread API Reference

Signature¶

Thread::corr_with(const Thread& other, ThreadCorrMethod method = ThreadCorrMethod::Pearson, std::int64_t min_count = 1) const -> ThreadValue

What It Does¶

Computes the same correlation corr() does, but returns it as a scalar ThreadValue gated by min_count instead of a raw double — below min_count valid pairs, the result is marked invalid rather than returning NaN as a plain, unflagged value. Both threads must be numeric Series; case labels align the pairing exactly as they do for corr().

Note

invalid whenever the underlying correlation isn’t finite Beyond the min_count gate, the result is also marked invalid whenever the underlying corr() computation itself doesn’t come out to a finite number — for example, zero variance on either side (every observed value tied, under any of Pearson/Spearman/KendallTau) produces a NaN correlation, and that NaN is caught and reflected in .thread().notnull() rather than silently passing through as a “valid” result. You never need to separately guard against a NaN hiding behind a true validity flag — check the scalar validity mask and trust it.

Parameters¶

other (const Thread&) The numeric Series thread to correlate with.

method (ThreadCorrMethod, default Pearson) Pearson, Spearman, or KendallTau — same semantics as corr().

min_count (std::int64_t, default 1) The smallest number of valid pairs still considered valid. Must be >=     1, or it throws.

Returns¶

ThreadValue A scalar Float64 (or Float32 off-CPU) holding the correlation coefficient.

Examples¶

Example 1. Same computation as corr(), wrapped as a ThreadValue.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0, 40.0}));
auto other = Thread(pluss::make_series({10.0, 10.0, 35.0, 45.0}));
auto out = scores.corr_with(other, ThreadCorrMethod::Pearson, 1);
std::cout << out.to_dbl();

Output¶

0.943119

Example 2. Below min_count valid pairs, the result is marked invalid.

auto small = Thread(pluss::make_series({1.0, 2.0}));
auto small_other = Thread(pluss::make_series({3.0, 4.0}));
auto out2 = small.corr_with(small_other, ThreadCorrMethod::Pearson, 5);
std::cout << out2.thread().notnull().as_series().to_vec<bool>()[0];

Output¶

false

Example 3. Zero variance on the Pearson path is caught by the validity check — the scalar validity mask is false, not just a NaN value hiding behind true.

auto constant = Thread(pluss::make_series({5.0, 5.0, 5.0}));
auto varying = Thread(pluss::make_series({1.0, 2.0, 3.0}));
auto out3 = constant.corr_with(varying, ThreadCorrMethod::Pearson, 1);
std::cout << out3.thread().notnull().as_series().to_vec<bool>()[0];

Output¶

false

Example 4. The same zero-variance case under KendallTau — the underlying rank correlation is NaN (every rank on the constant side ties), and that’s caught too, not just the Pearson path.

auto out4 = constant.corr_with(varying, ThreadCorrMethod::KendallTau, 1);
std::cout << out4.thread().notnull().as_series().to_vec<bool>()[0];

Output¶

false

Notes¶

  • min_count must be >= 1, or it throws "Thread::corr_with: min_count must be >= 1".

  • Case-label alignment applies exactly as it does for corr().

  • See the important callout above: validity covers both the min_count gate and whether the underlying correlation itself came out finite, across all three methods.

  • Both threads must already share the same platform, or it throws "Thread::corr_with: operands must share a platform".

  • Restricted to numeric Series payloads; anything else throws "Thread::corr_with: expected a real numeric Series Thread".

See Also¶

  • Thread::corr: the same computation, returned as a raw double with NaN on failure instead of a validity-gated ThreadValue.

  • Thread::covar: the unnormalized counterpart.
