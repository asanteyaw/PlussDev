Thread::flow¶

Back to Thread API Reference

Signature¶

Thread::flow(const std::function<Thread(const Thread&)>& fn) const -> Thread

What It Does¶

Calls fn exactly once, passing the entire current thread, and returns exactly what fn returns — with no size or shape validation at all. It’s the least restrictive of the whole-thread functional escape hatches: fold() does the same single call but checks the result’s size against a ResultShape; flow() skips that check entirely and only confirms the callback isn’t empty and that it returned a defined Thread.

Reach for flow() when you want to drop into a pipeline stage that changes row count arbitrarily (filtering, expanding, reducing) and don’t want a shape check getting in the way; reach for fold() instead when you want that check as a lightweight assertion on your own transform’s contract.

Important

No size validation whatsoever — unlike fold() flow()’s callback can return a Thread of any length, including a different length than the input. This is the key difference from fold(), which validates the result size against its shape parameter. If you want that safety net, use fold() instead.

Parameters¶

fn (const std::function<Thread(const Thread&)>&) Called exactly once with *this. Must return a defined Thread of any length; must not be empty.

Returns¶

Thread Exactly what fn returned, unmodified.

Examples¶

Example 1. Reduce the whole thread to a single summary value — flow() places no restriction on the result’s length, so this “changes shape” without issue.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0}));

auto out = scores.flow([](const Thread& t) {
  return Thread(pluss::make_series({t.sum().to_dbl()}));
});
std::cout << out;

Output¶

0  60
ptype: Series

Example 2. Return a result with a different row count than the input — something fold()’s Reduce/Preserve shapes would reject, but flow() accepts without complaint.

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0}));

auto out = scores.flow([](const Thread& t) {
  return Thread(pluss::make_series({1.0, 2.0}));
});
std::cout << out;

Output¶

0  1
1  2
ptype: Series

Example 3. An empty callback throws immediately.

auto thread = Thread(pluss::make_series({10.0, 20.0, 30.0}));
try {
  std::function<Thread(const Thread&)> empty_fn;
  auto out = thread.flow(empty_fn);
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::flow: callback is empty

Example 4. Returning a default-constructed (undefined) Thread throws.

auto thread = Thread(pluss::make_series({10.0, 20.0, 30.0}));
try {
  auto out = thread.flow([](const Thread& t) {
    return Thread{};
  });
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::flow: callback returned an undefined Thread

Notes¶

  • fn is called exactly once, with the whole thread — not once per row. Use map() for genuine row-by-row iteration.

  • No size or shape validation on the result — this is the one real difference from fold(). Use fold() instead if you want that check.

  • The only two failure modes are an empty callback and a callback that returns an undefined Thread — anything else, at any length, passes through.

See Also¶

  • Thread::fold: the same “call fn once with the whole thread” shape, plus a ResultShape size check on the result.

  • Thread::map: the row-by-row counterpart — calls fn once per valid row instead of once for the whole thread.

  • Thread::transform: the dispatcher that forwards to map() or fold() depending on which overload you call — flow() is not one of its targets.
