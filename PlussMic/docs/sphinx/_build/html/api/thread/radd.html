Thread::radd¶

Back to Thread API Reference

Signatures¶

Thread::radd(double other) const -> Thread
Thread::radd(const Thread& other) const -> Thread

What It Does¶

The reflected form of add(). For numbers, addition is commutative, so radd() and add() produce identical results in every observable way. The distinction only matters for Note (string) threads, where add() means concatenation and concatenation order depends on which operand comes first — radd() reverses that order.

Parameters¶

other (double or const Thread&)

Same shape as add().

Returns¶

Thread For numbers, identical to what add() would produce for the same arguments. For two Note threads, the concatenation with the operand order reversed.

Examples¶

Example 1. For a scalar, radd() and add() agree exactly.

using namespace pluss::table;

auto prices = Thread(pluss::make_series({10.0, 20.0, 30.0}));
auto out = prices.radd(5.0);
std::cout << out;

Output¶

0  15
1  25
2  35

ptype: Series

Same values as prices.add(5.0) — addition doesn’t care about order.

Example 2. For Note threads, radd() concatenates in the opposite order from add().

auto prefix = Thread(pluss::make_note({"north-", "south-", "east-"}));
auto base_name = Thread(pluss::make_note({"store", "hub", "depot"}));

auto forward = prefix.add(base_name);
auto reflected = prefix.radd(base_name);
std::cout << forward << "\n" << reflected;

Output¶

0  north-store
1  south-hub
2  east-depot

ptype: Note
0  storenorth-
1  hubsouth-
2  depoteast-

ptype: Note

prefix.add(base_name) puts prefix’s text first at each position; prefix.radd(base_name) is equivalent to base_name.add(prefix) — base_name’s text comes first instead.

Notes¶

  • For numeric threads, radd() exists purely for API symmetry with the rest of the reflected family (rsub, rmul, and so on) — there is no behavioral reason to prefer it over add().

  • See add() for the shared mechanics every arithmetic method in this family follows: positional matching, the length-mismatch throw, and the Note-concatenation special case.

See Also¶

  • Thread::add: the forward form, and the canonical reference for this whole arithmetic family’s shared mechanics.
