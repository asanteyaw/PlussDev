Thread::tl¶

Back to Thread API Reference

Signature¶

Thread::tl() const -> ThreadTimelineAccessor

What It Does¶

Enters the dedicated timestamp accessor for this thread — calendar-component extraction (year, month, weekday, …), formatting, timezone conversion, flooring/ceiling/rounding to a unit, spans between two timestamps, and more, one method per operation. Unlike nt(), tl() validates eagerly: the thread must already be defined and must already be Timeline- or TimeIndex-kind, or the .tl() call itself throws immediately, before any accessor method runs.

Unlike DataFrame::tl(), this accessor is bound to a single thread — there’s no equivalent of .features(...) narrowing to do first.

This page previews the accessor’s most common entry points. Every one of its methods has its own dedicated, example-rich reference page — start at the ThreadTimelineAccessor API Reference and use its left sidebar to jump straight to any method (year, month, fmt, floor, tz, span, and more).

Parameters¶

None

Returns¶

ThreadTimelineAccessor A lightweight accessor bound to this (already-validated) Timeline/TimeIndex thread. Nearly every method on it returns a new Thread; the source thread is never mutated.

Examples¶

Example 1. Pull calendar components off a Timeline thread.

using namespace pluss::table;

auto dates = Thread(pluss::make_timeline({
    "2024-01-15T00:00:00Z",
    "2024-06-30T00:00:00Z",
    "2024-12-25T00:00:00Z",
}));

auto years = dates.tl().year();
std::cout << years;

Output¶

0  2024
1  2024
2  2024

ptype: Series

auto weekdays = dates.tl().weekday_name();
std::cout << weekdays;

Output¶

0  Monday
1  Sunday
2  Wednesday

ptype: Note

.year() returns an Int64 Series-kind thread; .weekday_name() returns a Note-kind thread of full weekday names.

Example 2. tl() throws immediately on a non-Timeline/TimeIndex thread — unlike nt(), the check happens at the .tl() call itself, not on first method use.

auto numbers = Thread(pluss::make_series({10.0, 20.0, 30.0}));
try {
  auto bad = numbers.tl();
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::tl: expected Timeline or TimeIndex payload

Notes¶

  • tl() validates eagerly: the thread must be defined and must already be Timeline- or TimeIndex-kind, or .tl() itself throws ("Thread::tl: Thread is undefined" / "Thread::tl: expected Timeline or TimeIndex payload") before any accessor method runs.

  • Compare nt(), whose Note-kind check is lazy (deferred to the first method call on the accessor) rather than eager.

  • No options/narrowing step is needed before calling .tl(), unlike DataFrame::tl() — a Thread is already a single payload.

See Also¶

  • Thread::nt: the equivalent dedicated accessor for Note text payloads, which validates its payload kind lazily instead of eagerly.

  • Thread::label: the dedicated accessor for the case-label axis, which works regardless of the thread’s own payload kind.

  • DataFrame::tl: the frame-level equivalent, which requires every selected feature to already be Timeline/TimeIndex-kind.
