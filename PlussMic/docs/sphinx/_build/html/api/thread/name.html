Thread::name¶

Back to Thread API Reference

Signatures¶

Thread::name() const -> std::string
Thread::name(std::string value) const -> Thread

What It Does¶

Two overloads, chosen by whether an argument is passed: the zero-argument form is a getter that reads the thread’s currently attached name; the one-argument form is a setter that returns a new thread with a name attached, leaving the original unmodified. This name is presentation metadata used for labeling and identification (for example, ThreadPlotAccessor’s chart methods use it to label axes and legends when wrapping a Thread into a chart) — it is not schema truth the way a DataFrame feature name is, and it never affects the thread’s own values.

Important

The getter throws if no name is set — check named() first Unlike many “get the current X” accessors that return a default or empty value when nothing has been set, name() (the getter) throws "Thread::name: name is not set" if the thread has no name attached. Always check named() first (or catch the exception) before calling the getter on a thread that might be unnamed.

Parameters¶

value (std::string, setter overload only) The name to attach. Must be non-empty — passing an empty string throws "Thread::name(value): name must not be empty".

Returns¶

For the getter: std::string The thread’s currently attached name.

For the setter: Thread A new thread with value attached as its name; the values and any other metadata (validity mask, row labels) are carried over unchanged.

Examples¶

Example 1. Attach a name, then read it back.

using namespace pluss::table;

auto balance = Thread(pluss::make_series({100.0, 250.5, 75.25}));
auto named_balance = balance.name("balance");

std::cout << named_balance.name();

Output¶

balance

balance itself is left unmodified — name(...) is non-mutating, so named_balance is a distinct copy carrying the new name.

Example 2. Calling the getter on an unnamed thread throws.

try {
  auto bad = balance.name();
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::name: name is not set

balance (the original, still unnamed) throws because no name was ever attached to it — see named() for how to check first.

Example 3. An empty name throws immediately.

try {
  auto bad = balance.name("");
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::name(value): name must not be empty

Notes¶

  • The getter throws "Thread::name: name is not set" on an unnamed thread — check named() first, or catch the exception.

  • The setter throws "Thread::name(value): name must not be empty" on an empty string.

  • Both overloads are non-mutating; the setter always returns a new Thread.

  • This is presentation metadata, not schema — it never affects the thread’s own values or comparisons between threads.

See Also¶

  • Thread::named: check whether a name is attached without risking the getter’s throw.

  • Thread::unname: remove an attached name.

  • Thread::plot: chart methods use a thread’s name to label axes and legends when one is set.
