Thread::invalid¶

Back to Thread API Reference

Signature¶

Thread::invalid() const -> Thread

What It Does¶

Returns a Bool-typed Series thread, same length as *this, marking true wherever a cell should be treated as unusable data. The exact meaning depends on payload kind:

  • Series-kind: true for NULL, NaN, or ±Inf — the union of isnull() and the logical negation of isfinite(). This is a strictly broader check than isnull() alone.

  • Every other kind (Note, Timeline, TimeIndex): invalid() is exactly isnull() — there’s no separate “not finite” concept for text or temporal payloads, so the two checks coincide.

Important

invalid() is not isfinite()’s exact opposite for masked cells For Series-kind threads, invalid() and isfinite() are close to opposites but computed slightly differently under the hood — invalid() is built as “not finite, or explicitly null,” which lands on the same result as !isfinite() for every practical case, but the two are documented separately here because they’re implemented via genuinely different code paths, not simply negated from one another.

Parameters¶

None

Returns¶

Thread A new Bool-typed Series thread, same length as *this.

Examples¶

Example 1. On a Series-kind thread, invalid() catches NULL, NaN, and Inf alike.

using namespace pluss::table;

auto readings = Thread(
    pluss::make_series({1.0, std::nan(""), std::numeric_limits<double>::infinity(), 4.0}),
    pluss::make_series(std::vector<bool>{true, true, true, false}));
std::cout << readings.invalid();

Output¶

0  false
1  true
2  true
3  true

ptype: Series

Every one of positions 1 through 3 is flagged true: NaN, Inf, and masked-NULL are all “invalid” together — a strictly broader net than isnull() alone would catch (which would only flag position 3).

Example 2. On a Note-kind thread, invalid() is exactly isnull().

auto names = Thread(pluss::make_note({"Ada", "Bola", "Chen"}),
    pluss::make_series(std::vector<bool>{true, false, true}));
std::cout << names.invalid() << "\n";
std::cout << names.isnull();

Output¶

0  false
1  true
2  false

ptype: Series
0  false
1  true
2  false

ptype: Series

Notes¶

  • For Series-kind threads, invalid() is strictly broader than isnull() — it also catches NaN and ±Inf.

  • For every other kind, invalid() and isnull() produce identical results.

  • Always returns a Bool-typed Series thread, regardless of the source thread’s own kind.

See Also¶

  • Thread::isnull: the narrower, validity-mask-only check this method extends for Series-kind threads.

  • Thread::isfinite: the near-opposite numeric check.

  • Thread::dropnull: remove rows rather than just flagging them.
