Thread::matmul¶

Back to Thread API Reference

Signature¶

Thread::matmul(const Thread& other) const -> ThreadValue

What It Does¶

Computes the dot product of two numeric threads — sum(this[i] * other[i]) over every row — and returns it wrapped in a ThreadValue rather than a full Thread. Both operands must be numeric Series-kind threads; every other payload kind is rejected.

Important

matmul() tolerates no NULL values at all, including ones introduced by alignment Unlike most arithmetic on Thread (which quietly skips or propagates NULL rows), matmul() refuses to run if either operand has any NULL at all — whether those NULLs were already present, or introduced because the two threads don’t line up one-to-one (for example, mismatched lengths with no shared case labels to align by). Either situation produces the same throw. See Examples 3 and 4.

Parameters¶

other (const Thread&) The right-hand numeric thread to dot with *this. Must be numeric Series-kind, with no NULL values, and must line up one-to-one with *this (matching length, or matching case labels if both threads carry them).

Returns¶

ThreadValue A single-value wrapper holding the dot-product result. Extract it with .to_dbl() (or the other ThreadValue accessors) rather than treating it like a multi-row Thread.

Examples¶

Example 1. Dot product of two equal-length numeric threads — read the scalar out with .to_dbl().

using namespace pluss::table;

auto a = Thread(pluss::make_series({10.0, 20.0, 30.0}));
auto b = Thread(pluss::make_series({15.0, 10.0, 35.0}));

auto out = a.matmul(b);
std::cout << out.to_dbl();

Output¶

1400

10*15 + 20*10 + 30*35 = 150 + 200 + 1050 = 1400.

Example 2. ThreadValue’s own operator<< prints the raw underlying Series debug representation, not the friendly row-indexed rendering Thread uses — prefer .to_dbl() (as in Example 1) when you just want the number.

auto a = Thread(pluss::make_series({10.0, 20.0, 30.0}));
auto b = Thread(pluss::make_series({15.0, 10.0, 35.0}));

auto out = a.matmul(b);
std::cout << out;

Output¶

pluss::Series(shape=[1], strides=[1], dtype=float64, platform=cpu, numel=1, contiguous=true)
data=[1400]

Example 3. Calling matmul() on a non-numeric thread throws.

auto notes = Thread(pluss::make_note({"a", "b"}));
auto numbers = Thread(pluss::make_series({1.0, 2.0}));
try {
  auto out = notes.matmul(numbers);
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::matmul: expected a real numeric Series Thread

Example 4. Mismatched lengths (with no shared case labels to align by) also throw — the message is the same NULL-rejection message as an explicit NULL, since the two threads can’t be lined up one-to-one without introducing a gap.

auto a = Thread(pluss::make_series({1.0, 2.0}));
auto b = Thread(pluss::make_series({1.0, 2.0, 3.0}));
try {
  auto out = a.matmul(b);
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Thread::matmul: null values are not supported

Notes¶

  • Requires both operands to be numeric Series-kind; throws otherwise.

  • No tolerance for NULL in either operand — including NULLs introduced implicitly by a failed one-to-one alignment. See the important callout above.

  • Returns ThreadValue, not Thread — extract the scalar with .to_dbl() rather than printing the ThreadValue directly (Example 2 shows why).

See Also¶

  • Thread::sum: the reduction matmul()’s dot product is built from conceptually ((a * b).sum()), for when you don’t need the elementwise product retained.

  • Thread::mul: elementwise multiplication, if you want the per-row products instead of their sum.
