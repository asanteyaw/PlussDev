Thread::dtype¶

Back to Thread API Reference

Signature¶

Thread::dtype() const -> std::string

What It Does¶

Returns the concrete dtype name of the underlying payload — one level more specific than ptype()’s broad family name. For a Series-kind thread this is the scalar type’s own name ("float64", "bool", "int64", and so on); for Note it’s "utf8" (or "bytes", for byte-string payloads); for Timeline/TimeIndex it’s "datetime64[ns, <tz>]", including the timezone.

Parameters¶

None

Returns¶

std::string The concrete dtype name, formatted per payload kind as described above.

Examples¶

Example 1. dtype() across the payload kinds — note how it differs from ptype(), which would report "Series" / "Note" / "Timeline" for the same threads.

using namespace pluss::table;

auto numeric = Thread(pluss::make_series({10.0, 20.0, 30.0}));
auto text = Thread(pluss::make_note({"a", "b"}));
auto dates = Thread(pluss::make_timeline({"2024-01-01T00:00:00Z"}));

std::cout << numeric.dtype() << "\n";
std::cout << text.dtype() << "\n";
std::cout << dates.dtype();

Output¶

float64
utf8
datetime64[ns, UTC]

dates was built from a UTC-suffixed (Z) timestamp string, so its Timeline carries the UTC timezone — dtype() includes it directly in the string, unlike ptype(), which would just say "Timeline" regardless of timezone.

Notes¶

  • Series-kind threads report their scalar type by name ("float64", "bool", "int64", etc.) — the same names DataFrame::dtypes() reports per feature.

  • Note-kind threads report "utf8" (or "bytes" for a byte-string payload).

  • Timeline/TimeIndex-kind threads report "datetime64[ns, <tz>]", including the timezone.

  • Calling dtype() on an undefined thread throws "Thread: undefined handle".

See Also¶

  • Thread::ptype: the broader payload family, without concrete storage detail.

  • DataFrame::dtypes: the same concrete-dtype summary across every feature of an entire frame.
