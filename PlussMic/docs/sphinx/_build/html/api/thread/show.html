Thread::show¶

Back to Thread API Reference

Signatures¶

Thread::show(const display::DisplayOptions& options = {}) const -> void
Thread::show(std::ostream& os, const display::DisplayOptions& options = {}) const -> void

What It Does¶

Renders the thread’s row values — the same rendering operator<< and to_string() use — as a side effect, rather than returning it. The two overloads behave differently in one important way, not just “default stream vs. explicit stream”:

  • show(os, options) always prints plain text straight to os, exactly like os << thread.

  • show(options) (no stream argument) first checks whether a GUI backend is available and configured. If one is, it opens an interactive viewer window instead of printing to std::cout; only if no GUI backend is available does it fall back to printing to std::cout.

Important

show() with no stream argument may open a GUI window instead of printing On a machine with a GUI session available (a typical desktop dev environment), calling thread.show() with no arguments and default options can resolve to a native or web-based viewer window rather than writing to std::cout — and can block waiting for that window. If you want guaranteed plain-text output to the console, either pass std::cout explicitly (thread.show(std::cout)) or use to_string()/operator<<, neither of which ever opens a GUI window.

Parameters¶

options (const display::DisplayOptions&, optional) Rendering options — see to_string() for which fields actually affect Thread output, plus backend (Auto/Terminal/NativeWebView/PlussWebView), which only matters for the no-stream overload’s GUI-vs-terminal decision.

os (std::ostream&, show(os, options) overload only) The destination stream. Always renders plain text here — this overload never opens a GUI window.

Returns¶

void Renders as a side effect; produces no return value.

Examples¶

Example 1. show(os) with an explicit stream always prints plain text — safe to use anywhere, including scripts and tests.

using namespace pluss::table;

auto scores = Thread(pluss::make_series({10.0, 20.0, 30.0}));

scores.show(std::cout);

Output¶

0  10
1  20
2  30
ptype: Series

Example 2. Passing DisplayOptions alongside an explicit stream still renders plain text — only the no-stream overload considers opening a GUI window.

display::DisplayOptions options;
options.terminal_height = 12;

std::vector<double> values;
for (int i = 0; i < 30; ++i) {
  values.push_back(static_cast<double>(i));
}
auto series = Thread(pluss::make_series(values));

series.show(std::cout, options);

Output¶

  0  0
  1  1
  2  2
  3  3
  4  4
...  ...
 27  27
 28  28
 29  29
ptype: Series

Notes¶

  • show(os, options) is equivalent to os << thread (plus whichever options you pass) — always plain text, never a GUI window.

  • show(options) (no stream) may open a GUI viewer window instead of printing, depending on the runtime environment — see the important callout above. Pass std::cout explicitly if you always want plain text.

  • Shares its rendering (and the same “row-index column and ptype: footer are always present for Thread” behavior) with to_string() — see that page for which DisplayOptions fields matter.

See Also¶

  • Thread::to_string: render to a std::string instead of a stream — never opens a GUI window, and documents which DisplayOptions fields actually affect Thread rendering.

  • Thread::info / Thread::info_string: render metadata (name, kind, dtype, null counts) instead of row values.
