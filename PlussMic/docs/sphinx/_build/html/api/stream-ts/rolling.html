What It Does¶

Computes a trailing rolling window statistic over the bound stream, in one of three shapes:

  • Fixed row count (first overload): each position’s window is the window positions ending at (and including) that position. The very first window - 1 positions use whatever’s available rather than waiting for a full window.

  • Calendar duration (second overload): the same trailing-window idea, but each position’s window spans a fixed span of time (like "2D") looked up against an explicit time axis, rather than a fixed row count. axis must be Timeline or TimeIndex, the same length as the bound stream, non-missing, and sorted ascending.

  • Calendar duration, grouped (third overload): the same calendar-duration window, but restarted independently within each distinct value of groups — a position’s window never crosses a group boundary.

Important

StreamTimeSeriesAccessor requires the bound stream to be numeric Series-kind Same precondition as every method on this accessor — see Stream::ts’s own important callout for the exact throw message pattern.

Important

A larger surface than CatalogTimeSeriesAccessor::rolling Catalog::ts().rolling() only has the first (fixed-window) overload — a multi-key catalog has no single unambiguous time axis to key the calendar-duration overloads off of implicitly. See CatalogTimeSeriesAccessor::rolling’s own important callout for the reverse view.

Parameters¶

window (std::int64_t, fixed-window overload) The trailing window size, in positions. Must be positive, or it throws.

statistic (pluss::table::WindowStatistic, default Mean) The statistic computed over each window: Sum, Mean, Minimum, Maximum, Var, Std, Sem, Skew, or Kurtosis.

options (const pluss::table::WindowOptions&, fixed-window overload) min_count (default 1), ddof (default 1), centered (default false), closure (default Right) — same meaning as CatalogTimeSeriesAccessor::rolling.

axis (const Stream&, calendar-duration overloads) An explicit time axis (Timeline or TimeIndex), the same length as the bound stream, non-missing and sorted ascending.

groups (const Stream&, third overload) The grouping key, one entry per position, same length as the bound stream. Any stream kind; compared by value.

duration (std::string_view, calendar-duration overloads) A duration string (for example "2D", "12H", "30min").

options (const pluss::table::StatisticOptions&, calendar-duration overloads) ddof and min_count; only Sum, Mean, Var, and Std are supported for these overloads.

closure (pluss::table::WindowClosure, calendar-duration overloads, default Right) Which end of the time window is inclusive.

Returns¶

Stream A new stream, same length as the bound source, holding the rolling statistic at each position.

Examples¶

Example 1. A fixed-size trailing rolling mean, including its partial windows.

auto stream = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 15.0, 30.0}));
auto out = stream.ts().rolling(2);
std::cout << out;

Example 2. The calendar-duration overload, keying off an explicit Timeline axis instead of a fixed row count.

auto stream = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 15.0, 30.0}));
auto axis = pluss::kindle::Stream(pluss::make_timeline({
    "2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z",
    "2024-01-04T00:00:00Z", "2024-01-07T00:00:00Z"}));
auto out = stream.ts().rolling(axis, "3D");
std::cout << out;

========================================================================================================================
kindle::Stream  kind=Series  dtype=Series[float64]  records=4
label=no  mask=yes  meta=0
------------------------------------------------------------------------------------------------------------------------
label        | value

Position 3’s (Jan 7) 3-day window only reaches back to Jan 4, so its window is just itself — 30.

Example 3. The grouped calendar-duration overload restarts the window at each group boundary. The output’s row labels are the axis’s own timestamps.

auto stream = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 30.0, 40.0}));
auto axis = pluss::kindle::Stream(pluss::make_timeline({
    "2024-01-01T00:00:00Z", "2024-01-02T00:00:00Z",
    "2024-01-01T00:00:00Z", "2024-01-03T00:00:00Z"}));
auto groups = pluss::kindle::Stream(pluss::make_note({"A", "A", "B", "B"}));
auto out = stream.ts().rolling(axis, groups, "5D");
std::cout << out;

Group "A" (positions 0, 1) windows independently from group "B" (positions 2, 3) even though their axis ticks overlap.

Notes¶

  • See the important callouts above.

  • The fixed-window overload’s default options mean the first window - 1 positions use a growing partial window rather than becoming NULL.

  • The calendar-duration overloads only support Sum/Mean/Var/Std — see StreamTimeSeriesAccessor::timed for the fully worked duration-window boundary rules this overload delegates to internally.

See Also¶

  • StreamTimeSeriesAccessor::expanding: the same engine with the window growing from the start of the stream instead of a fixed size.
