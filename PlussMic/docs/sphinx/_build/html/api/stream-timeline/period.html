StreamTimelineAccessor::period¶

Back to StreamTimelineAccessor API Reference

Signature¶

Stream StreamTimelineAccessor::period(std::string_view freq) const

What It Does¶

Replaces the bound stream’s timestamp with the start of the freq-sized period it falls within, replacing its values in place. For the fixed clock units, this is equivalent to floor(freq); for the calendar units it accepts, it snaps to the start of that calendar period (e.g. the first of the month).

Important

StreamTimelineAccessor requires the bound stream to be Timeline- or TimeIndex-kind Same precondition as every method on this accessor — see StreamTimelineAccessor::isnat’s own important callout for the full explanation and the exact throw message.

Parameters¶

freq (std::string_view) One of "S"/"s"/"sec"/"second", "min"/"m"/"minute", "H"/"h"/"hour", or "D"/"d"/"day". Cannot be empty. An unsupported frequency throws.

Returns¶

Stream A new stream with its timestamp replaced by its period start.

Examples¶

Example 1. Snap a mid-day timestamp to its containing day’s start.

auto stream = pluss::kindle::Stream(pluss::make_timeline({"2024-01-31T09:15:30Z"}));
auto out = stream.tl().period("D");
auto fmted = out.tl().fmt("%Y-%m-%d %H:%M:%S");
std::cout << fmted.as_note().at(0);

Output¶

2024-01-31 00:00:00

Notes¶

  • For the fixed units this method accepts, period(freq) behaves the same as floor(freq) — see that page for the unrecognized-unit throw text.

  • See the important callout above.

See Also¶

  • StreamTimelineAccessor::shift: move the timestamp by a fixed offset instead of snapping to a period boundary.

  • Stream::tl: the entry point this accessor is reached from.
