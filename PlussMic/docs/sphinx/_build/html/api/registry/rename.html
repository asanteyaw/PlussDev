Registry::rename¶

Back to Registry API Reference

Signatures¶

Registry Registry::rename(std::string_view from, std::string_view to) const
Registry Registry::rename(std::initializer_list<std::pair<std::string_view, std::string_view>> mapping) const
Registry Registry::rename(const std::unordered_map<std::string, std::string>& mapping) const

What It Does¶

Returns a new registry with one or more fields renamed, in place in the field order — values are untouched, only the field names change. The single from/to overload renames exactly one field; the mapping overloads (an initializer list of {from, to} pairs, or an unordered_map) rename several fields in one call.

Important

Both overloads validate differently, and rename() never overwrites your own mistake The initializer-list overload rejects a duplicate source key within the same call ("Registry::rename: duplicate source key in mapping") before it even reaches the shared rename logic. Both overloads (after that point) reject any target name that collides with another field’s final name — "Registry::rename: duplicate target key '<name>'" — including a target that collides with a field that wasn’t itself being renamed. An unknown source key throws "Registry::rename: unknown key '<name>'", and an empty target name throws too. An empty mapping (unordered_map overload only) is the one case that succeeds trivially, returning the registry unchanged.

Parameters¶

from / to (std::string_view) The existing field name and its replacement (single-pair overload).

mapping (std::initializer_list<std::pair<std::string_view, std::string_view>> / const std::unordered_map<std::string, std::string>&) A {from, to} mapping for renaming several fields in one call.

Returns¶

Registry A new registry with the requested field(s) renamed; every other field keeps its original name.

Examples¶

Example 1. Rename several fields at once via an initializer list of pairs.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1), pluss::make_series(2), pluss::make_series(3)})},
    {"population", pluss::bundle::Slot({pluss::make_series(100), pluss::make_series(200), pluss::make_series(300)})},
    {"city", pluss::bundle::Slot({pluss::make_note("Accra"), pluss::make_note("Tema"), pluss::make_note("Kumasi")})},
});

auto out = rg.rename({{"city", "location"}, {"id", "identifier"}});
for (const auto& key : out.fields()) std::cout << key << " ";

Output¶

identifier population location

Example 2. The same rename via an unordered_map.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1)})},
    {"city", pluss::bundle::Slot({pluss::make_note("Accra")})},
});

std::unordered_map<std::string, std::string> mapping{{"city", "location"}};
auto out = rg.rename(mapping);
for (const auto& key : out.fields()) std::cout << key << " ";

Output¶

id location

Example 3. The single-pair overload for renaming exactly one field.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1)})},
    {"city", pluss::bundle::Slot({pluss::make_note("Accra")})},
});

auto out = rg.rename("city", "location");
for (const auto& key : out.fields()) std::cout << key << " ";

Output¶

id location

Example 4. Renaming to a name that already belongs to another field throws.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1)})},
    {"city", pluss::bundle::Slot({pluss::make_note("Accra")})},
});

try {
  auto out = rg.rename("city", "id");
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Registry::rename: duplicate target key 'id'

Notes¶

  • Field order is preserved — a renamed field keeps its original position, only its name changes.

  • See the important callout above for the exact throw messages and the empty-mapping special case.

  • Never mutates the receiver — use rename_() for the in-place form.

See Also¶

  • Registry::rename_: the in-place counterpart (single-pair form only).

  • Registry::combine: auto-generates suffixed names on collision, rather than throwing — useful when you want automatic collision handling instead of manual renaming.

  • Catalog::rename: the equivalent operation on the kindle model.
