Registry::fieldaxis¶

Back to Registry API Reference

Signature¶

RegistryFieldAxisAccessor Registry::fieldaxis() const

What It Does¶

The entry point into field-name and field-kind filtering — fieldaxis() binds the current registry and hands back a RegistryFieldAxisAccessor, documented in full on its own pages (see RegistryFieldAxisAccessor API Reference): name-pattern filters (like(), match(), prefix(), suffix()) and value-kind filters (kind(), series(), note(), timeline(), timeindex(), mixed(), nulls(), empty()). Each accessor method returns a new Registry containing only the matching fields.

Parameters¶

None

Returns¶

RegistryFieldAxisAccessor A binder for the current registry — call one of its methods to select a subset of fields by name or by value kind.

Examples¶

Example 1. Select only the fields whose values are entirely Series-kind.

auto rg = pluss::scribble::Registry({
    {"id", pluss::scribble::Slot({pluss::make_series(1), pluss::make_series(2), pluss::make_series(3)})},
    {"city", pluss::scribble::Slot({pluss::make_note("Accra"), pluss::make_note("Tema"), pluss::make_note("Kumasi")})},
});

auto series_only = rg.fieldaxis().series();
for (const auto& key : series_only.fields()) std::cout << key << " ";

Output¶

id

Notes¶

  • fieldaxis() alone does no work — it only binds the registry; call one of its methods to actually filter fields.

  • Distinct from fields(keys), which selects fields you already know the names of — fieldaxis() selects fields by pattern or by value kind instead.

  • The full accessor surface is documented separately — see RegistryFieldAxisAccessor API Reference.

See Also¶

  • Registry::fields: field access when you already know the exact field names, rather than a pattern or kind — fields(keys) is the lower-level explicit-list projection this accessor’s filters are built on top of.

  • AtlasLabelAccessor: a similarly-shaped filtering accessor on the table model, for depth labels rather than field names.
