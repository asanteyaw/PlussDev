Registry::map¶

Back to Registry API Reference

Signature¶

Registry Registry::map(const std::function<Slot(const Slot&)>& fn) const

What It Does¶

Runs fn over every field’s Slot and returns a new registry with all of them replaced.

Important

Whole-registry transform fn runs on every field regardless of value kind, so a callback written only for one kind can throw on a field of a different kind. Registry has no scoped, apply-to-named-fields sibling method anymore — to transform just one field, fetch it via fields(key), call fn on it directly, and reinsert with set(): rg.set("population", fn(rg.fields("population"))).

Parameters¶

fn (const std::function<Slot(const Slot&)>&) A callback taking each field’s Slot in turn and returning its replacement. Must return a defined Slot for every field.

Returns¶

Registry A new registry with every field replaced by fn’s result.

Examples¶

Example 1. Apply one transform to every field.

auto rg = pluss::bundle::Registry({
    {"id", pluss::bundle::Slot({pluss::make_series(1), pluss::make_series(2), pluss::make_series(3)})},
});

auto out = rg.map([](const pluss::bundle::Slot& s) { return s; });
std::cout << out.nfields();

Output¶

1

Notes¶

  • Never mutates the receiver — returns a new Registry; use map_() for the in-place form.

See Also¶

  • Registry::map_: the in-place counterpart.

  • Registry::fields / Registry::set: fetch-transform-reinsert for scoping a Slot -> Slot transform to one named field instead of every field.

  • Registry::morph: a value-level (not whole-Slot) transform, scoped to one field.

  • Catalog::map: the closest equivalent on the kindle model.
