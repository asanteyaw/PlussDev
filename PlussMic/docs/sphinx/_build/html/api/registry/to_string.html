Registry::to_string¶

Back to Registry API Reference

Signature¶

std::string Registry::to_string() const

What It Does¶

Renders the registry as a JSON summary string — one entry per field, each showing its size and a tally of value kinds (types). This is the format operator<</show() also use; all three are identical. It is a coarser summary than to_json(), which lists every individual value’s type instead of just a per-kind count.

Parameters¶

None

Returns¶

std::string A JSON summary of the registry’s fields.

Examples¶

Example 1. A registry with a uniform-kind field and a mixed-kind field.

auto rg = pluss::scribble::Registry({
    {"id", pluss::scribble::Slot({pluss::make_series(1), pluss::make_series(2)})},
    {"mixed", pluss::scribble::Slot({pluss::make_series(10), pluss::make_note("hello")})},
});

std::cout << rg.to_string();

Output¶

{
  "_type": "Registry",
  "defined": true,
  "nfields": 2,
  "fields": {
    "id": {
      "size": 2,
      "types": {
        "Series": 2
      }
    },
    "mixed": {
      "size": 2,
      "types": {
        "Note": 1,
        "Series": 1
      }
    }
  }
}

Notes¶

  • Identical output to operator<< and show().

  • A field’s types tally having more than one entry is exactly what makes that field not stream-compatible — see Registry::kindelize.

  • On an undefined registry, returns { "_type": "Registry", "defined": false } rather than throwing.

See Also¶

  • Registry::to_json: the finer-grained, per-value counterpart.

  • Registry::show: writes this same string to a caller-provided stream.

  • Registry::profiles: the same per-field type tally, as data rather than a rendered string.

  • Catalog::to_string: the equivalent method on the kindle model (a box-table format, not JSON).
