What It Does¶

Joins two catalogs already in the workspace and returns the result directly. With no keys set in spec, the declared link between left and right supplies them – an error if more than one link connects the pair – and that link’s cardinality is enforced; set spec.keys to join on explicit columns without any declared link at all. Matching is done on the key streams alone and every other stream is rebuilt through the matches, so a ragged catalog’s raggedness is preserved on both sides of the join, not flattened.

The JoinPath overload joins along a chain of links, accumulating columns table by table – path() finds the shortest such chain, and each hop enforces its own link’s cardinality, the same as a single-hop join() would.

join_detailed() is the same join, returning both the Catalog (.catalog) and a CatalogJoinReport (.report) describing what was matched, left without a partner, or omitted – join() itself discards that report.

struct JoinSpec {
  std::vector<std::pair<std::string, std::string>> keys{};
  JoinHow how{JoinHow::Inner};
  std::string right_suffix{};
  std::optional<RelationshipCardinality> validate{};
  std::optional<std::string> relationship_name{};
  std::optional<std::string> result_name{};
};

Returns¶

join returns the joined Catalog directly. join_detailed returns a LocusJoinResult – .catalog (the same Catalog) and .report (a CatalogJoinReport, with its own .summary()).

Errors¶

Throws when neither spec.keys nor a single unambiguous declared link is available, when a named key column doesn’t exist, when an unknown table is named, or when the join’s actual cardinality contradicts a declared or requested one.

Examples¶

Example 1. Inner (default), left, and explicit-key joins, and the no-link failure.

// customers 1..3; orders 10..13 (order 13's customer, 9, does not exist).
const auto shop = make_shop().link("orders", "cust_id", "customers", "id", RelationshipCardinality::ManyToOne);

const auto joined = shop.join("orders", "customers");
std::cout << "inner join rows: " << joined.get("amount")->size() << '\n';

JoinSpec left_spec;
left_spec.how = JoinHow::Left;
const auto kept = shop.join("orders", "customers", left_spec);
std::cout << "left join rows: " << kept.get("amount")->size() << '\n';

JoinSpec explicit_keys;
explicit_keys.keys = {{"cust_id", "id"}};
const auto manual = make_shop().join("orders", "customers", explicit_keys);
std::cout << "explicit-key join rows: " << manual.get("amount")->size() << '\n';

try {
  (void)make_shop().join("orders", "customers");
  std::cout << "unlinked join: did not throw\n";
} catch (const std::exception& e) {
  std::string msg = e.what();
  std::cout << "unlinked join threw: " << msg.substr(0, msg.find('\n')) << '\n';
}

Output¶

inner join rows: 3
left join rows: 4
explicit-key join rows: 3
unlinked join threw: Locus::join: no direct relationship connects 'orders' and 'customers'

The default Inner join drops order 13 (no matching customer); Left keeps all four orders, with a null on the customer side for the orphan. With no declared link at all, join() with no explicit keys has nothing to join on and throws.

Example 2. join_detailed(): the same join, plus a report. Continues from Example 1’s shop.

const auto detailed = shop.join_detailed("orders", "customers");
std::cout << "join_detailed matched: " << detailed.catalog.get("amount")->size() << '\n';
std::cout << "join_detailed report: " << detailed.report.summary() << '\n';

Output¶

join_detailed matched: 3
join_detailed report: 3 output record(s); 3 matched pair(s). left: 1 of 4 record(s) without a partner (0 without a key), 1 omitted. right: 1 of 3 without a partner (0 without a key), 1 omitted.

The report’s own prose names exactly what join() alone would leave you to infer: one order and one customer each had no partner, and each was omitted (the default Inner semantics), not silently dropped without a count.
