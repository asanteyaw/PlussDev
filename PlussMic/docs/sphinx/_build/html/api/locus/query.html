Locus::query¶

Back to Locus API Reference

Signatures¶

LocusQuery Locus::query() const
LocusQuery Locus::query(pluss::table::DataFrame::SqlOptions options) const

What It Establishes¶

query() exposes every named catalog as a table in one in-memory SQL workspace and returns a LocusQuery. The call obtains Locus’s cached aligned Nexus view, then the accessor owns that workspace handle and a copy of its options. No SQL is parsed and no result is allocated at this point.

Continue in the LocusQuery API Reference: use execute() for a one-shot statement or prepare() to retain statement text and bind values repeatedly. Results return as Catalog, not DataFrame, so the query boundary stays inside the ragged data model even though SQL execution uses rectangular alignment internally.

The no-argument overload uses default SQL policy. The options overload captures limits, parameter defaults, diagnostics, collision policy, and execution policy for every later call made through that accessor or a prepared query derived from it.

Returns¶

LocusQuery

A workspace-owning accessor with copied options. It remains valid when created from a temporary Locus. SqlOptions::sources is the exception: each SourceBinding contains a borrowed DataFrame*, so externally added frames must outlive execution through the accessor.

Examples¶

Example 1. Default options expose all catalog keys as SQL table names.

auto default_query = data.query();
const auto all = default_query.execute("SELECT order_id FROM orders ORDER BY order_id");
print_numbers(all, "order_id");

Output¶

order_id=[100, 101, 102, 103]

Example 2. Options are captured by value. Here the result-row cap retains the first two rows after SQL ordering.

SqlOptions limited;
limited.max_result_rows = 2;
const auto first_two = data.query(limited).execute(
    "SELECT order_id FROM orders ORDER BY order_id");
print_numbers(first_two, "order_id");

Output¶

order_id=[100, 101]

Example 3. The accessor owns the workspace needed for later execution.

const auto retained = shop().query();
print_words(retained.execute(
    "SELECT name FROM customers ORDER BY customer_id"), "name");

Output¶

name=[Ada, Bola, Chen]

Cost And Ownership¶

Creating the accessor copies options and a reference-counted aligned workspace handle. Locus caches that alignment by catalog and policy, so unchanged catalogs are not padded again for each accessor. Building and loading the transient SQL database remains deferred to execution. Keep the accessor when several related statements share the same options; use a prepared query when the statement text itself also repeats.
