CatalogTimeSeriesAccessor::log_returns¶

Back to CatalogTimeSeriesAccessor API Reference

Signature¶

Catalog CatalogTimeSeriesAccessor::log_returns(std::int64_t periods = 1) const

What It Does¶

Computes the logarithmic period-over-period change of every bound key: out[i] = ln(x[i] / base[i]), where base is x shifted by periods (a lag when periods > 0, a lead when periods < 0). A position is NULL wherever x[i] or base[i] is missing or non-finite, or either value is not strictly positive — unlike returns(), a zero or negative value anywhere in the comparison always yields NULL, since the logarithm would otherwise be undefined.

Important

CatalogTimeSeriesAccessor requires every bound key to be numeric Series-kind Same precondition as every method on this accessor — see CatalogTimeSeriesAccessor::diff’s own important callout for the full explanation and how to project down to numeric keys first.

Parameters¶

periods (std::int64_t, default 1) The shift distance used to build the comparison base. Positive shifts compare each position against an earlier one (a lag); negative shifts compare against a later one (a lead). Must not be 0, or the call throws.

Returns¶

Catalog A new catalog with every bound key replaced by its period-over-period log return.

Examples¶

Example 1. Compute the one-period log return of a numeric key.

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "metric"_k = pluss::kindle::Stream(pluss::make_series({10.0, 20.0, 15.0, 30.0})),
});
auto out = ct.ts().log_returns(1);
std::cout << out;

Output¶

========================================================================================================================
kindle::Catalog  keys=1
keys: [metric]
------------------------------------------------------------------------------------------------------------------------
key                      | kind         | dtype            | cs      | preview                                          
------------------------------------------------------------------------------------------------------------------------
metric                   | Series       | Series[float64]  | 4       | [nan, 0.69314718056, -0.287682072452, 0.69314718~
========================================================================================================================

Position 1 is ln(20 / 10) = ln(2) ≈ 0.6931; position 2 is ln(15 / 20) ≈ -0.2877; position 3 is ln(30 / 15) ≈ 0.6931 — the same log return as position 1, since both moves double the value.

Example 2 (edge case). A negative value in the comparison always yields NULL for log_returns(), unlike returns().

using namespace pluss::kindle::literals;

auto ct = pluss::kindle::Catalog({
    "metric"_k = pluss::kindle::Stream(pluss::make_series({10.0, -5.0, 20.0})),
});
auto out = ct.ts().log_returns(1);
std::cout << out;

Output¶

========================================================================================================================
kindle::Catalog  keys=1
keys: [metric]
------------------------------------------------------------------------------------------------------------------------
key                      | kind         | dtype            | cs      | preview                                          
------------------------------------------------------------------------------------------------------------------------
metric                   | Series       | Series[float64]  | 3       | [nan, nan, nan]                                  
========================================================================================================================

log_returns() requires both sides to be strictly positive; since every comparison here involves the negative -5, all three positions come back nan.

Notes¶

  • Unlike returns(), log_returns() requires both x[i] and base[i] to be strictly greater than 0; a zero or negative value in either produces NULL rather than an error.

  • Log returns are additive across periods (the sum of consecutive one-period log returns equals the multi-period log return), which plain fractional returns() are not — a common reason to prefer this method for compounding analysis.

  • periods must not be 0, or it throws — see returns() for the throw example (same message pattern).

  • See the important callout above.

See Also¶

  • CatalogTimeSeriesAccessor::diff: the absolute period-over-period change.

  • Catalog::ts: the entry point this accessor is reached from.
