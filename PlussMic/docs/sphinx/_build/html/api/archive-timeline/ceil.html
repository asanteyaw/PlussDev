ArchiveTimelineAccessor::ceil¶

Back to ArchiveTimelineAccessor API Reference

Signature¶

Archive ArchiveTimelineAccessor::ceil(std::string_view unit) const

What It Does¶

Rounds each bound key’s timestamp up to the nearest unit boundary, replacing each bound key’s values in place (the key stays Timeline-kind). Applied to every catalog in the stack, by delegating to that catalog’s own CatalogTimelineAccessor::ceil.

Important

Binding and kind-check rules are inherited from Archive::tl() This method’s key-binding (from catalog(0)) and lazy Timeline-kind check follow exactly the rules documented on Archive::tl — see that page’s two important callouts for the full explanation. ArchiveTimelineAccessor requires every bound key to be Timeline-kind, checked the moment any method (including this one) is called.

Parameters¶

unit (std::string_view) One of "S"/"s"/"sec"/"second", "min"/"m"/"minute", "H"/"h"/"hour", or "D"/"d"/"day". Cannot be empty. An unsupported unit throws.

Returns¶

Archive A new archive of the same depth, with every bound key’s timestamps ceiled to unit, in every catalog.

Examples¶

Example 1. Ceil two timestamps to the nearest hour. Delegation to CatalogTimelineAccessor::ceil is exact — the same input catalog produces the identical per-catalog output shown on CatalogTimelineAccessor::ceil’s own page.

using namespace pluss::kindle::literals;

auto c0 = pluss::kindle::Catalog({
    "ts"_k = pluss::kindle::Stream(pluss::make_timeline({"2024-01-31T09:15:30Z", "2024-02-29T23:45:00Z"})),
});
auto archive = pluss::kindle::Archive({c0});
auto out = archive.tl().ceil("H");
auto fmted = out.tl().fmt("%Y-%m-%d %H:%M:%S");
std::cout << fmted.catalog(0).keys("ts").as_note().at(0) << " | " << fmted.catalog(0).keys("ts").as_note().at(1);

Output¶

2024-01-31 10:00:00 | 2024-03-01 00:00:00

Notes¶

  • See the important callout above — binding and kind-check rules come from Archive::tl.

  • This method’s per-catalog result is identical to calling CatalogTimelineAccessor::ceil directly on each catalog in the stack.
