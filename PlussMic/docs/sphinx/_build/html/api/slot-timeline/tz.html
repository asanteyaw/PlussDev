SlotTimelineAccessor::tz¶

Back to SlotTimelineAccessor API Reference

Signature¶

Slot SlotTimelineAccessor::tz(std::string_view name) const

What It Does¶

Relabels each value’s display timezone to name, without changing the underlying instant — the same operation as Thread::tl().tz()/ DataFrame::tl().tz() at the table layer.

The relabeling survives being read back through any further .tl() call (fmt(), hour(), another tz(), anything) — see Example 1.

Parameters¶

name (std::string_view) The target timezone. Only "UTC" (also the empty string), "America/Edmonton", "America/New_York", and "Europe/London" are recognized (case-insensitive); any other name throws.

Returns¶

Slot A new slot with each value relabeled to name. Reading the result back through any further .tl() call reflects the new display timezone.

Examples¶

Example 1. tz() relabels the display timezone, and the relabeling is still in effect on the very next .tl() read.

auto slot = pluss::scribble::Slot({pluss::make_timeline("2024-01-31T09:15:30Z")});
auto shifted = slot.tl().tz("America/New_York");
auto fmted = shifted.tl().fmt("%Y-%m-%d %H:%M:%S");
std::cout << std::get<pluss::Note>(fmted.at(0)).at(0);

Output¶

2024-01-31 04:15:30

04:15:30 is the "America/New_York"-relative reading of the same instant (a -5:00 offset in January) — matching what Thread::tl().tz() produces on the same input.

Notes¶

  • Only four timezone names are recognized: "UTC" (or empty string), "America/Edmonton", "America/New_York", and "Europe/London" — any other name throws.

  • Requires the slot to be Timeline-kind — a non-Timeline slot throws "Slot::tl: slot kind must be Timeline".

  • Internally, a Slot stores each row’s Timeline value independently (one scalar Timeline per row, not one shared column). tz() relabels every value, and that relabeling round-trips correctly through the kindle::Stream boundary every further .tl() call goes through — this is the same fix verified on RegistryTimelineAccessor::tz, since Registry::tl().tz() calls this method per field internally. If every value does not already share the same display timezone going into a .tl() call, the call throws rather than picking one arbitrarily — combine to a common zone with tz()/localize() first if needed.

See Also¶

  • SlotTimelineAccessor::utc: shorthand for tz("UTC").

  • SlotTimelineAccessor::localize: changes the underlying instant (which does persist) rather than just the display label.

  • Slot::tl: the entry point this accessor is reached from.
