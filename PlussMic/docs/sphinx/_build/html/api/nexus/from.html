Nexus::from¶

Back to Nexus API Reference

Signature¶

Nexus::from(std::string_view table) const -> NexusTraverse

What It Does¶

Enters the fluent NexusTraverse builder, anchored at table. from() itself does no joining — it just binds a starting table and hands back a builder whose methods (.join(), .via(), .pick(), .drop(), .name()) accumulate a JoinPlan one call at a time, materialized only when you call .collect().

This is the higher-level counterpart to building a JoinPlan by hand via path()/plan() and executing it with materialize() — NexusTraverse covers the common case (a chain of joins from one anchor table) with a shorter, chainable spelling, and can auto-detect the relationship to use at each step when it’s unambiguous.

Parameters¶

table (std::string_view) The table to anchor the query at. Must already exist in the workspace — an unknown name throws "Nexus::from: unknown table '<table>'".

Returns¶

NexusTraverse A query builder anchored at table, with an empty plan (zero steps) so far.

Examples¶

Example 1. Enter the builder and immediately collect — with no .join() calls, this is equivalent to frame(table).

using namespace pluss::table;
using namespace pluss::bundle;

auto customers = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0, 3.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben", "Cy"}))},
});

auto biz = Nexus({{"customers", customers}});

auto result = biz.from("customers").collect();
std::cout << result.ncases() << " " << result.nfeatures();

Output¶

3 2

Example 2. An unknown table throws immediately, before any joining is attempted.

try {
  auto bad = biz.from("missing");
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Nexus::from: unknown table 'missing'

Notes¶

  • Never touches table data itself — the anchor is validated (it must exist) but nothing is read or joined until .collect() runs.

  • See the NexusTraverse API Reference for the full builder method list (.join(), .via(), .pick(), .drop(), .name(), .collect()).
