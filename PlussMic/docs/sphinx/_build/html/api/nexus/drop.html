Nexus::drop¶

Back to Nexus API Reference

Signature¶

Nexus::drop(std::initializer_list<std::string_view> keys) const -> Nexus

What It Does¶

Builds a new workspace by removing the named tables you specify and carrying forward every unmentioned table unchanged.

drop() is the complement of select():

  • select() says “keep exactly these tables”

  • drop() says “remove exactly these tables”

That difference affects ordering. drop() does not use request order to build the output; instead, it preserves the original left-to-right order of every table that survives.

Like the other subset operations, drop() carries forward table metadata for the remaining tables and keeps only the relationships and saved views that still make structural sense after the removal.

Parameters¶

keys (std::initializer_list<std::string_view>)

The table names to remove.

  • Each key must be non-empty.

  • Each key must be unique within the request.

  • Each key must already exist in the source workspace.

An empty list is allowed and acts as a no-op.

Returns¶

Nexus A new workspace containing every source table except the ones named in keys, with the surviving tables kept in their original order.

The source `Nexus` is unchanged.

Examples¶

Example 1. Remove two named tables and preserve the original order of what remains.

using namespace pluss::table;

auto print_keys = [](const Nexus& nx) {
  for (std::int64_t i = 0; i < nx.ntables(); ++i) {
    if (i > 0) {
      std::cout << ", ";
    }
    std::cout << nx.keys()[static_cast<std::size_t>(i)];
  }
  std::cout << "\n";
};

auto customers = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0, 3.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben", "Cy"}))},
});

auto orders = DataFrame({
    {"order_id",    Thread(pluss::make_series({101.0, 102.0}))},
    {"customer_id", Thread(pluss::make_series({1.0, 2.0}))},
});

auto payments = DataFrame({
    {"payment_id", Thread(pluss::make_series({9001.0, 9002.0}))},
    {"order_id",   Thread(pluss::make_series({101.0, 102.0}))},
});

auto refunds = DataFrame({
    {"refund_id", Thread(pluss::make_series({77.0}))},
    {"order_id",  Thread(pluss::make_series({102.0}))},
});

auto biz = Nexus({
    {"customers", customers},
    {"orders", orders},
    {"payments", payments},
    {"refunds", refunds},
});

auto out = biz.drop({"orders", "refunds"});
print_keys(out);
print_keys(biz);

Output¶

customers, payments
customers, orders, payments, refunds

Example 2. Continuing from Example 1, dropping an empty list is a no-op.

print_keys(biz.drop({}));

Output¶

customers, orders, payments, refunds

Example 3. Continuing from Example 1, validation is strict: empty names, duplicate names in the request, and unknown names all throw.

try {
  auto bad = biz.drop({"", "orders"});
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

try {
  auto dup = biz.drop({"orders", "orders"});
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

try {
  auto missing = biz.drop({"orders", "missing"});
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

Nexus::drop: key cannot be empty
Nexus::drop: duplicate key 'orders'
Nexus::drop: unknown key 'missing'

Notes¶

  • drop() is non-mutating.

  • Surviving tables keep their original order. This is the key semantic difference from select(), whose request list determines output order.

  • Surviving table metadata is preserved.

  • Relationships and saved views are pruned to the subset still supported by the remaining tables.

  • If you want the result to contain only a named list of tables, use select() instead.

See Also¶

  • Nexus::select: keep an explicit table list instead of removing one.

  • Nexus::tail: drop by position from the front rather than by name.

  • Nexus::keys: inspect the remaining order after dropping tables.
