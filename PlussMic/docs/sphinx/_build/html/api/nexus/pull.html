Nexus::pull¶

Back to Nexus API Reference

Signature¶

Nexus::pull(std::string_view root, std::initializer_list<std::string_view> fields) const -> DataFrame

What It Does¶

Assembles a wide feature table, one row per root row, from fields spread across the whole relationship graph — a “give me these specific columns, from wherever they live” alternative to materialize(), which instead returns the full joined frame with every column from every hop. pull() never changes root’s own row count or row grain; every requested field, however many hops away, comes back as exactly one value per root row.

Each entry in fields is a small expression, parsed according to its own grammar:

  • A bare name ("amount") — a feature on root itself.

  • table.feature ("customers.name") — a feature on a related table, reached by walking the shortest relationship path from root to table (via the same search path() uses). The path must be root-preserving: every hop along the way must be ManyToOne or OneToOne from root’s side, so each root row maps to at most one row on table. A path that would require expanding root into several rows (a OneToMany or ManyToMany hop) throws — see Example 5.

  • table.feature.aggregate ("orders.amount.sum") — an aggregate of a related table’s feature, computed by grouping that table’s rows by root’s declared primary key. aggregate is one of count, ndistinct, sum, mean, min, max (case-insensitive). Unlike plain fields, aggregate fields work across any cardinality, including OneToMany — that’s the whole point of aggregating. table must not be root itself (aggregating a root feature against itself doesn’t mean anything — see Example 8).

  • `quoted.name` — backtick-quote any path segment that itself contains a literal ., so it isn’t mistaken for a path separator — see Example 9.

Every output column is aliased automatically: a plain root feature keeps its own name; a plain related-table feature becomes <table>_<feature> (each piece sanitized to alphanumerics-and-underscores); an aggregate becomes <table>_<feature>_<aggregate>.

Important

Aggregate fields require a complete, unique declared primary key on root Every aggregate field needs to group by something — that something is root’s declared TableMeta::primary_key. If root has no declared metadata, or a primary_key that doesn’t fully and uniquely identify its rows, requesting any aggregate field throws before touching the aggregation itself — see Example 10. Plain (non-aggregate) fields have no such requirement.

Important

Windowed aggregates: _[_root] Appending a duration to an aggregate token turns it into a windowed aggregate: "orders.amount.sum_7d" sums amount only over orders within a trailing time window, instead of every matching row unconditionally. The duration is a positive integer followed by a unit — s/sec/secs/second/seconds, m/min/mins/minute/minutes, h/hr/hrs/hour/hours, d/day/days, or w/wk/wks/week/weeks. A windowed aggregate requires the related table (orders, above) to have a declared time_field.

The window’s end point — where the trailing window is measured from — depends on the anchor, chosen by an optional _root suffix:

  • _<N><unit> (no _root; the default, “Latest” anchor): the window ends at each root row’s own most recent matching related-table row, per the related table’s time_field. Concretely, "orders.amount.sum_7d" sums each customer’s orders that fall within 7 days before their own latest order — a trailing window anchored to each customer’s own activity, not a fixed calendar date.

  • _<N><unit>_root: the window ends at root’s own declared time_field instead — which also means root itself must have a declared time_field for this form, not just the related table. See Example 7 for how this changes the result compared to the default “Latest” anchor.

ndistinct windows are not supported and throw "ndistinct windows are not supported yet".

Parameters¶

root (std::string_view) The table whose row grain is preserved. Must already exist in the workspace.

fields (std::initializer_list<std::string_view>) One or more field expressions, parsed as described above. Each parsed field’s output alias must be unique — two expressions that would collide on the same alias throw. At least one field is required.

Returns¶

DataFrame One row per root row, one column per requested field (aliased as described above), titled root + "_pull".

Examples¶

Example 1. A bare field from root itself.

using namespace pluss::table;

auto customers = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0, 3.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben", "Cy"}))},
});
auto orders = DataFrame({
    {"order_id",    Thread(pluss::make_series({101.0, 102.0, 103.0, 104.0}))},
    {"customer_id", Thread(pluss::make_series({1.0, 2.0, 2.0, 1.0}))},
    {"amount",      Thread(pluss::make_series({50.0, 75.0, 20.0, 30.0}))},
});

auto biz = Nexus({
    {"customers", customers},
    {"orders", orders},
});

TableMeta customers_meta;
customers_meta.primary_key = {"customer_id"};
auto tagged = biz.set_table_meta("customers", customers_meta);

Relationship rel;
rel.name = "orders_to_customers";
rel.left_table = "orders";
rel.right_table = "customers";
rel.keys = {{"customer_id", "customer_id"}};
rel.cardinality = RelationshipCardinality::ManyToOne;

auto linked = tagged.add_relationship(rel);

auto p1 = linked.pull("customers", {"name"});
std::cout << p1.features("name");

Output¶

0  Ada
1  Ben
2  Cy
Name: name, ptype: Note

Example 2. A plain field pulled from root (orders, the “many” side) across to a related table (customers, the “one” side) — root-preserving, since each order matches exactly one customer.

auto p2 = linked.pull("orders", {"order_id", "customers.name"});
std::cout << p2.features("customers_name");

Output¶

0  Ada
1  Ben
2  Ben
3  Ada
Name: customers_name, ptype: Note

Example 3. An aggregate: how many orders each customer has.

auto p3 = linked.pull("customers", {"name", "orders.order_id.count"});
std::cout << p3.features("orders_order_id_count");

Output¶

0  2
1  2
2  0
Name: orders_order_id_count, ptype: Series

Cy (customer 3, with zero orders) correctly gets 0, not a missing value.

Example 4. An aggregate that has nothing to aggregate returns a missing value, not 0 — contrast count’s Example 3.

auto p4 = linked.pull("customers", {"name", "orders.amount.sum"});
std::cout << p4.features("orders_amount_sum");

Output¶

0  80
1  95
2  NULL
Name: orders_amount_sum, ptype: Series

Example 5. Pulling a plain (non-aggregate) field the other direction — from customers (the “one” side) out to orders (the “many” side) — is not root-preserving, and throws.

try {
  auto bad = linked.pull("customers", {"orders.amount"});
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Nexus::pull: requested field 'orders.amount' requires expanding relationship 'orders_to_customers' from 'customers' to 'orders'. pull preserves root grain and cannot traverse one-to-many or many-to-many paths

This is exactly the situation orders.amount.sum (Example 4) is for — aggregate the many-side rows down to one value per root row, instead of trying to expand root.

Example 6. Windowed aggregates: a customer’s two orders 10 days apart, summed within a trailing 7-day window anchored at their own latest order.

auto customers2 = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben"}))},
});
auto orders2 = DataFrame({
    {"order_id",    Thread(pluss::make_series({101.0, 102.0, 103.0}))},
    {"customer_id", Thread(pluss::make_series({1.0, 1.0, 2.0}))},
    {"amount",      Thread(pluss::make_series({50.0, 30.0, 75.0}))},
    {"ordered_at",  Thread(pluss::make_timeline({
        "2024-01-01T00:00:00Z",
        "2024-01-11T00:00:00Z",
        "2024-01-01T00:00:00Z",
    }))},
});

auto biz2 = Nexus({
    {"customers", customers2},
    {"orders", orders2},
});

TableMeta customers2_meta;
customers2_meta.primary_key = {"customer_id"};
auto tagged2 = biz2.set_table_meta("customers", customers2_meta);

TableMeta orders2_meta;
orders2_meta.time_field = "ordered_at";
auto tagged3 = tagged2.set_table_meta("orders", orders2_meta);

auto linked2 = tagged3.add_relationship(rel);

auto plain_sum = linked2.pull("customers", {"name", "orders.amount.sum"});
std::cout << plain_sum.features("orders_amount_sum") << "\n";

auto windowed_sum = linked2.pull("customers", {"name", "orders.amount.sum_7d"});
std::cout << windowed_sum.features("orders_amount_sum_7d");

Output¶

0  80
1  75
Name: orders_amount_sum, ptype: Series
0  30
1  75
Name: orders_amount_sum_7d, ptype: Series

The plain sum counts both of Ada’s orders (50 + 30 = 80). The windowed sum only counts orders within 7 days before Ada’s own latest order (Jan 11) — her Jan 1 order (50) is 10 days earlier, outside that window, so only the Jan 11 order’s own 30 survives. Ben has one order either way, so his result is unchanged.

Example 7. The _root anchor changes the window’s end point from “each customer’s own latest order” to “the root table’s own declared time — here, signup_at.”

auto customers3 = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben"}))},
    {"signup_at",   Thread(pluss::make_timeline({
        "2024-01-08T00:00:00Z",
        "2024-01-01T00:00:00Z",
    }))},
});

auto biz3 = Nexus({
    {"customers", customers3},
    {"orders", orders2},
});

TableMeta customers3_meta;
customers3_meta.primary_key = {"customer_id"};
customers3_meta.time_field = "signup_at";
auto step1 = biz3.set_table_meta("customers", customers3_meta);
auto step2 = step1.set_table_meta("orders", orders2_meta);
auto linked3 = step2.add_relationship(rel);

auto root_anchored = linked3.pull("customers", {"name", "orders.amount.sum_7d_root"});
std::cout << root_anchored.features("orders_amount_sum_7d_root");

Output¶

0  50
1  75
Name: orders_amount_sum_7d_root, ptype: Series

Ada signed up Jan 8. A 7-day trailing window ending there (Jan 1–Jan 8) includes her Jan 1 order (50) but excludes her Jan 11 order (which happens after signup) — the opposite selection from Example 6’s “Latest” anchor, which excluded Jan 1 and kept Jan 11.

Example 8. An aggregate field targeting root itself throws.

try {
  auto bad = linked.pull("customers", {"customers.name.count"});
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Nexus::pull: aggregate field 'customers.name.count' must target a related table, not the root table

Example 9. Backtick-quoting a feature name that itself contains a literal ..

auto customers4 = DataFrame({
    {"customer_id",  Thread(pluss::make_series({1.0, 2.0}))},
    {"display.name", Thread(pluss::make_note({"Ada A.", "Ben B."}))},
});
auto orders4 = DataFrame({
    {"order_id",    Thread(pluss::make_series({101.0, 102.0}))},
    {"customer_id", Thread(pluss::make_series({1.0, 2.0}))},
});

auto biz4 = Nexus({
    {"customers", customers4},
    {"orders", orders4},
});
auto linked4 = biz4.add_relationship(rel);

auto p9 = linked4.pull("orders", {"order_id", "customers.`display.name`"});
std::cout << p9.features("customers_display_name");

Output¶

0  Ada A.
1  Ben B.
Name: customers_display_name, ptype: Note

Without the backticks, customers.display.name would parse as three path segments (customers, then display, then name) instead of one table plus one literally-dotted feature name.

Example 10. Requesting any aggregate field when root has no usable declared primary key throws — checked before any aggregation runs.

try {
  auto bad = linked.pull("orders", {"order_id", "customers.name.count"});
} catch (const std::exception& e) {
  std::cout << e.what();
}

Output¶

Nexus::pull: no metadata declared for table 'orders'

orders (used as root here) never had TableMeta declared at all in this session, so the aggregate field’s primary-key requirement fails immediately.

Notes¶

  • Never changes root’s row count — plain fields must be root-preserving (throws otherwise); aggregate fields collapse any cardinality down to one value per root row.

  • Output column aliases are generated automatically: bare name for a root feature, <table>_<feature> for a plain related field, <table>_<feature>_<aggregate> for an aggregate. Two requested fields that would alias to the same name throw.

  • Aggregate fields require root to have a complete, unique declared primary_key — see the important callout above.

  • Windowed aggregates require the related table’s declared time_field; the _root anchor additionally requires root’s own declared time_field. ndistinct windows are unsupported.

  • count/ndistinct aggregates fill unmatched root rows with 0; every other aggregate leaves them missing (NULL) — see Examples 3 and 4.

See Also¶

  • Nexus::materialize: the full-frame alternative, returning every column from every hop instead of hand-picked fields.

  • Nexus::path: the same root-preservation check applies to the routes this method walks for plain fields.

  • Nexus::table_meta: declare primary_key and time_field, both required by different parts of this method.
