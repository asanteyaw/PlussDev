Nexus::meta¶

Back to Nexus API Reference

Signatures¶

Nexus::meta(std::string_view key) const -> std::optional<TableMeta>

Nexus::meta(std::string_view key, const TableMeta& value) const -> Nexus

Nexus& Nexus::meta_(std::string_view key, const TableMeta& value)

What It Does¶

A trio of exact aliases: the one-argument meta(key) calls table_meta(key) internally, meta(key, value) calls set_table_meta(key, value), and meta_(key, value) calls set_table_meta_(key, value). All three behave identically to their canonical counterparts — same throws, same non-mutating/mutating split, same return types. meta exists purely as a shorter, more conversational spelling for the same three calls.

Parameters¶

See table_meta() and set_table_meta() for the full parameter documentation — identical here.

Returns¶

Identical to table_meta() (getter overload) and set_table_meta() (the two setter overloads).

Examples¶

Example 1. meta(key, value) and meta(key) behave exactly like their canonical counterparts.

using namespace pluss::table;

auto customers = DataFrame({
    {"customer_id", Thread(pluss::make_series({1.0, 2.0, 3.0}))},
    {"name",        Thread(pluss::make_note({"Ada", "Ben", "Cy"}))},
});

auto biz = Nexus({{"customers", customers}});

TableMeta info;
info.grain = "one row per customer";
info.primary_key = {"customer_id"};

auto tagged = biz.meta("customers", info);
auto fetched = tagged.meta("customers");

std::cout << std::boolalpha << fetched.has_value() << "\n";
std::cout << *fetched->grain;

Output¶

true
one row per customer

Notes¶

  • Purely a naming alternative — see table_meta() and set_table_meta() for the full documentation, including throw conditions and the read-modify-write pattern for partial updates.
