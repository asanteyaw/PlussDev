ThreadNoteAccessor::normalize¶

Back to ThreadNoteAccessor API Reference

Signature¶

ThreadNoteAccessor::normalize(UnicodeForm form = UnicodeForm::NFC) const -> Thread

What It Does¶

Rewrites each cell of the bound thread into a canonical Unicode normalization form — the standard fix for text that looks identical on screen but compares unequal because it was encoded with a different sequence of combining characters (e.g. "é" as one precomposed codepoint vs. "e" + a combining acute accent). A direct forward to Thread::normalize(). Requires the bound thread to be Note-kind.

Parameters¶

form (UnicodeForm, default UnicodeForm::NFC)

Which of the four standard Unicode normalization forms to apply: NFC (canonical composition — the default, and the one most comparisons want), NFD (canonical decomposition), NFKC (compatibility composition), or NFKD (compatibility decomposition).

Returns¶

Thread A new Note-kind thread, same length as the bound thread, with each cell rewritten into the requested normalization form.

Examples¶

Example 1. Two visually identical strings, encoded differently, become byte-for-byte identical after normalization.

using namespace pluss::table;

// "café" - "e" + a combining acute accent (decomposed form)
auto decomposed = Thread(pluss::make_note({"café"}));
auto out = decomposed.nt().normalize();  // -> "café" as one precomposed codepoint
std::cout << (out == Thread(pluss::make_note({"café"})));

Output¶

0  true

ptype: Series

Example 2. Requesting NFD explicitly decomposes precomposed characters instead.

auto precomposed = Thread(pluss::make_note({"café"}));
auto out2 = precomposed.nt().normalize(UnicodeForm::NFD);
std::cout << (out2 == decomposed);

Output¶

0  true

ptype: Series

Example 3. A non-Note thread throws — the same message Thread::normalize() produces directly.

auto numbers = Thread(pluss::make_series({1.0, 2.0, 3.0}));
try {
  auto bad = numbers.nt().normalize();
} catch (const std::exception& e) {
  std::string msg(e.what());
  std::cout << msg.substr(0, msg.find('\n')) << "\n";
}

Output¶

Thread::normalize: expected Note payload

Notes¶

  • ThreadNoteAccessor::normalize() is a one-line forward to Thread::normalize() — identical behavior and throws.

  • Requires the optional Unicode backend (GNU libunistring) to be linked into this build; without it, non-ASCII normalization is unavailable.

  • A null cell on input stays null on output.

  • Normalizing is a good idea before any equality comparison, has()/matches() search, or grouping key built from user-entered or externally-sourced text.

See Also¶

  • Thread::normalize: the direct, non-accessor form this method forwards to.

  • ThreadNoteAccessor::casefold: case-insensitive comparison normalization — a complementary, not overlapping, concern.

  • ThreadNoteAccessor::encode: byte-level re-encoding, distinct from Unicode form normalization.
