ThreadNoteAccessor::findall¶

Back to ThreadNoteAccessor API Reference

Signatures¶

ThreadNoteAccessor::findall(std::string_view pattern) const -> DataFrame
ThreadNoteAccessor::findall(std::string_view pattern, const TextOptions& options) const -> DataFrame

What It Does¶

Finds every match of pattern in each cell of the bound thread and expands the result into one output column per match position — column match_0 holds each row’s first match, match_1 its second, and so on. Rows with fewer matches than another row have NULL in the columns beyond their own match count; the number of output columns is however many matches the most-matching row produced.

Danger

The single-argument overload defaults to regex mode, same gotcha as count() Exactly like count(), the single-argument findall(pattern) defaults internally to {.regex = true} — a literal "." is interpreted as “match any character,” not a literal period. See Example 1, where the default call splits every cell into one match per character.

Parameters¶

pattern (std::string_view)

A regular expression pattern under the single-argument overload (always regex mode — see the danger box above), or literal/regex text under the two-argument overload depending on options.regex.

options (TextOptions, two-argument overload only)

options.regex (default false): treat pattern as regex instead of literal text. options.case_sensitive (default true): case-insensitive matching when false. options.limit (default -1): cap the number of matches collected per row (and therefore an upper bound on the number of output columns). options.prefix is not used by findall() — output columns are always named match_0, match_1, regardless of options.prefix.

Returns¶

DataFrame A new frame with match_0, match_1, … features (as many as the row with the most matches needed). A row with fewer matches has NULL in the extra columns.

Examples¶

Example 1. The regex-by-default gotcha, and the column-expansion mechanic at the same time: findall(".") under the default overload splits each cell into one match per character.

using namespace pluss::table;

auto samples = Thread(pluss::make_note({"hi", "a.b", "xyz", "x"}),
    pluss::make_series(std::vector<bool>{true, true, true, false}));
std::cout << samples;

auto out1 = samples.nt().findall(".");
std::cout << out1;

auto out2 = samples.nt().findall(".", {.regex = false});
std::cout << out2;

Output (before)¶

0  hi
1  a.b
2  xyz
3  NULL

ptype: Note

Output (findall("."), regex mode — every character is a match)¶

================================
     | match_0  match_1  match_2
--------------------------------
0    | h        i        NULL   
1    | a        .        b      
2    | x        y        z      
3    | NULL     NULL     NULL   
--------------------------------
[4 cs x 3 feat]

Output (findall(".", {.regex = false}), literal mode — actual dots only)¶

==============
     | match_0
--------------
0    | NULL   
1    | .      
2    | NULL   
3    | NULL   
--------------
[4 cs x 1 feat]

Under regex mode, . matches any character, so "hi" produces two matches and "a.b"/"xyz" each produce three — the widest row (three matches) sets the output at three match_N columns. Under literal mode, only actual . characters count.

Example 2. A realistic case: extract every run of digits from a cell, producing a ragged, NULL-padded result.

auto orders = Thread(pluss::make_note({"1 2 3 4", "10 20", "no digits", "x"}),
    pluss::make_series(std::vector<bool>{true, true, true, false}));
auto out3 = orders.nt().findall(R"(\d+)", {.regex = true});
std::cout << out3;

Output¶

=========================================
     | match_0  match_1  match_2  match_3
-----------------------------------------
0    | 1        2        3        4      
1    | 10       20       NULL     NULL   
2    | NULL     NULL     NULL     NULL   
3    | NULL     NULL     NULL     NULL   
-----------------------------------------
[4 cs x 4 feat]

Row 0 has four number matches, so it drives the output to four columns. Row 1 (two matches) has NULL in match_2/match_3. Row 2 (no matches) and row 3 (invalid) are NULL across every column.

Example 3. options.limit caps matches per row — and since the widest row determines the column count, it also caps how many match_N columns appear at all.

auto out4 = orders.nt().findall(R"(\d+)", {.regex = true, .limit = 2});
std::cout << out4;

Output¶

=======================
     | match_0  match_1
-----------------------
0    | 1        2      
1    | 10       20     
2    | NULL     NULL   
3    | NULL     NULL   
-----------------------
[4 cs x 2 feat]

Notes¶

  • The single-argument overload defaults to {.regex = true} — the same gotcha documented on count().

  • Output columns are always named match_0, match_1, … — options.prefix has no effect here (contrast split() / indicate(), which do use it).

  • The number of output columns equals the largest per-row match count (after any limit is applied); rows with fewer matches get NULL in the extra columns.

  • An invalid input cell contributes zero matches, the same as a cell with genuinely no matches.

  • Requires the bound thread to be Note-kind, or the call throws.

See Also¶

  • ThreadNoteAccessor::extract: capture-group-based extraction, for pulling apart structured substrings instead of collecting every raw match.

  • ThreadNoteAccessor::count: just the match count, without the matched text itself.

  • ThreadNoteAccessor::split: delimiter-based cell splitting, another column-expanding method.

  • DataFrameNoteAccessor::findall: the multi-feature counterpart, sharing this exact regex-by-default gotcha.
