# PlussII 0.0.6 — Steady

A tagged, fully tested release for macOS (Apple Silicon CPU and MPS, Intel), Linux (x64, arm64) and Windows x64.

## Changes since 0.0.5

- Excel and Parquet loading and saving (`load_excel`, `save_excel`, `load_parquet`, `save_parquet`) work out of the box: every archive now bundles its own static libzip, Arrow and Parquet, and each archive is verified by round-tripping both formats. Windows archives use the dynamic C runtime.
- On Windows, `<pluss/pluss.h>` alone now gives the full PlussMic and PlussPl surface. Before, the module umbrella headers could include themselves on a case-insensitive filesystem.
- The LibTorch bridge (`pluss::series::from_torch` and `Series::tensor()`) now compiles with any include order. `<pluss/pluss.h>` no longer has to come after `<torch/torch.h>`.
- Apple Silicon is published twice: a CPU-only archive (`Darwin-arm64`) and one with the Apple GPU (MPS) backend (`Darwin-arm64-mps`). Intel Mac, Linux and Windows archives are CPU-only.
- Training errors from the tagger and entity-recognition stages no longer name an internal function.
- The plot window has views. Besides Theme, Colors and Save it now has a Reset entry and a View menu with the views that apply to the figure being shown: isolate or focus one series, split a figure into one panel per series, a window onto part of the data, transforms (index to 100, percent change, difference, running total, z-score, scaled 0 to 1, share of total), moving and exponential averages, line, steps, area, stems or points, guides and marks (mean, median, standard-deviation bands, quartiles, extremes, every value), a summary line, a fit line, outliers and density shading for a scatter, bins, density and a curve for a histogram, sort and orientation for bars, log scales, y range, legend, grid, shape and text size. Choices combine, a check mark shows what is in effect, and Reset clears them. The same views are available from code as `pluss::pl::views::groups(figure)` and `pluss::pl::views::apply(figure, choices)`.
- PlussView draws rotated text (turned axis labels), draws translucent lines and strokes as translucent instead of as pale opaque ones, and the legend of a filled plot (bars, areas, histograms) shows the color that was set.
- A histogram's bars can be scaled to a density or accumulated: `BucketData::scale`.
- The PlussView test hook `PLUSSTILS_VIEW_NSEVENTS` posts real mouse events so the hover, drag and double-click paths can be tested without a person at the mouse.

## Breaking changes

Plotting from a table now names its features explicitly, and the x-axis is never guessed.

- **x first, then y.** `plot().line`, `step`, `area`, `bar`, `area_stacked` and `bar_stacked` on a `DataFrame`, `Catalog`, `Archive` and `Atlas` (and `frames` on `Archive` and `Atlas`) take the x feature first: `line("month", "sales")`, `line("month", {"sales", "cost"})`. A single name is a y feature drawn against the row labels. Calls written as `line("sales", "month")` now draw `month` against `sales`; swap the two names.
- **No guessing of x.** The x-axis is the x feature you name (or `default_x_feature`) or the row labels. A frame's single time column is no longer picked as x for you; name it, as in `line("date", {"close", "open"})`.
- **Feature selection.** With no y feature named, the line-like plots draw the features of a selection on one axes. Set it per plot (`line({.features = {.include_features = {"a", "b"}}})`) or for the whole accessor (`df.plot({.include_features = {"a", "b"}})`). The fields are `all_features`, `include_features` and `exclude_features`; a plot's own selection overrides the accessor's, and names in the call override both. With nothing set, `plot().line()` draws every numeric feature. Misuse throws a `pluss::Error` that says what was combined and what to do.
- **A Catalog selects keys, not features.** The selection knobs of `Catalog::plot()` use the Catalog's own vocabulary: `all_keys`, `include_keys` and `exclude_keys`, set per plot (`line({.keys = {.include_keys = {"a", "b"}}})`) or for the whole accessor (`catalog.plot({.include_keys = {"a", "b"}})`). The per-plot options of a Catalog are `CatalogLinePlotOptions`, `CatalogStepPlotOptions`, `CatalogAreaPlotOptions`, `CatalogBarPlotOptions`, `CatalogHistPlotOptions`, `CatalogDensityPlotOptions` and `CatalogAutoPlotOptions`, and `CatalogCorrHeatmapPlotOptions` and `CatalogScatterMatrixPlotOptions` gain a `keys` field. The rules, precedence and directive errors are those of a DataFrame, worded for keys (`Catalog::plot().line: all_keys and exclude_keys cannot be combined ...`). Passing `all_features`, `include_features` or `exclude_features` to a Catalog throws an error that names the key knobs to use instead.
- **An Archive selects keys, not features.** The depth plots of `Archive::plot()` use the Archive's own vocabulary: `ArchiveDepthComparePlotOptions` and `ArchiveDepthFacetPlotOptions` replace `AtlasDepthComparePlotOptions` and `AtlasDepthFacetPlotOptions` and carry `keys` (`all_keys`, `include_keys`, `exclude_keys`) and `max_keys` instead of `features` and `max_features`; `Archive::plot(const KeySelection&)` and `Archive::plot(const ArchivePlotOptions&)` replace `Archive::plot(const AtlasPlotOptions&)`, and `triplot` takes `ArchiveTriplotPlotOptions` (the grid style of the flash triplot plus `keys` and `max_keys`) instead of `pluss::pl::flash::TriplotOptions`. Errors name keys and catalogs, with the closest key and the available keys for an unknown name. Passing `all_features`, `include_features` or `exclude_features` to an Archive throws an error that names the key knobs to use instead. `Atlas` keeps its feature selection.
- **flash is explicit.** The frame-level functions of `pluss::pl::flash` (`lineplot(pane, frame, ...)`, `histplot`, `scatterplot`, `relplot`, `heatmap`, `pairplot` and the rest) no longer infer columns from the shape of the frame (a frame of exactly two columns is no longer taken as x and y, a one-column frame no longer as the value). Name the columns with `TableColumns` (`x_feature`, `y_feature`, ...) or set `TableColumns::selection` (`all_columns`, `include_columns`, `exclude_columns`) for plots that draw one trace per column. Calling a frame-level function with an empty `TableColumns` throws an error that lists the options.
- `Catalog` line-like plots and `Archive`/`Atlas` `frames` follow the same order; `Atlas::plot().triplot()`, `depth_compare` and `depth_facet` accept the same selection fields.

## Renamed methods

Public method and function names in PlussMic now have at most two words. Update call sites as follows.

| Type | 0.0.5 | 0.0.6 |
| --- | --- | --- |
| `pluss::series` | `select(conditions, choices, default)` | `branch(conditions, choices, default)` |
| `pluss::note` | `select(conditions, choices, default)` | `branch(conditions, choices, default)` |
| `pluss::timeline` | `select(conditions, choices, default)` | `branch(conditions, choices, default)` |
| `Shelf`, `Stream` | `has_validity_mask`, `with_validity_mask`, `clear_validity_mask` | `has_mask`, `with_mask`, `clear_mask` |
| `Shelf` | `has_display_labels`, `with_display_labels`, `clear_display_labels` | `has_labels`, `with_labels`, `clear_labels` |
| `Nexus`, `Locus` | `has_table_meta` | `has_meta` |
| `Nexus`, `Locus` | `set_table_meta`, `set_table_meta_` | `meta(key, value)`, `meta_(key, value)` |
| `Locus` | `alignment_cache_stats` | `cache_stats` |
| `Slot`, `Registry` | `is_stream_compatible`, `ensure_stream_compatible` | `streamable`, `ensure_streamable` |
| `ConfigValue` | `is_string_list`, `as_string_list` | `is_list`, `as_list` |
| `LoadResult` | `sheet_by_index` | `sheet` |
| `pluss::table::display` | `set_default_backend`, `set_default_theme`, `gui_backend_available`, `render_info_html` | `default_backend(backend)`, `default_theme(theme)`, `gui_available`, `info_html` |

## Compatibility

Unchanged from 0.0.5. The distribution requires CMake 3.28 or newer and a C++20 compiler. See the download page for the archive for your system.
