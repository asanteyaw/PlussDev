# PlussII Transient

The latest validated development build. It carries no version number and is replaced on every update, so expect it to change. Only Steady releases are versioned and tagged.

## Changes since 0.0.6

- Notebook: each type shows in the shape that suits it. A `DataFrame` is a compact HTML table in the notebook's own colours (a long one shows its first and last five cases). A `Catalog` or a `Registry` is a ragged table, blank where a key has no entry. An `Atlas`, an `Archive` or an `Axel` is a short summary of how many tables are stacked and what they hold. A `Shelf`, a `Stream` or a `Slot` is text, as in the terminal. A compile error is a traceback about your own line. The notebook starts with `<pluss/pluss.h>` only, as a `main.cpp` does.
- Terminal: a `Stream` prints exactly as a `Shelf` does, and a `Slot` as a table of its cells with a `ptype` footer (`Mixed` when the cells are of different kinds), not as JSON. A `Registry` prints an overview with one row per field. An `Atlas`, an `Archive` and an `Axel` print a short list of facts that does not grow with their depth or width.
- PlussView: `Registry.show()` opens the ragged window a `Catalog` opens, and `Atlas.show()`, `Archive.show()` and `Axel.show()` open one window with a Level menu to move between their tables (a frame, or a catalog or registry as a ragged grid). Double-click on a divider fits a column to its header and its longest value over every row, with a small margin, as a spreadsheet does: it is a guide, not a toggle, so a fitted column stays fitted and a dragged one returns to the fit (two presses in quick succession count as a double-click on systems that do not report one), a table ends at its last row, and sizing a column moves only its right edge.
- PlussView: Save As → PNG and PDF now write only the content. A plot is saved at its own size with no window chrome, and a table is saved from its column headers down, with no title card, search box or scrollbars, cropped to the columns and rows that are shown.
- PlussView: every table size (column limits, sort-arrow size, row heights) is now one block of values in units of the font size, `HtmlTableGeometry`, so tables scale with the font and the numbers are changed in one place.
- PlussView on Windows and Linux now matches macOS: the toolbar has View and other menus and a "Save As" button sized to its label (Linux gained a toolbar), PDF export works on every platform, and on Linux Save As asks where to save when zenity or kdialog is installed.
- PlussView: table text no longer wraps by default, like a spreadsheet: one line per cell ending in an ellipsis, so a row's height follows the font and resizing a column never changes any row (set `value_max_lines` in `HtmlTableGeometry` to let long text wrap). A number that does not fit is shown as `#` repeated across the cell instead of being cut.
- PlussView: dragging a column of a table with many columns is about ten times faster to lay out (the table is measured once per frame instead of twice with no cache), headers stay on one line and end in an ellipsis when their column is narrow, and the window no longer flickers while macOS decides to activate it.
- PlussView: resizing a column of a large table is much faster. Styles are resolved once per kind of cell and text widths once per cell, so a drag does arithmetic instead of re-resolving every cell.
- PlussView: dragging or auto-fitting a column changes only that column. The last column is the table's automatic column: it takes whatever room the others leave, so the table always fills the panel, and it has no divider of its own. Past its minimum the table scrolls sideways. `html_table_geometry().slack` switches to a spreadsheet-style blank grid instead (`HtmlTableSlack::Continuation`).
- PlussView: clicking a column header no longer sorts the table; only the up and down triangles do.
- PlussView: the last column really is the table's automatic column by default. An earlier build documented this but still ended a resized table with a blank continuation column; `HtmlTableGeometry::slack` now defaults to `HtmlTableSlack::LastColumn`.
- PlussView: only a missing value (`NULL`) is marked, and only by its text: bold and red, in a red chosen for each theme. NaN and infinity are values and are drawn like any other (the new View → Filter finds them), in small and large tables alike. A long table takes its header, row stripes, case column and divider colours from the theme's stylesheet, like a short one.
- PlussView: the guide is rewritten around `.show()`, with pictures of the real window: views, number formats, themes, sorting, column widths, the plot window and Save As. The pixel-level canvas, scene and renderer pages are removed from the public reference: PlussView is a window, not a library.
- New `pluss` command, installed as `bin/pluss`: `pluss run file.cpp` builds a single file against the download and runs it, `pluss new name` starts a project with a CMake preset that points at the download, and `pluss doctor` builds and runs a test program to show what is missing. Programs share one precompiled header, and a program that has not changed runs without calling the build tool. Guide: "The pluss command".
- `pluss::tils::doc` reads the documentation from your program: `doc(value)`, `doc(value, "member")`, `doc("Series::sum")` print the page in the terminal, `doc_link` prints a file your editor's terminal opens and the website address, and `doc_open` opens it in the editor. The documentation (about 13 MB, packed) is bundled in the download under `share/pluss/docs`, so it works offline. Guide: "Reading the documentation from your program".
- `pluss::tils::Settings` layers defaults, a JSON file, the environment and the command line, strict about unknown keys, with typed reads that say where a bad value came from. Guide: "Settings from a file, the environment and the command line".
- `pluss::tils::Cache` keeps results between runs by key and input parts, tied to the library version, written atomically; an unreadable entry is replaced, never an error. Guide: "Keeping results between runs".
- `pluss/version.h` (`pluss::version()`), `pluss::tils::info::build()` and `describe()` report the version, channel, build, system and usable compute platforms, and `pluss::tils::derive_seed(base, index)` gives every run of a sweep a seed that does not depend on the thread that runs it. Guide: "Version, build information and run seeds".
- Array files: `pluss::io::save_npy`, `load_npy`, `save_npz` and `load_npz` write and read a `Series` in the common array-exchange formats, with either byte order, column-major data and compressed archives accepted on reading and no copy of the array beyond the one it is read into. Guide: "Array files" in the PlussQit manual.
- Datastores: `pluss::loader::datastores()` and `datastore(name)` (in `pluss/tils/kit/datastore.h`) return 26 built-in datasets, the same on every machine, in every container shape: single columns, streams and slots (1D), tables, catalogs and registries (2D) and catalogs and registries whose columns differ in length (ragged 2D). Guide: "Datastores: ready-made data" in the PlussTils manual. (These replace the five example tables that were briefly `pluss::table::example`.)
- A preview of a Jupyter notebook kernel for C++ (clang-repl as the engine, tables and plots shown in the notebook), installed with `pluss kernel install`. Guide: "Notebooks (preview)".
- Notebook: the kernel declares the language `cpp`, the name VS Code asks for suggestions under, so a dot, a name or `pluss::` offers members, variables and functions from the compiler. VS Code also needs `"jupyter.completionTriggerCharacters": { "cpp": [".", ":", ">"] }`; `pluss kernel install` offers to add it. A cell that only showed a value (`s1` without a semicolon) no longer hides the variable declared in the cell after it from the suggestions.
- Notebook: the help beside a suggestion is a short summary from the bundled documentation: the signature, what it does in a sentence or two, and the page's address (a variable shows its type and what that type is). It is read without running anything in the notebook's session, and a name with no page shows no help instead of a "No documentation page" message. The class's own name (`Series`) is no longer offered after a dot.
- Notebook: several kernels side by side, each under a name of your own, like the environments of other languages: `pluss kernel install --name transient-mps --display-name "PlussII (Transient, MPS)"`. Each has its own shared library under `~/.pluss/kernels/<name>`, so installing one never replaces another; `pluss kernel list` shows them and the download each runs, and `pluss kernel remove name` removes one. Without `--name` the kernel is `pluss`, shown as "PlussII C++", as before. The single library earlier installers kept in `~/.pluss` is deleted once no kernel uses it.
- New `pluss kernel check [--fix] [notebook ...]` checks the installed kernel (it belongs to this download, declares `cpp`, clang-repl reads the SDK, the shared library is built) and VS Code's setting, and cleans the language tags an earlier kernel left in a notebook's cells, which make VS Code skip them. It changes nothing without `--fix` and keeps the original of every file it edits. `pluss kernel install` runs the same checks at its end.
- Notebook: a plot appears when its `.show()` is called, as in a program (one left on a cell's last line shows nothing), as a picture as wide as the output, never wider than drawn, keeping its real size for a saved copy; it stays a picture, so VS Code's own buttons apply to it: the plot viewer (a larger view in a tab beside the notebook, with zoom and export) and Save, and Copy in the output's menu. PlussPl does the fitting, so every way a figure reaches a notebook is fitted the same way.
- Notebook: a catalog's or a registry's table carries, under each column's name, the bar the window draws: how much of the longest column this one covers, so the raggedness shows at a glance.
- Notebook: every frame is a table, whatever made it: `df.head()`, `df.tail()` and `df.describe()` return frames and are shown as the same HTML table as `df`, not as text. `#include <pluss/tils.h>` compiles in the notebook (the kernel now turns on the Timeline and Duration method sets the library is built with); before, the cell never finished.
- Plots: an axis labelled from a column in which several rows share one label (a month with a row per city) ticks each label once, evenly spaced, instead of repeating it. `pluss::pl::distinct_labeled_ticks` builds the ticks for PlussPl, flash and the DataFrame and Catalog plots alike.
- Notebook: what has been checked. The smoke test exercises the kernel itself (running cells, tables, plots, `tils.h`, completion, a crash and an interrupt) on macOS (Apple Silicon and Intel) and Ubuntu 24.04 (x86_64 and ARM64) when the release is built. How VS Code behaves with the kernel (suggestions, running cells, the Copy button, the setting above) has been checked on an Apple Silicon Mac only. If you use VS Code on Linux, or hit a problem, run `pluss kernel check` and send what it prints. The kernel is not available on Windows.
- The release workflow now builds seven checks of these helpers from the archive and runs them, and runs `pluss doctor` on every platform; a failure of either stops the release.
- PlussView: table columns now behave like browser tabs. A few columns grow to fill the window; as more are added they shrink together, down to a minimum width, with the text ending in an ellipsis, and then the table scrolls sideways. Drag a column border, or double-click it, to see the full text of a column.
- PlussView: tables fit their content. A short table is only as tall as its rows, the header band covers just the columns, and an unresized column is as wide as its header and first values need (up to a limit) instead of a fixed width, so short names no longer wrap.
- PlussView: the sort arrows are a stacked pair of triangles, which leaves more room for column names.
- PlussView: saved PNG and PDF tables leave out the sort arrows.
- PlussView: dragging or double-clicking a column border is much more responsive. Only the column that moved is measured again, instead of the whole table.
- PlussView: the Save As button is sized from its own title, so the label is never clipped.
- PlussView: a DataFrame in a window is painted from the frame by one renderer at every size, so a table of five rows and one of five million have the same header controls (sort arrows, draggable dividers with a highlight, the label column too), scrollbars, themes and number formats. Before, large tables had a separate renderer that lacked some of them. Column widths follow one rule: each column fits its header and the values read from the frame (headers alone for frames with more than 64 columns), then the table shares the room.
- PlussView: **View → Filter** (Invalid, Null, NaN, Inf) keeps the rows that hold a kind of cell, decided on what the cell is and never on its text, so a name like `Nancy` is not a NaN. It works on every table size. **View → Visit** shows the first, middle or last ten rows, or a range typed in (Custom, both ends included: 3 to 8 shows rows 3 through 8). The Table view clears both.
- PlussView: new theme Paperwhite, the page of an e-reader. The header fade now blends straight from one theme colour to the other instead of passing through white, column names are bold in every table, and the Default theme's column dividers are visible.
- PlussView: wrapping, cutting off and sizing text now measure with the width the text is painted at, so a row of items is sized for the text it holds and header names are no longer cut short.
- `Catalog::show()` opens a ragged grid instead of one card per key: the keys side by side, each column as long as its own stream and nothing padded. A cell past the end of a stream is absent, which is not NULL. Headers carry each key's length and a bar showing how much of the longest key it covers; **View → Align** puts keys by their head or tail; the View menu has Summary, Correlation, Validity, Outliers and Raggedness views computed from the streams as they are. The window opens in Ember and has the Format menu. Guide: "The catalog window" in the PlussView manual.
- Notebook preview: `PLUSS_NOTEBOOK_LOG` writes what the kernel and the compile engine say to each other to a file, and the smoke test prints it when a check fails. The notebook is still being fixed on Linux.

## Names that changed

Free functions now live in the lowercase namespaces, and the types hold only methods. These spellings were removed with no alias left behind:

- `pluss::Series::empty`, `zeros`, `ones`, `full`, `arange`, `linspace`, `eye`, `rand`, `randn` are now `pluss::series::empty`, `zeros`, `ones`, `full`, `arange`, `linspace`, `eye`, `rand`, `randn`, with the same arguments. `pluss::series::arange` now takes `double` for `start`, `end` and `step`, and every function that took a `Platform` has a `pluss::series::` form that takes one. `Series::from_storage` is gone; it was only used inside the library.
- `pluss::series::einsum(equation, operands)` is now `pluss::series::einsum(equation, operands)`.
- `pluss::timeline::from_ymd`, `from_ymdhms`, `from_epoch_seconds`, `from_epoch_millis`, `from_epoch_micros`, `from_buffer`, `now`, `today`, `yesterday` and `tomorrow` are now `pluss::timeline::` functions of the same names. `Timeline::date_range` (which returned a `std::vector`) is gone: use `pluss::timeline::date_range`, which returns a `Timeline`.
- `pluss::duration::range` is now `pluss::duration::range`.
- `pluss::note::undefined()` is now `pluss::note::undefined()`.
- `pluss::table::examples()` and `example(name)` are now `pluss::loader::datastores()` and `datastore(name)`.
- `Stream::show(os)` and `Slot::show(os)` are removed: a one-dimensional type is printed, not shown. Use `std::cout << stream` and `std::cout << slot`. `show()` belongs to the two- and three-dimensional types.
- `Catalog::nrows()`, `minrows()` and `maxrows()` are now `nentries()`, `minentries()` and `maxentries()`, and `Catalog::cloc` is now `Catalog::eloc`. A catalog's rows are its entries. `Registry::cloc` is now `Registry::sloc`: a registry's rows are its states.

## Compatibility

The distribution requires CMake 3.28 or newer and a C++20 compiler. See the download page for the archive for your system.
