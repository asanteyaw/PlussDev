# PlussBI: Controls

```{raw} html
<meta name="pluss-doc-kind" content="guide">
```

[Back to PlussTils](../index.md) · [PlussBI API Reference](../api/bi.md) · [PlussBI: A Guide](bi.md)

A control is a tile that changes what the other tiles show. A reader uses it to pick a category, a number range, or a time range. This chapter covers the three control kinds, the control members, and what a control does when its feature is missing.

## The mental model

A control has a key, a label, a feature to filter on, a kind that says what it offers, an optional scope, and a layout. The constructor sets the kind. The page shows the label and the choices, and a control that names a feature the source lacks shows a placeholder rather than failing.

## Worked tour

Every example is a complete program, and the output under it is copied from that program's run.

## Example 1: A control's key must be unique

A control's key identifies it on its board, so two controls cannot share one. This example adds two with the same key.

```cpp
#include <pluss/bi/bi.h>
#include <pluss/bundle/bundle.h>
#include <pluss/mic.h>

#include <cstdint>
#include <filesystem>
#include <fstream>
#include <iostream>
#include <iterator>
#include <string>
#include <vector>

namespace bi = pluss::bi;
namespace fs = std::filesystem;

// Six sales rows. Regions: north, south, north, east, south, north. Months: jan, jan, feb, feb, mar, mar.
// Amounts 10 to 60, units 1 to 6, and one date per row from January to June 2024.
pluss::bundle::Nexus make_nexus() {
  using pluss::table::DataFrame;
  using pluss::table::Slate;
  const auto cfg = pluss::Config{}.with_dtype(pluss::ScalarType::Float64).with_platform(pluss::pCPU);
  const DataFrame sales({
      {"region", Slate(pluss::make_note({"north", "south", "north", "east", "south", "north"}))},
      {"month", Slate(pluss::make_note({"jan", "jan", "feb", "feb", "mar", "mar"}))},
      {"amount", Slate(pluss::make_series(std::vector<double>{10, 20, 30, 40, 50, 60}, {6}, cfg))},
      {"units", Slate(pluss::make_series(std::vector<double>{1, 2, 3, 4, 5, 6}, {6}, cfg))},
      {"placed", Slate(pluss::make_timeline({"2024-01-05", "2024-02-10", "2024-03-15", "2024-04-20", "2024-05-25", "2024-06-30"}))},
  });
  return pluss::bundle::Nexus({{"sales", sales}});
}

// Renders a studio that holds one board with one view, and returns the first rendered tile.
template <class Build>
bi::TileRender one_tile(Build build) {
  const auto nexus = make_nexus();
  bi::Studio studio("sales_studio");
  studio.source(nexus);
  studio.board("overview").grid(1, 1);
  studio.board("overview").view(build());
  return studio.render().boards.front().tiles.front();
}

// The text of the page a studio exports, for checks on what is shown.
std::string page_text(const bi::Studio& studio) {
  const fs::path dir = fs::temp_directory_path() / "pluss_view_page_example";
  fs::remove_all(dir);
  fs::create_directories(dir);
  studio.export_html((dir / "page.html").string(), "T", 900, 600, bi::DashboardChrome::None);
  std::ifstream in((dir / "page.html").string());
  std::string text((std::istreambuf_iterator<char>(in)), std::istreambuf_iterator<char>());
  fs::remove_all(dir);
  return text;
}

// Renders a studio that holds one board with one control, and returns the first rendered tile.
bi::TileRender control_tile(bi::Control control) {
  const auto nexus = make_nexus();
  bi::Studio studio("sales_studio");
  studio.source(nexus);
  studio.board("overview").grid(1, 1);
  studio.board("overview").control(control);
  return studio.render().boards.front().tiles.front();
}

// True when the exported page contains the given text.
bool page_has(const bi::Studio& studio, const std::string& needle) {
  return page_text(studio).find(needle) != std::string::npos;
}

template <class Fn>
bool throws(Fn fn) {
  try {
    fn();
  } catch (const std::exception&) {
    return true;
  }
  return false;
}

int main() {
  const auto nexus = make_nexus();
  bi::Studio studio("sales_studio");
  studio.source(nexus);
  studio.board("overview").grid(1, 1);
  studio.board("overview").control(bi::category("pick", "region", "Region").place(0, 0));
  studio.board("overview").control(bi::category("pick", "month", "Month").place(0, 1));
  std::cout << "duplicate control key refused: " << throws([&] { (void)studio.render(); }) << '\n';
  return 0;
}
```

Output

```text
duplicate control key refused: 1
```

The second control is refused when the studio renders.

## Decisions

| You want | Use | Notes |
|---|---|---|
| A reader picks one value out of a list | `category` | The page lists the distinct values of the feature. |
| A reader picks a span of numbers | `range` | Works on numbers; the studio does not refuse text. |
| A reader picks a span of dates | `time_range` | Works on timeline columns. |
| A control should affect only one kind of query | a scope | A scoped copy leaves the original alone. |

## Pitfalls

**Expecting a missing feature to fail the render.** control_feature_03 shows the placeholder instead.

**Expecting a range to refuse text.** range_02 renders on text, so check the feature's kind yourself.
