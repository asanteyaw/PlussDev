Lymph prep¶

prep is the Lymph family for conditioning features before they reach a learner.

This is the family you enter when the central question is not yet “which model family wins?” but rather:

  • which features belong together

  • which columns should be scaled, encoded, imputed, or passed through

  • which transformation state must be learned once and reused later

  • how to keep training-time and inference-time feature handling identical

That concern deserves its own family because preprocessing failures often look like modeling failures until you inspect the feature contract closely.

What This Family Owns¶

prep owns five connected concerns:

  • route: declarative feature selection through prep::Route

  • stage: attachable stage descriptors such as prep::stage::standard_scaler(...)

  • scaling: standalone numeric transformers such as prep::StandardScaler

  • encoding: standalone categorical transformers such as prep::OneHotEncoder

  • feature: multi-branch transformation under one reusable prep::FeatureTransformer

The family boundary is deliberate:

  • models owns the learner artifact

  • prep owns the feature-conditioning contract

  • selection owns the evidence policy that judges the learner

  • workflow owns the broader runtime and deployment-shaped orchestration

Mental Model¶

Read prep in two layers.

The first layer is reusable transformer objects. Those are the classes you can fit, inspect, and reuse directly:

  • prep::StandardScaler

  • prep::OneHotEncoder

  • prep::FeatureTransformer

The second layer is attachable stage planning. That is the route-plus-stage surface used by Model::prepare() or Model::append(...):

  • prep::Route

  • prep::Stage

  • prep::stage::* factories

If you want a model to carry preprocessing as part of its own contract, the second layer is usually the right entry. If you want a standalone transformer object in its own right, start with the first layer.

Practical Example¶

This executed example shows the highest-level everyday path: attach prep to a model, learn once, then infer and assess through the same feature contract.

#include <pluss/lymph.h>
#include <pluss/mic.h>

#include <iostream>

int main() {
  namespace lymph = pluss::ai::lymph;
  using pluss::ScalarType;
  using pluss::table::DataFrame;
  using pluss::table::Thread;

  const pluss::Config f64 =
      pluss::Config{}.with_dtype(ScalarType::Float64).with_platform(pluss::pCPU);

  const DataFrame raw({
      {"income", Thread(pluss::make_series({1.0, 1.4, 1.8, 2.2, 3.8, 4.2, 4.6, 5.0}, {8}, f64))},
      {"balance", Thread(pluss::make_series({0.2, 0.4, 0.6, 0.9, 1.8, 2.1, 2.4, 2.7}, {8}, f64))},
      {"late", Thread(pluss::make_series({0, 0, 0, 0, 1, 1, 1, 1}, {8}, f64))},
      {"region", Thread(pluss::make_note({"north", "west", "north", "south", "east", "south", "west", "east"}))},
      {"default", Thread(pluss::make_series({0, 0, 0, 0, 1, 1, 1, 1}, {8}, f64))},
  });

  lymph::options::Linear logistic_options{};
  logistic_options.regularization = lymph::RegularizationKind::L2;
  logistic_options.regularization_strength = 1e-3;
  logistic_options.fit_intercept = true;

  lymph::models::Model model = lymph::models::linear::logistic_regression(logistic_options);
  lymph::models::ModelPrep prep = model.prepare();
  prep.standardize({"income", "balance", "late"});
  prep.encode(
      lymph::prep::route::names({"region"}),
      lymph::prep::OneHotEncoderOptions{
          .max_categories = 8,
          .overflow = lymph::prep::CategoryOverflowPolicy::KeepMostFrequent,
          .include_unknown_bucket = true,
      });

  lymph::options::Train train_options{};
  train_options.max_iterations = 600;
  train_options.tolerance = 1e-8;
  train_options.random = {.seed = 20260825ULL, .deterministic = true};

  lymph::options::DFBatch data_options{};
  data_options.feature_names = {"income", "balance", "late", "region"};
  data_options.label_feature = "default";
  data_options.note_policy = lymph::DataNotePolicy::Factorize;

  model.learn_(raw, data_options, train_options);
  const pluss::Series predicted = model.infer(raw, data_options);
  const lymph::reports::Metric report = model.assess(
      raw,
      data_options,
      lymph::options::Assess{
          .metrics = {lymph::MetricKind::Accuracy, lymph::MetricKind::F1},
      });
  const DataFrame prediction_frame({
      {"predicted", Thread(predicted)},
  });

  std::cout << "== prep ==\n";
  std::cout << "stage_count = " << model.stage_count()
            << ", trained = " << std::boolalpha << model.trained()
            << ", task_kind = " << static_cast<int>(model.task_kind()) << "\n\n";
  std::cout << prediction_frame << "\n";
  std::cout << "accuracy = " << report.accuracy.item<double>()
            << ", f1 = " << report.f1.item<double>() << "\n";

  return 0;
}

The point of that example is not the perfect toy accuracy. It is the ownership boundary:

  • the prep contract was attached before fitting

  • the fitted model reused it for inference

  • the same contract also governed assessment
